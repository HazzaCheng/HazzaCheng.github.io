尾递归调研笔记

引言

　　递归函数大家都知道，如果一个函数在内部调用自身本身，这个函数就是递归函数。那么什么叫尾递归呢？顾名思义，如果一个函数中所有递归形式的调用都出现在函数的末尾，我们称这个递归函数是尾递归的。当递归调用是整个函数体中最后执行的语句且它的返回值不属于表达式的一部分时，这个递归调用就是尾递归。尾递归函数的特点是在回归过程中不用做任何操作，这个特性很重要，因为大多数现代的编译器会利用这种特点自动生成优化的代码。

尾递归的优势

　　大家都知道，使用递归函数需要注意防止栈溢出。在计算机中，函数调用是通过栈（stack）这种数据结构实现的，每当进入一个函数调用，栈就会加一层栈帧，每当函数返回，栈就会减一层栈帧。由于栈的大小不是无限的，所以，递归调用的次数过多，会导致栈溢出。
　　解决递归调用栈溢出的方法是通过尾递归优化，事实上尾递归和循环的效果是一样的，所以，把循环看成是一种特殊的尾递归函数也是可以的。 尾递归是指，在函数返回的时候，调用自身本身，并且，return语句不能包含表达式。这样，编译器或者解释器就可以把尾递归做优化，使递归本身无论调用多少次，都只占用一个栈帧，不会出现栈溢出的情况。
　　尾递归事实上和循环是等价的，没有循环语句的编程语言只能通过尾递归实现循环。

测试

　　那么是不是所有语言都会对尾递归做出优化呢，从而减少栈溢出呢，答案是否定的。我们可以用阶乘的例子对Java,Scala,Python做测试，因为递归阶乘，要想测试出编程语言是否做出了尾递归优化，我们需要阶乘1000!,这会产生极大的数字，为了防止溢出，我们需要使用各个编程语言的大树类型，那么我们首先先来讨论下这几种语言的大数类型。

大数类型

Java

　　在Java中有两个类BigInteger和BigDecimal分别表示大整数类和大浮点数类，至于两个类的对象能表示最大范围不清楚，理论上能够表示无线大的数，只要计算机内存足够大。这两个类都在java.math.*包中，因此每次必须在开头处引用该包。
　　Java中的大数类型不支持+，-等运算符，而是实现了add(),subtract()等成员函数。

Scala

　　Scala在scala.math包里提供了两个类似Java的类：BigInt和BigDecimal。因为在Scala里不存在运算符的概念，只有操作符的概念，所以这两个类都重载了+，-等各种运算操作符，计算起来显得更加自然一点。

Python

　　Python可以处理任意大小的整数，不需要特别使用别的类型。

阶乘测试

　　我们分别对各种编程语言测试普通递归和尾递归的阶乘，比较有没有做出栈优化。

Java

　　实验Java版本为open jdk1.8。

普通递归

public static BigInteger fact(BigInteger n) {
	if (n.intValue() == 1) return new BigInteger("1");
    else return n.multiply(fact(n.subtract(new BigInteger("1"))));
}

　　结果：

执行 fact(new BigInteger("9900")) 
成功输出，耗时143ms

执行 fact(new BigInteger("10000"))
输出：Exception in thread "main" java.lang.StackOverflowError

尾递归

public static BigInteger fact(BigInteger n) {
    return fact_iter(n, new BigInteger("1"));
}

private static BigInteger fact_iter(BigInteger n, BigInteger p) {
    if (n.intValue() == 1) return p;
    return fact_iter(n.subtract(new BigInteger("1")), n.multiply(p));
}

　　结果：

执行 fact(new BigInteger("9900")) 
成功输出，耗时141ms

执行 fact(new BigInteger("10000"))
输出：Exception in thread "main" java.lang.StackOverflowError

循环

public static BigInteger loop(BigInteger n) {
        BigInteger value = new BigInteger("1");
        for (int i = 1; i < n.intValue(); ++i) 
            value = value.multiply(new BigInteger("" + i));
        return value;
}

　　结果:

执行 loop(new BigInteger("9900")) 
成功输出，耗时147ms

结论

　　我们可以看出，不管是普通递归还是尾递归，10000！都是爆栈的，9900！两者之间相差的时间也不是很多，和循环的差距也不是很多，应该说在JDK1.8里JVM是没有做尾递归优化的，或者说尾递归的优化程度还不是很高。
　　然而尾递归通常是函数式语言必须要实现的特性，Java是命令式语言，我们也不必对Java太过失望，也许在以后的新jdk里，尾递归会得到优化。

Scala

　　下面是我最喜欢的函数式编程语言Scala,实验Scala版本为2.12.2。

普通递归

def fact(n: Int): BigInt =
    if (n == 1) 1 else n * fact(n - 1)

　　结果：

执行 fact(10000) 
输出:Exception in thread "main" java.lang.StackOverflowError

尾递归

def fact(n: Int): BigInt = fact_iter(n, 1)

@tailrec  
def fact_iter(n: Int, p: BigInt): BigInt =
    if (n == 1) p else fact_iter(n - 1, n * p)

　　结果：

执行 fact(500000) 
成功输出，耗时121652ms

循环

def loop(n: Int): BigInt = {
    var value: BigInt = 1;
    for (i <- 1 to n)
      value = value * i
    value
}

　　结果:

执行 loop(500000) 
成功输出，耗时111655ms

结论

　　我们发现普通递归和java一样在10000！时就会爆栈，而尾递归在500000！时都没有爆栈，而且尾递归和循环的执行时间相差也不是很对。由此可以看出，确实Scala编译器为将函数式代码编译成高性能的字节码，会把尾递归优化为运行时的循环执行，而不是递归调用。如果不优化，递归会使栈的占用急剧增长。递归优化最主要是避免栈溢出错误而不是提高速度。

Python

　　Python的版本是3.6。

普通递归

def fact(n):
    if n == 1:
        return 1
    return n * fact(n - 1)

　　结果:

执行 fact(990) 
成功输出，耗时1253ms

执行 fact(1000)
输出：RecursionError: maximum recursion depth exceeded in comparison

尾递归

def fact(n):
    return fact_iter(n, 1)

def fact_iter(n, p):
    if n == 1:
        return p
    return fact_iter(n - 1, n * p)

　　结果:

执行 fact(990) 
成功输出，耗时2358ms

执行 fact(1000)
输出：RecursionError: maximum recursion depth exceeded in comparison

循环

def loop(n):
    value = 1
    for x in range(1, n):
        value *= x
    return value

　　结果:

执行 fact(990) 
成功输出，耗时364ms

结论

　　很显然，Python也没有做尾递归的优化，Python相比Java和Scala栈的处理能力和速度就要慢多了，不仅1000!就爆栈了，递归调用和循环的速度也差了很多，看来写Python的时候，如果追求速度还是少写一点递归，当然Python的优势一直不是它的速度，而是它强大的类库，所以大家也不用太担心。

总结

　　经过比较,Java和Python没有明显的尾递归优化，都会出现爆栈，作为函数式编程语言的Scala在递归和尾递归优化上就要做的好很多，当然Scala编译器执行尾递归优化时除了要加上**@tailrec**(不加的话也会执行尾递归优化)，还需要满足以下条件:

  • 方法必须是final或私有，换句话来说，方法不能多态。
  • 方法必须注明返回类型。
  • 方法必须在其某个分支的最后一句调用自身。

　　这样就可以把尾递归函数优化为while函数，就不存在堆栈溢出的问题了。
