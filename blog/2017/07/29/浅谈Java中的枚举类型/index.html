引言

　　最近在看EffectiveJava，看到枚举类型，这个类型我以前用的不多，用也经常只把它当常量来用，但是通过学习，发现它还有很多其它特性，以及很强的功能，遂把它们记录下来。

枚举类型

　　Java的枚举本质是int值，Java中的枚举类型就是通过公有的静态fina域为每个枚举常量导出实例的类，因为没有可以访问的构造器，枚举类型是真正的final。因为客户端既不能创建美剧类型的实例，也不能对它进行扩展，因此很有可能没有实例，而只有声明过的枚举常量，也就是说，枚举类型是实例受控的，它们是单例的泛型化，本质上是单元素的枚举。
　　枚举提供了编译时的类型安全。如果声明一个参数的类型是Animal，就可以保证被传到该参数上的任何非null的对象的引用一定属于有效的Animal值，试图传递类型错误的值时，会导致编译错误，就像视图将某种枚举类型的表达式赋给另一种枚举类型的变量，或者试图用==操作符来比较不同枚举类型的值一样。

在枚举类型中添加域和方法

　　枚举类型还允许添加任意的方法和域，并实现任意的接口。它们提供了所有Object方法的高级实现，实现了Comparable和Serializable接口，并针对枚举类型的可任意改变行设计了序列化方式。
　　我们举书中一个很有趣的例子：

public enum Planet {
    MECURY(3.302e+23, 2.439e6),
    VENUS(4.869e+24, 6.052e6),
    EARTH(5.975e+24, 6.478e6),
    MARS(6.419e+23, 3.939e6),
    JUPITER(1.899e+27, 7.149e7),
    SATURN(5.685e+26, 6.027e7),
    URANUS(8.683e+25, 2.556e7),
    NEPTUNE(1.024e+26, 2.477e7);


    private final double mass;      // in kilograms
    private final double radius;    // in meters
    private final double surfaceGravity;

    private static final double G = 6.67300E-11;

    Planet(double mass, double radius) {
        this.mass = mass;
        this.radius = radius;
        surfaceGravity = G * mass / (radius * radius);
    }
    public double getMass() {
        return mass;
    }

    public double getRadius() {
        return radius;
    }

    public double getSurfaceGravity() {
        return surfaceGravity;
    }

    public double surfaceWeight(double mass) {
        return mass * surfaceGravity;
    }
}

　　这是一个计算在八大行星上的重量的枚举类，在枚举类中为了将数据与枚举常量关联起来，得声明实例域，并编写一个带有数据并将数据保存在域中的构造器。
　　我们可以调用Plant类打印某个物体在八大行星上的重量：


public static void main(String[] args) {
    double earthWeight = 63.4;
    double mass = earthWeight / Planet.EARTH.getSurfaceGravity();
    for (Planet p: Planet.values())
        System.out.printf("Weight on %s is %f%n", p, p.getSurfaceWeight(mass));
}


输出：
Weight on MECURY is 24.716485
Weight on VENUS is 59.193657
Weight on EARTH is 63.400000
Weight on MARS is 18.421655
Weight on JUPITER is 165.450318
Weight on SATURN is 69.688533
Weight on URANUS is 59.180869
Weight on NEPTUNE is 74.315804

　　我们看出，枚举类的功能实际上是非常强大的。

特定于常量的类主体

　　在枚举类型中声明一个抽象的apply方法，并在特定于常量的类主体中，用具体的方法覆盖每个常量的抽象apply方法，这种方法也被称作为特定于常量的方法实现(constant-specific method implementation)。
　　举个例子：

public enum Operation {
    PLUS, MINUS, TIMES, DIVIDE;
    
    double apply(double x, double y) {
        switch (this) {
            case PLUS: return x + y;
            case MINUS: return x - y;
            case TIMES: return x * y;
            case DIVIDE: return x / y;
        }
        throw new AssertionError("Unkonwn op: " + this);
    }
}

　　如果我们相对上面的枚举类型添加新的运算符，添加了新的枚举常量，但是却忘了给switch添加相应的条件，枚举仍可以编译，但是当你试图运用新的运算时，就会运行失败，而且如果没有throw语句，编译报Error:(17, 5) java: missing return statement的错失败。但是如果提供了特定于常量的方法实现，就会解决这个问题，代码也会优美很多。

public enum Operation {
    PLUS { double apply(double x, double y) {return x + y;}},
    MINUS {double apply(double x, double y) {return x - y;}},
    TIMES {double apply(double x, double y) {return x * y;}},
    DIVIDE {double apply(double x, double y) {return x / y;}};

    abstract double apply(double x, double y);
}

　　这样你在添加新的常量时，就不可能忘记提供apply方法了。
　　同时，特定于常量的方法实现可以与特定于常量的数据结合起来，例如下面的Operation覆盖了toString来返回通常与该操作关联的符号。

public enum Operation {
    PLUS("+") {
        double apply(double x, double y) {return x + y;}
        },
    MINUS("-") {
        double apply(double x, double y) {return x - y;}
        },
    TIMES("*") {
        double apply(double x, double y) {return x * y;}
        },
    DIVIDE("/") {
        double apply(double x, double y) {return x / y;}
    };

    private String symbol;

    Operation(String symbol) {
        this.symbol = symbol;
    }

    abstract double apply(double x, double y);

    @Override
    public String toString() {
        return symbol;
    }
}

　　这样我们就可以很容易的打印算术表达式了:

    public static void main(String[] args) {
        double x = 3.2;
        double y = 1.7;
        for (Operation op: Operation.values())
            System.out.printf("%f %s %f = %f%n", x, op, y, op.apply(x, y));
    }
    
    
    输出：
    3.200000 + 1.700000 = 4.900000
    3.200000 - 1.700000 = 1.500000
    3.200000 * 1.700000 = 5.440000
    3.200000 / 1.700000 = 1.882353

策略枚举

　　特定于常量的方法实现有一个美中不足的地方，它们使得在枚举常量中共享代码变得更加困难了，例如我们举一个工资包枚举类的例子，根据工作日和周末工作时间的不同计算工资。

public enum PayrollDay {
    MONDAY, TUESDAY, WEDNESDAY, THURSDAY, FRIDAY, SATURDAY, SUNDAY;

    private static final int HOURS_PER_SHIFT = 8;
    
    double pay(double hoursWorked, double payRate) {
        double basePay = hoursWorked * payRate;
        double overtimePay= 0.0;
        switch (this) {
            case SATURDAY:
            case SUNDAY:
                overtimePay = hoursWorked * payRate / 2;
            default:
                overtimePay = hoursWorked <= HOURS_PER_SHIFT ?
                        0 : (hoursWorked - HOURS_PER_SHIFT) * payRate / 2;
                break;
        }

        return basePay + overtimePay;
    }
}

　　乍一看，上面的代码很简洁，也很容易立即，似乎也有很好的功能，但是当我们考虑添加一个元素，它表示一个假期的特殊值，类似于春节什么的，虽然不是周末但也算周末加班，这时如果你忘记在switch语句里添加一个case的话，程序依然可以编译，但是pay方法会偷偷地将假期工资计算成正常工作日的工资。为了解决这个问题，你可能会利用特定于常量的方法安全地执行工资计算，你需要重复计算每个常量的加班工资，或者将计算移到两个辅助方法中，一个计算工作日工资，一个计算节假日工资，这样是可行的，但是这样会产生大量重复的代码，降低了程序的可读性。
　　这时，我们可以考虑将加班工资移到一个私有的嵌套类中，这就是枚举策略。

public enum PayrollDay {
    MONDAY(PayType.WORKDAY),
    TUESDAY(PayType.WORKDAY),
    WEDNESDAY(PayType.WORKDAY),
    THURSDAY(PayType.WORKDAY),
    FRIDAY(PayType.WORKDAY),
    SATURDAY(PayType.HOLIDAY),
    SUNDAY(PayType.HOLIDAY),
    SPRING_FESTIVAL(PayType.HOLIDAY);

    private PayType payType;

    PayrollDay(PayType payType) {
        this.payType = payType;
    }

    double pay(double hoursWorked, double payRate) {
        return payType.pay(hoursWorked, payRate);
    }

    private enum PayType {
        WORKDAY {
            double overtimePay(double hours, double rate) {
                return hours <= HOURS_PER_SHIFT ?
                        0 : (hours - HOURS_PER_SHIFT) * rate / 2;
            }
        },
        HOLIDAY {
            double overtimePay(double hours, double rate) {
                return hours * rate / 2;
            }
        };

        private static final int HOURS_PER_SHIFT = 8;

        abstract double overtimePay(double hours, double rate);

        double pay(double hoursWorked, double payRate) {
            double basePay = hoursWorked + payRate;
            return basePay + overtimePay(hoursWorked, payRate);
        }
    }
}

　　这样一来我们就可以轻松的添加春节这样的节假日类型了，我们将这个策略枚举的实例传到PayrollDay的枚举的构造器中，之后PayrollDay枚举将工资加班计算委托给策略枚举，PayrollDay中就不需要switch等语句或者特定于常量的方法实现了，虽然看上去不是很简洁，但更加安全灵活。

EnumSet

　　如果我们在使用一个枚举类型时，每次会用到一项或多项时，在Java没有引入EnumSet前，我们可能会使用int枚举模式(int enum pattern)，将2的不同倍数赋予每个常量，例如一个字体的样式style会写成类似这样：

public class Font {
    public static final int STYLE_BOLD = 1 << 0; // 1
    public static final int STYLE_ITALIC = 1 << 1; // 2
    public static final int STYLE_UNDERLINE = 1 << 2; // 4
    public static final int STYLE_STRIKETHROUGH = 1 << 3; // 8
    
    public void applyStyls(int styles) {
        
    }
}

　　在使用的时候，我们会这样使用:

font.applyStyles(STYLE_BOLD | STYLE_ITALIC);

　　但是当我们有了EnumSet后，就不比如此了。java.util包提供的EnumSet类有效地表示从单个枚举类型中提取多个值的多个集合。这个类实现Set接口，提供了丰富的功能和类型安全性，以及可以从任何其他Set实现中得到的互用性。
　　但是在内部具体实现上，EnumSet内容都表示为位矢量。如果底层的枚举类型有64个或者更少的元素，整个EnumSet就用单个long表示，因此它的性能比得上位域的性能，类似removeAll和retainAll的批处理也都是利用位运算算法来实现的。
　　我们将刚才的例子改动一下：

public class Text {
    public enum Style { BOLD, ITALIC, UNDERLINE, STRIKETHROUGH }
    
    public void applyStyls(Set<Style> styles) {
        
    }
}

　　注意applyStyles的参数是Set<Style>而不是EnumSet<Style>，这是考虑到可能会有其它特殊的客户端需要传递一些其他的Set实现，我们只需这样调用就可以达到与之前int枚举模式一样的效果了：

font.applyStyles(EnumSet.of(Style.BOLD, Style.ITALIC));

EnumMap

　　《Effective Java》中说最好不用序数来索引数组，而要使用EnumMap，这是什么意思呢，这是要求我们最好不要枚举类型中的ordinal函数来索引枚举变量的数组，在Java中，有一种非常快速的Map实现专门用于枚举键，它就是java.util包里的EnumMap。
　　EnumMap在运行速度方面可以和使用序数的程序相媲美，它也没有不安全的转换，也不必手工标注这些索引的输出，因为映射键知道如何把自身翻译成可打印字符串的枚举，计算数组索引时也不可能出错。需要注意的是EnumMap构造器采用键类型的Class对象，这是一个有限制的类型令牌，它提供了运算时的泛型信息。
　　即使是枚举变量的多维数组，我们依然可以用EnumMap来代替，我们举个固液气三态相互转化的例子，这个程序一个状态转换到另一个状态。

public enum Phase {
    SOLID, LIQUID, GAS;

    public enum Transition {
        MELT(SOLID, LIQUID),
        FREEZE(LIQUID, SOLID),
        BOIL(LIQUID, GAS),
        CONDENSE(GAS, LIQUID),
        SUBLIME(SOLID, GAS),
        DEPOSIT(GAS, SOLID);

        private final Phase src;
        private final Phase dst;
        Transition(Phase src, Phase dst) {
            this.src = src;
            this.dst = dst;
        }

        private static final Map<Phase, Map<Phase, Transition>> m =
                new EnumMap<Phase, Map<Phase, Transition>>(Phase.class);
        static {
            for (Phase p: Phase.values())
                m.put(p, new EnumMap<Phase, Transition>(Phase.class));
            for (Transition t: Transition.values()) 
                m.get(t.src).put(t.dst, t);
        }
        
        public static Transition from(Phase src, Phase dst) {
            return m.get(src).get(dst);
        }
    }
}

　　我们将这种转换关系表示为一个map，这个map的的键是一个枚举（表示起始状态），值为另一个map，这第二个map的键是为为第二个枚举(表示目标状态)，它的值为结果(表示过度阶段)，即可以表示一个类似多维数组的结构，例如我们利用这个程序来查找三态之间相互转换的过渡阶段。

    public static void main(String[] args) {
        for (Phase src: Phase.values()) {
            for (Phase dst: Phase.values()) {
                Transition transition = Transition.from(src, dst);
                if (transition != null) System.out.println(src + " to " + dst + " is " + transition);
            }
        }
    }
    
    输出:
    SOLID to LIQUID is MELT
    SOLID to GAS is SUBLIME
    LIQUID to SOLID is FREEZE
    LIQUID to GAS is BOIL
    GAS to SOLID is DEPOSIT
    GAS to LIQUID is CONDENSE

　　我们看到可以正确的输出，那么我们再来考虑下这个枚举类的扩展性，假设我们现在想添加一个ｉｅ新的阶段PLASMA(离子)，只有两个过渡与这个阶段有关，它将气体变成离子(电离化)，它将将离子变为气体(消电离化)，而在我们的程序中所需要做的就是将PLASMA添加到Phase列表，并将IONIZE(GAS, PLASMA)和DEIONIZE(PLASMA, GAS)加到Phase.Transition列表中。

public enum Phase {
    SOLID, LIQUID, GAS, PLASMA;

    public enum Transition {
        MELT(SOLID, LIQUID),
        FREEZE(LIQUID, SOLID),
        BOIL(LIQUID, GAS),
        CONDENSE(GAS, LIQUID),
        SUBLIME(SOLID, GAS),
        DEPOSIT(GAS, SOLID),
        IONIZE(GAS, PLASMA),
        DEIONIZE(PLASMA, GAS);

        private final Phase src;
        private final Phase dst;
        Transition(Phase src, Phase dst) {
            this.src = src;
            this.dst = dst;
        }

        private static final Map<Phase, Map<Phase, Transition>> m =
                new EnumMap<Phase, Map<Phase, Transition>>(Phase.class);
        static {
            for (Phase p: Phase.values())
                m.put(p, new EnumMap<Phase, Transition>(Phase.class));
            for (Transition t: Transition.values())
                m.get(t.src).put(t.dst, t);
        }

        public static Transition from(Phase src, Phase dst) {
            return m.get(src).get(dst);
        }
    }
}

    public static void main(String[] args) {
        for (Phase src: Phase.values()) {
            for (Phase dst: Phase.values()) {
                Transition transition = Transition.from(src, dst);
                if (transition != null) System.out.println(src + " to " + dst + " is " + transition);
            }
        }
    }
    
    输出:
    SOLID to LIQUID is MELT
    SOLID to GAS is SUBLIME
    LIQUID to SOLID is FREEZE
    LIQUID to GAS is BOIL
    GAS to SOLID is DEPOSIT
    GAS to LIQUID is CONDENSE
    GAS to PLASMA is IONIZE
    PLASMA to GAS is DEIONIZE

　　通过实验，我们发现程序会自动处理所有的事情，我们什么都不需要做，程序的扩展性和易维护性都非常好。

接口模拟可伸缩的枚举

　　编写可扩展的枚举类型是一件非常苦难的事，需要考虑许多细节。虽然无法编写可扩展的枚举类型，却可以通过编写接口以及实现该接口的基础枚举类型，对它进行模拟。例如我们前面所说的Operation类型，它表示一个简单计算器中的某些函数，有时候要尽可能地让API的用户提供它们自己的操作，这样可以有效地扩展API所提供的操作集。我们可以通过定义接口让枚举类型来实现，从而实现任意接口。

public interface Operation {
    double apply(double x, double y);
}

public enum BasicOperation implements Operation {
    PLUS("+") {
        public double apply(double x, double y) {return x + y;}
    },
    MINUS("-") {
        public double apply(double x, double y) {return x - y;}
    },
    TIMES("*") {
        public double apply(double x, double y) {return x * y;}
    },
    DIVIDE("/") {
        public double apply(double x, double y) {return x / y;}
    };

    private final String symbol;

    BasicOperation(String symbol) {
        this.symbol = symbol;
    }

    @Override
    public String toString() {
        return symbol;
    }
}

　　虽然枚举类型BasicOperation不是可扩展的，但是接口类型Operation则是可以扩展的，它是用来表示API中的操作的接口类型。例如我们还想要定定义一个操作类型的扩展，由求幂和求余操作组成，我们只需要编写另外一个枚举类型ExtendedOperation，让它来实现Operation接口。

public enum ExtendedOperation implements Operation {
    EXP("^") {
        public double apply(double x, double y) {
            return Math.pow(x, y);
        }
    },
    REMAINDER("%") {
        public double apply(double x, double y) {
            return x % y;
        }
    };
    
    private final String symbol;
    ExtendedOperation(String sumbol) {
        this.symbol = sumbol;
    }

    @Override
    public String toString() {
        return symbol;
    }
}

　　只要API是被写成采用接口类型Operation而非实现BasicOperation，我们就可以在使用基础操作的任何地方，都可以使用新的操作。我们不需要再像在原来的Oeration枚举利用特定于实例的方法实现来声明抽象的apply方法，这是因为抽象的方法是接口的一部分。
　　通过参数的设置，我们可以在任何需要＂基本枚举＂的地方单独传递一个＂扩展枚举＂的实例，而且除了那些基本元素之外，还可以传递完整的扩展类型，并使用它的元素，例如我们可以这样操作。

private static <T extends Enum<T> & Operation> void test(
        Class<T> opSet, double x, double y) {
    for (Operation op: opSet.getEnumConstants())
        System.out.printf("%f %s %f = %f%n", x, op, y, op.apply(x, y));
}

public static void main(String[] args) {
    double x = 4.0, y = 2.1;
    test(BasicOperation.class, x, y);
    test(ExtendedOperation.class, x, y);
}

输出:
4.000000 + 2.100000 = 6.100000
4.000000 - 2.100000 = 1.900000
4.000000 * 2.100000 = 8.400000
4.000000 / 2.100000 = 1.904762
4.000000 ^ 2.100000 = 18.379174
4.000000 % 2.100000 = 1.900000

　　我们通过<T extends Enum<T> & Operation>这个很复杂的声明确保了class既表示枚举又表示Operation的子类型，这正是遍历元素与每个元素相关联的操作所需要的。
　　我们可以通过更简单的方法使用它们的元素：

private static void test(
        Collection<? extends Operation> opSet, double x, double y) {
    for (Operation op: opSet)
        System.out.printf("%f %s %f = %f%n", x, op, y, op.apply(x, y));
}

public static void main(String[] args) {
    double x = 4.0, y = 2.1;
    test(Arrays.asList(BasicOperation.values()), x, y);
    test(Arrays.asList(ExtendedOperation.values()), x, y);
}

输出:
4.000000 + 2.100000 = 6.100000
4.000000 - 2.100000 = 1.900000
4.000000 * 2.100000 = 8.400000
4.000000 / 2.100000 = 1.904762
4.000000 ^ 2.100000 = 18.379174
4.000000 % 2.100000 = 1.900000

　　我们使用Collection<? extends Operation>将枚举类型变量转换成数组之后通过限制她是Operation的子类型来进行计算。
　　当然虽然用接口模拟可伸缩枚举的功能很强大，但是它也存在不足，它无法将枚举类型继承到另一个枚举类型，像BasicOperation和ExtendedOperation它们直接复用的代码很少我们可以直接复制重复的代码，但如果两个枚举类型共享功能较多，我们可以将它封装在一个辅助类或者静态辅助方法中，来避免代码的复制工作。
