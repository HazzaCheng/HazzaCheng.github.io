Scala学习笔记（四）- Scala中命名参数的一个小坑（截至Scala2.12.2）

引言

　　今天在学习Scala的命名参数时，遇到一个小坑，和静态类型有关，分享一下。

命名参数

　　Scala 2.8.x增加了对命名参数的支持，这意味着你给方法参数的名字成为公开的api的一部分，更意味着修改名字会破坏客户代码，同时Scala允许子类定义不同的参数名。

命名参数的简单应用

　　Scala定义命名参数很容易，你定义方法时声明的参数可以在调用方法时使用，我来举个简单的例子：

class Foo {
    def foo(a: Int = 1, b: String = "b", c: Double = 2.5): String =
        a + b + c
}

scala> val x = new Foo
x: Foo = Foo@c1f0c7b
  • 使用全部默认值：
scala> x.foo()
res0: String = 1b2.5
  • 使用命名参数：
scala> x.foo(b = "Hello")
res1: String = 1Hello2.5
  • 使用混合参数：
scala> x.foo(2, c = 1.111)
res2: String = 2b1.111

问题

　　一切看上去都是很完美，用起来也很赏心悦目，但是当参数命名和继承结合到一起的时候，就会很让人困惑。
　　我们先举一个简单的例子，Child类继承Parent类，Child类继承了foo方法，但是我们故意重用相同的名字，却交换了他们的次序，默认值也不同,来表现出它所出现的问题：

class Parent {
    def foo(a: Int = 1, b: Int = 2): Int =
        a + b
}

class Child extends Parent{
    override def foo(b: Int = 3, a:Int = 4): Int =
        super.foo(b, a)
}
  • 声明一个普通的Parent类对象，执行foo方法：
scala> val p = new Parent
p: Parent = Parent@58cf8f94

scala> p.foo()
res0: Int = 3
  • 声明一个Child类对象，执行foo方法：
scala> val c = new Child
c: Child = Child@3a08078c

scala> c.foo()
res1: Int = 7
  • 实例化Child但是声明其静态类型为Parent,并执行foo放法：
scala> val cp: Parent = new Child
cp: Parent = Child@14ef2482

scala> cp.foo()
res2: Int = 7

　　以上结果都是正常的,当我们发现实例化Child类执行foo方法时，发现值为7,我们可以得出结论，默认值是动态的，确实Scala会动态的修改默认值。
　　但是现在问题就要出现了：

scala> c.foo(a = 10)
res3: Int = 13

scala> cp.foo(a = 10)
res4: Int = 14

　　明明都是Child类的实例化，只是cp的静态类型Parent类,为啥对foo方法调用a=10,结果不同呢，很明显c是用了子类的参数顺序去执行，而cp是用了静态类型Parent类的参数类型去执行。
　　为了看的更清楚，我们可以把Parent类中的foo方法改为，Child类中要稍作修改：

def foo(a: Int = 1, b: Int = 2) 
    = println(a + " " + b)

　　在用c和cp分别调用：

scala> c.foo(a = 10)
3 10

scala> cp.foo(a = 10)
10 4

　　这样子，结果就很明显了。

总结

　　从上面的问题我们可以发现Scala里的命名参数是根据静态类型来决定参数的顺序。Scala为参数名使用静态类型或变量，但是它会动态的修改默认值。因此我们可以总结出一个一个规律：
　　名字是静态绑定的，值是动态绑定的。
　　编译器不会为在子类里重命名参数的行为给出警告信息，所以我们需要注意变量的取名。
