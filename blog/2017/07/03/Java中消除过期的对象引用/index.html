Java中消除过期的对象引用

引言

　　众所周知，Java是具有垃圾回收机制的语言，当你用完对象后，它们会自动回收，程序员不需要考虑对象回收的功能。其实不然，使用Java如果不考虑内存管理的事情，依然会出现内存泄露的问题。

栈实现

　　首先我们实现一个简单的栈类，它可以入栈，出栈和扩容：

public class Stack {
    private Object[] elements;
    private int size = 0;
    private static final int DEFAULT_INITIAL_CAPACITY =16;

    public Stack() {
        elements = new Object[DEFAULT_INITIAL_CAPACITY];
    }

    public void push(Object e) {
        ensureCapacity();
        elements[size++] = e;
    }

    public Object pop() {
        if (size == 0) throw new EmptyStackException();
        return elements[--size];
    }

    private void ensureCapacity() {
        if (elements.length == size) elements = Arrays.copyOf(elements, 2 * size + 1);
    }
}

　　这段程序，乍一看没有明显的错误，无论如何测试它都会通过测试，但是实际上它有个潜在的内存泄露的bug。

内存泄露

　　那么程序到底是哪里发生了内存泄露了呢？
　　其实是发生在这里，如果一个栈先是增长，然后再收缩，那么从栈中弹出的对象不会被当作垃圾回收，即使用栈的程序不再引用这些对象，它们也不会被回收。
　　这是因为，栈内部维护着对象的过期引用（obsolete reference）。

过期引用

　　所谓过期引用，是指永远不会再被解除的引用。在本例中，凡是在elements数组的"活动部分"之外的引用都是过期的，活动部分是指elements中小于size的那些元素。

修复

　　这类问题修复的方法很简单，一旦对象引用过期，只需清空这些引用即可。对于上述例子中的Stack类而言，只要一个单元被弹出栈，指向它的引用就过期了，pop方法做下列修订即可：

public Object pop() {
        if (size == 0) throw new EmptyStackException();
        Object result = elements[--size];
        elements[size] = null;
        return result;
}

　　清楚过期引用的另一个好处是，如果它们以后又被错误地接触引用，程序就会立即抛出NullPointerException异常，而不是错误的运行下去。
　　当然，清空对象引用应该是一种例外，而不是一种规范行为，消除过期引用的最好的办法是让包含该引用的变量结束其生命周期。如果你是在最紧凑的作用域范围内定义每一个变量，这种情况就自然不会发生。

注意事项

　　在避免过期引用时，我们需要注意内存泄露的三个重要来源，具体我就不细说了，大家可以查阅相关资料。

  • 只要类是自己管理内存，程序员就应该警惕内存泄露问题
  • 内存泄露经常来自缓存
  • 内存泄露经常来自监听器和其他回调
