利用动态规划解决矩阵链乘法问题

引言

　　给定一个\(n\)个矩阵的序列(矩阵链)\(<A_1,A_2,...,A_n>\)，我们希望计算它的乘积\(A_1A_2...A_n\)，由于大家都知道矩阵乘法满足结合律，因此任何加括号的方法都会得到相同的计算结果，所以我们需要先用括号明确计算次序。
　　我们称有如下性质的矩阵链为完全括号化的(fully parenthesized)：它是单一矩阵，或者两个完全括号化的矩阵乘积链的积，且已外加括号。
　　其实对矩阵加括号的方式会对乘积运算的代价产生巨大的影响，这里的代价我们指的是执行标量乘法的次数，例如一个\(p \times q\)的矩阵和一个\(q \times r\)的矩阵相乘，它所执行的标量乘法的次数就为\(pqr\)。正因如此，加括号的方式会对计算效率产生极大影响，例如我们以矩阵链\(<A_1,A_2,A_3>\)相乘为例，三个矩阵的规模分别为\(10 \times 100\)，\(100 \times 5\)和\(5 \times 50\),如果按\(((A_1A_2)A_3)\)的计算顺序，它的代价是7500，而\((A_1(A_2A_3))\)的顺序计算顺序，代价则为75000，我们看到只是改变了括号的计算顺序，在速度上就产生了10倍的差距。

问题定义

　　**矩阵乘法问题(matrix-chain multiplication probelm)**即，在给定矩阵链\(<A_1,A_2,...,A_n>\)，矩阵\(A_i\)的规模的规模为\(p_{i-1} \times p_i(1 \le n)\)，求完全括号化方案使得计算乘积\(A_1A_2...A_n\)所需标量乘法次数最少。
　　需要注意的是，求解矩阵链乘法问题并不是真正进行矩阵相乘运算，我们的目标只是确定代价最低的计算顺序。

利用自底向上的动态规划算法计算最优代价

　　对于矩阵乘法问题，我们可以将对所有\(1 \le i \le j \le n\)来确定\(A_ｉA_{i+1}...A_j\)的最小代价括号化方案作为子问题。令\(m[i,j]\)表示计算矩阵所需标量乘法次数的最小值，那么原问题的最优解，计算\(A_{1..n}\)所需的最低代价就是\(m[1,n]\)，我们可以容易的推导出\(A_ｉA_{i+1}...A_j\)最小代价括号化方案的递归求解公式变为:

\[ m[i,j] = \begin{cases} 0, & \text{i = j} \\ \min_{i \le k \lt j}\{m[i,k] + m[k+1,j] + p_{i-1}p_{k}p_{j}\}, & \text{i < j} \end{cases} \]

　　\(m[i,j]\)的值给出了子问题最优解的代价，但它并未提供足够的信息来构造最优解。为此，我们用\(s[i,j]\)来保存\(A_ｉA_{i+1}...A_j\)最优括号化方案的分割点位置\(k\)，即使得\(m[i,j]=m[i,k] + m[k+1,j] + p_{i-1}p_{k}p_{j}\)成立的\(k\)值。
　　知道了递归原理后，我们来用Java实现一下代码，因为我们不进行实际的矩阵的运算，所以我们不传入真正的矩阵，\(n\)个矩阵的矩阵链我们仅用一个\(n\)行2列的二维数组代替了。

	//a direct down-top method, just return the best value
    int matrixChainOrderVal(int[][] matrixs) {
        int n = matrixs.length;
        int[][] m = new int[n][n];
        int[][] s = new int[n][n];

        for (int i = 0; i < n; i++) m[i][i] = 0;
        for (int l = 1; l < n; l++) {
            for (int i = 0; i < n -l; i++) {
                int j = i + l;
                int q;
                m[i][j] = Integer.MAX_VALUE;
                for (int k = i; k < j; k++) {
                    q = m[i][k] + m[k+1][j] + matrixs[i][0] * matrixs[k][1] * matrixs[j][1];
                    if (q < m[i][j]) {
                        m[i][j] = q;
                        s[i][j] = k;
                    }
                }
            }
        }

        return m[0][n - 1];
    }

    //a direct down-top method, return the whole array
    int[][] matrixChainOrderArr(int[][] matrixs) {
        int n = matrixs.length;
        int[][] m = new int[n][n];
        int[][] s = new int[n][n];

        for (int i = 0; i < n; i++) m[i][i] = 0;
        for (int l = 1; l < n; l++) {
            for (int i = 0; i < n -l; i++) {
                int j = i + l;
                int q;
                m[i][j] = Integer.MAX_VALUE;
                for (int k = i; k < j; k++) {
                    q = m[i][k] + m[k+1][j] + matrixs[i][0] * matrixs[k][1] * matrixs[j][1];
                    if (q < m[i][j]) {
                        m[i][j] = q;
                        s[i][j] = k;
                    }
                }
            }
        }

        return m;
    }

　　第一个方法是返回最优解的代价，而第二个方法返回整个\(m\)数组，我们可以看到算法的时间效率是\(O(n^3)\)，还需要额外的空间效率\(O(n^2)\)来保存\(m\)和\(s\)，比起穷举所有可能的括号化方案来寻找最优解的指数阶算法要高效得多。

输出最优括号化方案

　　在得到最优解后，如果我们还需要吧构造最优解的方案输出，就很简单了，因为矩\(A_iA_{i+1}...A_j\)的分割点都保存在\(s[i,j]\)里，所以我们只需要递归输出数组\(s\)就可以了。

private String printOptimalParens(int[][] s, int i, int j) {
    if (i == j) return "A[" + i + "]";
    else return "(" + printOptimalParens(s, i, s[i][j])
            + printOptimalParens(s, s[i][j] + 1, j) + ")";
}

自底向下的备忘递归算法

　　普通的递归实现时间复杂度是指数级，因为它需要重复计算许多子问题，所以我们增加一个辅助数组来保存这些子问题的解，这样就把时间复杂度降为了\(O(n^3)\)。

int memoizedMatrixChain(int[][] matrixs) {
    int n = matrixs.length;
    int[][] m = new int[n][n];
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            m[i][j] = Integer.MAX_VALUE;

    return lookupChain(matrixs, m, 0, n - 1);
}

int lookupChain(int[][] matrixs, int[][] m, int i, int j) {
    if (m[i][j] < Integer.MAX_VALUE) return m[i][j];
    if (i == j) m[i][j] = 0;
    else {
        for (int k = i; k < j; k++) {
            int q = lookupChain(matrixs, m, i, k) +
                    lookupChain(matrixs, m, k + 1, j) +
                    matrixs[i][0] * matrixs[k][1] * matrixs[j][1];
            if (q < m[i][j]) m[i][j] = q;
        }
    }

    return m[i][j];
}

比较

　　自底向下的备忘递归算法和自底向上的动态规划算法的时间复杂度都是\(O(n^3)\)。
　　但是通常情况下如果每个子问题都必须至少求解一次，自底向上的动态规划算法会比自底向下的备忘算法快一些（都是\(O(n^3)\)，相差一个常量系数），因为自底向上的动态规划算法没有递归调用的开销，表的维护开销也更小。而且对于某些问题，我们可以利用表的访问模式来进一步降低时空代价。
　　相反，如果子问题空间中的某些子问题完全不必求解，自底向下的备忘递归算法就会体现出优势了，因为它只会求解那些绝对必要的子问题。
