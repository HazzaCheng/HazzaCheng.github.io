引言

　　大家都知道Scala有一个非常强大的隐式转换系统，它定义了一套良好的查找机制，让编译器能够调整代码。也就是指程序员可以故意的漏掉一些信息，编译器会尝试在编译期自动推理出来。截至Scala2.12，Scala的编译器可以推导出下面两种情况：

  • 缺少参数的方法调用或构造器调用
  • 缺少了从一种类型到另一种类型的转换，就是指在某对象上调用不存在的方法时，隐式转换自动把对象转换成有该方法的对象。

隐式转换系统

　　Scala提供了implicit关键字，可以通过两种方式使用：

  • 方法或变量定义
  • 方法参数列表

　　如果关键字用在方法或变量定义上，就等于告诉编译器在隐式解析，隐式解析是指编译器发现代码里缺少部分信息，而去查找缺失的信息的过程。
　　implicit也能用在方法参数列表的开头，这告诉编译器参数值有可能缺失，这种情况下编译器应当通过隐式解析来确定参数值。
　　我们举个例子,来看一下通过隐式解析机制来确定缺少的参数值的过程:

  • printAnInt方法声明了参数x，类型为Int，是implicit的：
scala> def printAnInt(implicit x: Int) = println(x)
printAnInt: (implicit x: Int)Unit
  • 不传参调用方法：
scala> printAnInt
<console>:13: error: could not find implicit value for parameter x: Int
       printAnInt
       ^

　　不出意料，编译器报错，无法为x参数找到一个隐式值。

  • 提供一个int型的隐式值：　
scala> implicit val intVal = 10
intVal: Int = 10
  • 再次无参调用：
scala> printAnInt
10

　　我们可以看到，这次可以成功找到隐式值并打印出来。

  • 有参调用：
scala> printAnInt(1)
1

　　这说明,隐式方法的参数仍然能够显式地给出。

隐式解析

　　Scala语言规范定义了以下两种查找标记为implicit的实体的规则:

  • 隐式实体在查找发生的地点可见，并且没有任何前缀，比如不能是foo.x，只能是x。
  • 如果按照前一条规则没有找到隐式实体，那么会在隐式参数的类型的隐式作用域里包含的所有隐式实体里查找。

　　第一个规则，比较好理解，就是我们前面举的那个例子，第二个规则就有点复杂了，当编译器无法用第一个规则找到任何可用的隐式实体时，就会使用第二个规则。在这种情况下，编译器会在其目标类型的隐式作用域里面的任何对象里查找定义于其中的隐式实体。
　　一个类型的隐式作用域是指与该类型相关联的全部伴生模块。那么这里就涉及到两个关键词关联和伴生模块，分别是什么意思呢？

伴生模块

　　我们来举个例子，我们用一个holder对象来做包装，以便在REPL里定义trait和其伴生对象：

object holder {
     | 　trait Foo
     | 　object Foo {
     | 　　implicit val x = new Foo {
     | 　　　override def toString = "Companion Foo"
     | 　　}
     | 　}
     | }
defined object holder

　　接下来我们引入holder.Foo,并定义一个方法接收一个Foo类型的隐式参数：

scala> import holder.Foo
import holder.Foo

scala> def test(implicit foo: Foo) = println(foo)
test: (implicit foo: holder.Foo)Unit

　　我们试试无参调用test方法：

scala> test
Companion Foo

　　我们可以看到，通过隐式作用域可以实现隐式解析。
　　同时因为隐式作用域是第二优先级的，我们可以用隐式作用域来保存默认隐式实体，同时允许用户在必要的时候导入他们自己的隐式实体来覆盖掉默认的。

关联

　　T的隐式作用域是指与T类型相关联的所有类型的伴生对象集合。Scala语言规范里定义的"关联"是指类型T的某部分的任何一个基类。这里的类型T的某部分是这样定义的:

  • T的全部子类型都是T的部分，例如T定义为A with B with C,那么A，B，C都是T的部分，在隐式解析过程中，它们的伴生对象会被搜索。
  • 如果T是参数化类型，那么所有类型参数和类型参数的部分都算作T的部分，例如List[String]的隐式搜索会搜索List的伴生对象和String的伴生对象。
  • 如果T是一个单例类型p.T，那么类型p的部分也包含在T的部分里。也就是说，如果类型T在某个对象里，那么那个对象也会被搜索。
  • 如果T是个类型注入S#T，那么S的部分也包含在T的部分里。也就是说如果类型T位于某个类或特质里，那么那个类或特质的伴生对象也会被搜索。

隐式作用域

通过类型参数来获得隐式作用域

　　Scala语言把隐式作用域定义为包括其类型参数的全部伴生对象和子类型。也就是说，我们可以通过在Foo的伴生对象里定义隐式实体来个List[Foo]提供值：

scala> object holder {
     |  trait Foo 
     |  object Foo {
     |   implicit val list = List(new Foo{})
     |  }
     | }
defined object holder

　　implicitly函数用于在当前作用域里查找指定类型，我们调用implicitly查找类型List[holder.Foo]返回了定义在Foo的伴生对象里的隐式实体list：

scala> implicitly[List[holder.Foo]]
res0: List[holder.Foo] = List(holder$Foo$$anon$1@5c4f4330)

　　这样有什么应用呢，我们来举个例子吧：

trait BinaryFormat[T] {
  def asBinary(entity: T): Byte
}

　　BinaryFormat特质定义了asBinary方法。接受类型参数的实例，返回代表该参数的字节。需要把对象序列化到磁盘的代码，现在可以尝试通过隐式解析去查找BinaryFormat特质。我们可以通过在Foo的伴生对象里提供一个隐式实现来让Foo类型拥有序列化的能力。

trait Foo {}
object Foo {
  implicit lazy val binaryFormat = new BinaryFormat[Foo] {
    override def asBinary(entity: Foo): Byte = "serializedFoo".toByte
  }
}

　　Foo特质定一个为空特质，其伴生对象定义了一个隐式的值，用来放二进制格式的实现。现在当需要Binary的代码看到类型Foo时，它就能够找到其BinaryFormat的隐式转换。

通过嵌套获得隐式作用域

　　如果类型是定义在一个外部作用域里面，那么其外部作用域的伴生对象也包含在它的隐式作用域里。这允许我们给外部作用域的类型提供一些便利的隐式绑定：

scala> object Foo {
     |  trait Bar
     |  implicit def newBar = new Bar {
     |   override def toString = "Implicit Bar"
     |  }
     | }
defined object Foo

scala> implicitly[Foo.Bar]
res1: Foo.Bar = Implicit Bar

　　我们可以看到，Foo对象是外部类型，Bar特质定义在它内部，Foo对象同时定义了创建Bar特质的实例的隐式方法。当调用implicity[Foo.Bar]的时候，编译器通过搜索Foo的外部类找了隐式值。这个技巧类似于把隐式值绑定直接放在伴生对象里。

  • 当外部作用域里包含好几个子类型时，为嵌套类型定义隐式绑定是非常方便的技巧。
  • 当你无法在伴生对象里创建隐式绑定时可以使用这种技巧。

　　Scala对象没办法用用伴生对象（及其隐式绑定），因此如果想要在对象类型的隐式作用域里提供其相关的隐式绑定，就只能通过外部作用域来实现。

scala> object Foo {
     |  object Bar { override def toString = "Bar" }
     |  implicit def b: Bar.type = Bar 
     | }
defined object Foo

scala> implicitly[Foo.Bar.type]
res2: Foo.Bar.type = Bar

　　Bar对象嵌套在Foo对象里，Foo对象也定义了一个隐式绑定，返回Bar.Type。现在，当调用implicitly[Foo.Bar.type]时返回Bar对象，通过这种机制可以对对象定义隐式绑定。

包对象

　　从Scala２.8开始对象可以定义为包对象。任何定义在某个包里的类都算作该包的嵌套类。任何定义在包对象里的隐式绑定对于定义在该包里的所有类型都可见。这样就有了一个方便的位置来存放隐式绑定，而用不着为包里的每个类型都定义伴生对象。

package object foo {
  implicit def foo = new Foo
}

package foo {
  class Foo {
    override def toString: String = "Foo!"
  }
}

　　在Scala里包可以定义在多个源文件里，定义在多个文件里的类型最后会聚合起来成为一个完整的包。不过一个包的包对象只能存在与一个源码文件里，Foo对象覆盖了toString方法，输出字符串"Foo!"。

scala> implicitly[foo.Foo]
res0: foo.Foo = Foo!

隐式视图

　　隐式视图是指把一种类型自动转换到另一种类型，以符合表达式的要求。

scala> implicit def intToString(i: Int): String = i.toS
toShort   toString

scala> implicit def intToString(i: Int): String = i.toString
intToString: (i: Int)String

scala> foo(5)
5

　　例如我们定义隐式方法intToString，它接受一个整型类型的值，返回字符串，这个方法就是隐式视图，通常称为Int => String的隐式视图。

适用场景

  • 如果表达式不符合编译器要求的类型，编译器会查找能使之符合类型要求的隐式视图。
  • 给定一个选择e.t，这里的选择是指成员变量访问，如果e的类型里并没有成员t，则编译器会查找能应用到e类型且返回类型包含成员变量t的隐式视图。

隐式作用域

　　隐式视图所使用的隐式作用域与隐式参数相同，但是当编译器查找相关联类型时，会使用转换的"源类型"而不是"目标类型"，我们举个例子。

scala> object handler {
     |   trait Foo
     |   trait Bar
     |   object Foo {
     |     implicit def fooToBar(foo: Foo) = new Bar {}
     |   }
     |   object Bar {
     |     implicit def fooToString(foo: Foo) = "Foo"
     |   }
     | }
defined object handler

scala> import handler._
import handler._

scala> def bar(x: Bar) = println("Bar")
bar: (x: handler.Bar)Unit

scala>def str(x: String) = println(x)
str: (x: String)Unit

　　我们在handler对象里创建了Foo的特质和伴生对象，Bar的特质和伴生对象，定义了两个隐式视图，在Foo的伴生对象里定义了Foo => Bar的隐式试图，在Bar的伴生对象里定义了Foo => String的隐式试图，并且在handler外部定义了两个方法，分别接受Bar对象和String对象。
　　按照Scala的规定，当编译器查找隐式试图时是使用源类型的隐式作用域，这意味着在Foo伴生对象里的隐式视图只有在视图把Foo类型转为其他类型时才会用，Bar伴生对象里的隐式视图只有在视图把Bar类型转为其他类型时才会用,我们来测试一下。

scala> val x = new Foo {}
x: handler.Foo = $anon$1@4ce94d2f

scala> bar(x)
Bar

scala> str(x)
<console>:19: error: type mismatch;
 found   : handler.Foo
 required: String
       str(x)

情况与我们所设想的一样。

作用

　　这种隐式转换可以帮助我们在，库与库之间做适配，或者给别人写的类型添加我们自定义的便利方法，在Scala里的一个常用实践是对Java库做些适配。举个例子，我们来给java.io.File加一个便利方法，添加一个便捷的操作符/，使两个文件路径连起来。

class FileWrapper(val file: java.io.File) {
  def /(next: String) = new FileWrapper(new java.io.File(file, next))
  override def toString: String = file.getCanonicalPath()
}

object FileWrapper {
  implicit def wrap(file: java.io.File) = new FileWrapper(file)
}

　　我们在FileWrapper的伴生对象里添加了一个隐式视图，我们用REPL类看下这个实际的用法：

scala> import com.hazza.test.FileWrapper.wrap
import com.hazza.test.FileWrapper.wrap

scala> val cur = new java.io.File(".")
cur: java.io.File = .

scala> cur / "test.txt"
res0: com.hazza.test.FileWrapper = /home/hazza/codes/scala/study4scala/src/main/scala/com/hazza/test/test.txt

　　我们可以看到成功了，我们可以通过隐式视图给别人写的类型添加我们自定义的便利方法。
　　但是，FileWrapper还有一个缺陷就是调用＂/＂会返回一个FileWrapper对象，这意味这不能直接把结果传递给需要java.io.File类型参数的方法。我们可以修改"/“方法传回一个java.io.file对象，但是我们可以通过在伴生对象里添加一个unwrap的隐式视图。

object FileWrapper {
  implicit def wrap(file: java.io.File) = new FileWrapper(file)
  implicit def unwrap(wrapper: FileWrapper) = wrapper.file
}

　　我们在REPL里测试一下：

scala> import com.hazza.test.FileWrapper.wrap
import com.hazza.test.FileWrapper.wrap

scala> val cur = new java.io.File(".")
cur: java.io.File = .

scala> def useFile(file: java.io.File) = println(file.getCanonicalPath)
useFile: (file: java.io.File)Unit

scala> useFile(cur / "test.txt")
/home/hazza/codes/scala/study4scala/src/main/scala/com/hazza/test/test.txt

　　我们看到可以正常使用，你可能会有疑问，为什么仅仅导入了wrap，没有导入unwrap,但是编译器还是找到隐式视图了，这是因为使用wrap的时候，编译器实际上并不知道什么类型能让cur / “test.txt"编译通过，而java.io.File有没有伴生对象，因此编译器之查找了本地作用域。这特性是我们提供具有额外功能的包装对象，和包装类型几乎无缝地自动转换。

隐式参数与默认参数相结合

　　隐式参数提供了很好的机制，让用户无需指定冗余的参数。这个机制与默认参数也能很好的协同。当未提供参数，且通过隐式解析无法找到隐式值的时候，编译器就会使用默认参数，这样我们就可以创建默认参数来让用户不必输入冗余的参数，同时允许用户在需要的时候提供不同的参数。
　　接下来我们举书中一个关于矩阵计算的例子来看看这一特性的灵活性。

单线程的矩阵运算

class Matrix(private val repr: Array[Array[Double]]) {
  def row(idx: Int): Seq[Double] = {
    repr(idx)
  }

  def col(idx: Int): Seq[Double] = {
    repr.foldLeft(ArrayBuffer[Double]()) {
      (buffer, currentRow) =>
        buffer.append(currentRow(idx))
        buffer
    }.toArray
  }

  lazy val rowRank = repr.length
  lazy val colRank = if (rowRank > 0) repr(0).length else 0

  override def toString: String = "Matrix" + repr.foldLeft("") {
    (msg, row) => msg + row.mkString("\n|", " | ", "|")
  }
}

trait ThreadStrategy {
  def execute[A](func: Function0[A]): Function0[A]
}

object SameThreadStrategy extends ThreadStrategy {
  override def execute[A](func: () => A) = func
}

object MatrixUtils {
  def multiply(a: Matrix, b: Matrix)(implicit threading: ThreadStrategy): Matrix = {
    assert(a.colRank == b.rowRank)
    val buffer = new Array[Array[Double]](a.rowRank)
    for (i <- 0 until a.rowRank) buffer(i) = new Array[Double](b.colRank)

    def computeVal(row: Int, col: Int): Unit = {
      val pairElements = a.row(row).zip(b.col(col))
      val products = for ((x, y) <- pairElements) yield x * y
      val result = products.sum
      buffer(row)(col) = result
    }

    val computions = for {
      row <- 0 until a.rowRank
      col <- 0 until b.colRank
    } yield threading.execute(() => computeVal(row, col))
    computions.foreach(_())

    new Matrix(buffer)
  }
}

　　具体的代码实现，我也不多说，大家自己理解，在multiply方法里我们将threading设置了隐式参数，并将它进行了柯里化，我们为什么要进行柯里化呢？因为implicit关键字应用与全体参数列表，而不是单独的参数，所以我们需要将threading参数柯里化出来，让它与前面的参数有所区分。
　　SameThreadStrategy是我们继承自ThreadStrategy接口的单线程的单例对象，要想使单线程进行矩阵计算，我们只需要提供一个SameThreadStrategy的隐式值就可以了，我们来测试一下。

scala> import com.hazza.Matrix
import com.hazza.Matrix

scala> import com.hazza.MatrixUtils
import com.hazza.MatrixUtils

scala> import com.hazza.SameThreadStrategy
import com.hazza.SameThreadStrategy

scala> implicit val sts = SameThreadStrategy
sts: com.hazza.SameThreadStrategy.type = com.hazza.SameThreadStrategy$@e322ec9

scala> val x = new Matrix(Array(Array(1, 2, 3), Array(23.2, 22.1, 99.8), Array(76.2, 21.2, 11.2)))
x: com.hazza.Matrix =
Matrix
|1.0 | 2.0 | 3.0|
|23.2 | 22.1 | 99.8|
|76.2 | 21.2 | 11.2|

scala> val y = new Matrix(Array(Array(1, 3.2), Array(23.2, 11.2), Array(76.2, 87)))
y: com.hazza.Matrix =
Matrix
|1.0 | 3.2|
|23.2 | 11.2|
|76.2 | 87.0|

scala> MatrixUtils.multiply(x, y)
res0: com.hazza.Matrix =
Matrix
|276.0 | 286.6|
|8140.68 | 9004.36|
|1421.48 | 1455.6799999999998|

　　我们可以看出，编译器找到了隐式值，并正确的执行了计算。

多线程的矩阵运算

　　创建多线程的服务，我们只需要继承自ThreadStrategy接口再实现一个多线程的单例对象就行了，我们主要采用Java的线程池的相关功能与接口，线程数量等于CPU核心数量。

object ThreadPoolStrategy extends ThreadStrategy {
  val pool = Executors.newFixedThreadPool(
    java.lang.Runtime.getRuntime.availableProcessors());
  def execute[A](func: Function0[A]) = {
    val future = pool.submit(new Callable[A] {
      override def call(): A = {
        Console.println("Executing function on threads:" + Thread.currentThread().getName)
        func()
      }
    })
    () => future.get()
  }
}

　　execute方法接收传入函数，创建一个匿名回调实例。Java并发库用Callable接口来把任务传递给线程池，任务提交后返回Future对象，可以用来判断传入任务是否完成。execute方法的最后一行返回一个闭包，闭包里面调用future的get方法，这个调用会阻塞，直到函数执行完成并返回函数的执行结果。每当在Callable里的函数执行时，它会打印一条信息，告诉它是在哪个线程执行的。
　　我们来测试一下：

scala> import com.hazza.Matrix
import com.hazza.Matrix

scala> import com.hazza.MatrixUtils
import com.hazza.MatrixUtils

scala> import com.hazza.ThreadPoolStrategy
import com.hazza.ThreadPoolStrategy

scala> implicit val tps = ThreadPoolStrategy
tps: com.hazza.ThreadPoolStrategy.type = com.hazza.ThreadPoolStrategy$@479f738a

scala> val x = new Matrix(Array(Array(1, 2, 3), Array(23.2, 22.1, 99.8), Array(76.2, 21.2, 11.2)))
x: com.hazza.Matrix =
Matrix
|1.0 | 2.0 | 3.0|
|23.2 | 22.1 | 99.8|

　　我们发现有六个线程参与了计算，这正好与32的矩阵和23的矩阵计算，要执行六次行列相乘相吻合。
　　我们同样也可以给库的用户提供一个默认策略，同时又允许它们在需要的时候覆盖默认策略。我们可以用默认参数机制来提供默认策略，当隐式作用域里没有默认值时编译器会使用默认参数，也就是说用户可以通过在隐式作用域里导入或创建自己的ThreadStrategy来覆盖默认策略，也可以在调用方法时显示传入默认的ThreadStrategy，我们举个例子。

  def multiply(a: Matrix, b: Matrix)(
    implicit threading: ThreadStrategy = SameThreadStrategy
  ): Matrix = {
    assert(a.colRank == b.rowRank)
    val buffer = new Array[Array[Double]](a.rowRank)
    for (i <- 0 until a.rowRank) buffer(i) = new Array[Double](b.colRank)

    def computeVal(row: Int, col: Int): Unit = {
      val pairElements = a.row(row).zip(b.col(col))
      val products = for ((x, y) <- pairElements) yield x * y
      val result = products.sum
      buffer(row)(col) = result
    }

    val computions = for {
      row <- 0 until a.rowRank
      col <- 0 until b.colRank
    } yield threading.execute(() => computeVal(row, col))
    computions.foreach(_())

    new Matrix(buffer)
  }

　　我们给threading添加了默认值，这样即使我们在隐式作用域里不提供隐式值，这个方法也会有值去进行计算。当我们想覆盖掉默认值的时候，只需要提供隐式值就可以了。

限制隐式系统的作用域

　　在Scala里，隐式绑定通常可能处在:

  • 所有关联类型的伴生对象，包括包对象。
  • scala.Predef对象
  • 作用域里所有导入语句

　　我们在定义期望被显示导入的隐式视图或隐式参数时，需要确保一下几点:

  • 隐式视图或参数与其他隐式值没有冲突。
  • 隐式视图或参数的名字不和scala.Predef对象里的任何东西冲突。
  • 隐式视图或参数能够被库或模块的用户能够找到。

　　在Scala社区里，通常的做法是把可导入隐式转换限制在一下两个位置之一:

  • 包对象
  • 带Implicits后缀的单例对象

表达复数的库

　　我们通过隐式转换的第二个查阅规则知道，隐式转换不需要任何形式的导入就能很好的发挥作用，也就是通过关联类型的伴生对象查找，使得无需明确的导入就能使用隐式转换。我们通过《Scala In Depth》中的一个复数库的例子来更加具体的了解一下这个特性。

  • 我们首先定义一个表示复数的case class:
case class ComplexNumber(real: Double, imaginary: Double) {
  def *(other: ComplexNumber) =
    ComplexNumber(real * other.real + imaginary * other.imaginary,
      real * other.imaginary + imaginary * other.real)
  
  def +(other: ComplexNumber) =
    ComplexNumber(real + other.real, imaginary + other.imaginary)
}

　　复数类支持乘法和加法，我们在REPL里实验一下：

package com.hazza.complexMath

case class ComplexNumber(real: Double, imaginary: Double) {
  def *(other: ComplexNumber) =
    ComplexNumber(real * other.real + imaginary * other.imaginary,
      real * other.imaginary + imaginary * other.real)

  def +(other: ComplexNumber) =
    ComplexNumber(real + other.real, imaginary + other.imaginary)
}

　　可以正常运算。

  • 在包对象complexMath里用符号i定义-1的平方根，注意ComplexNumber不在complexMath包里
package com.hazza

package object complexMath {
  val o = ComplexNumber(0.0, 1.0);
}

　　这样就在complexMath包里定义了val i，这使名字在complex包内可见，也使它可以被直接导入。可以用这个名字通过实部或虚部构建复数，但是当我们想用一个double数乘以i时，会报错，所以我们需要定义一个隐式视图。

  • 在complexMath包对象里定义一个Double => ComplexNumber的隐式视图
package com.hazza

package object complexMath {
  val ｉ = ComplexNumber(0.0, 1.0);

  implicit def double2ComplexNumber(d: Double): ComplexNumber =
    new ComplexNumber(d, 0.0)
}

　　我们在REPL里实验一下：

scala> import com.hazza.complexMath.i
import com.hazza.complexMath.i

scala> i * 3 + 1
res1: com.hazza.complexMath.ComplexNumber = ComplexNumber(1.0,3.0)

　　我们看到可以成功进行隐式转换，并且我们不需要显示的导入double2ComplexNumber，我们只从complexMath里导入了名字i，其他的隐式转换都是由i触发的，当然我们也可以显示地引入隐式视图，这样做的缺点当然就是现在作用域里多了一个Double类型的隐式视图，如果我们恰好定义了其他给Double的隐式视图，编译器就会报有岐义的隐式转换的错误，从而导致无法通过编译。如果出现冲突，我们也只能通过不导入Double => ComplexNumber的隐式视图来避免冲突。

惯用法

　　通过这个例子，我们也知道避免隐式转换的惯用法，这样也可以创建强有力的代码，按照《Scala In Depth》可以采取一下形式:

  • 定义库的核心抽象，比如ComplexNumber类
  • 在某个关联类型里定义表达力的语法所需要的隐式转换。Double => Complex的隐式转换定义在与ComplexNumber关联的包对象里，因此可以在任何涉及ComplexNumber类型的隐式查找过程中被发现。
  • 在库里定义入口点，使入口点之后的隐式转换是无歧义的。在complexMath库里，i就是个入口点。
  • 有些情况无法避免显示导入。

总结

　　通过学习Scala强大的隐式转换系统，我们深深的感受到Scala语言的巨大魅力。
　　Scala支持两种形式的隐式转换:

  • 隐式值
  • 隐式视图

　　隐式视图可以用于:

  • 类型间转换
  • 使针对某类型的方法调用能成功

　　隐式视图和隐式值都使用相同的隐式解析机制，隐式解析采用一种两阶段过程:

  • 第一阶段在当前作用域里查找不带前缀的隐式转换
  • 第二阶段在关联对象的伴生对象里进行查找

　　隐式转换是十分强大的手段，可以增强已有类，隐式转换还可以和默认参数协作，使行为限定在某个隐式值的作用域内，需要我们负责任的使用，限制隐式转换的作用域，并把它们定义在众所周知，容易查找的位置。
