Scala学习笔记（五）- Scala中的＂致命钻石问题＂

引言

　　在Scala中，引入了override关键字，这个关键字区分一个方法是否要覆盖还是重载另一个方法。

  • 如果你漏了这个关键字，而编译器发现你在覆盖超类里的方法，编译器会发出警告。
  • 如果你加了overrid关键字，而超类里没有能覆盖的方法，编译器也会发出警告

　　但有一种情况overrid不是必须的，即如果是超类中的方法纯抽象方法，就不需要添加override关键词，纯抽象方法是指只有声明没有实现的方法。
　　那么，Scala为什么要这样做了呢？本文即将探讨一下这个问题。

特质与类中的覆盖方法

　　首先，我们来举个例子说明下在类与特质中不加override关键词的区别。

  • 先声明一个超类和子类：
trait Parent {
  def foo(data: String)
}

class Child extends Parent {
  def foo(data: String) = "I am child!"
}

　　我们可以看到子类中覆盖方法没有添加override关键词，顺利通过编译。

  • 修改超类中的底层方法：
trait Parent {
  def foo(new_data: Int)  //修改后的方法
}

class Child extends Parent {
  def foo(data: String) = "I am child!"   //编译不通过
}

　　我们将超类中foo方法的参数类型修改之后，子类就无法正常编译了，因为Child是个具体的类，编译器会发现Parent的foo方法没有实现，所以会编译失败。那么如果我们不提供具体类，而是提供一个部分功能的库呢？

  • 将Child类换成特质：
trait Parent {
  def foo(new_data: Int)  //修改后的方法
}

trait Child extends Parent {
  def foo(data: String) = "I am child!"   //编译通过
}

　　我们可以发现，变成特质后，编译通过了。在提供没有具体实现的库或者提供某种期望被用户扩展的DSL的时候，这问题就会发生，这意味着只有库用户很容易注意到这一点，才能避免错误，所以我们需要对每个覆盖方法使用override关键字。

  • 对覆盖方法添加override关键字：
trait Parent {
  def foo(new_data: Int)  //修改后的方法
}

trait Child extends Parent {
  override def foo(data: String) = "I am child!"   //编译错误
}

　　添加override关键字之后，编译就会报错。
　　那么既然这么容易就可以避免犯这种错误，Scala为什么又允许不添加override关键字呢？

多重继承

　　Scala之所以不要求实现抽象类的时候使用override关键字就是为了帮助多重继承。
　　我们考虑下多重继承中经典的＂致命钻石＂问题，如果一个类继承自两个父类，而两个父类又继承自同一个祖先，就产生了＂致命钻石＂问题，画个继承关系图，就能看到一个钻石菱形。
　　我们来实践一下，构造一个基础特质Fruit,两个特质Banana和Apple继承自基础特质Fruit：

trait Fruit {
    def color: String
}

trait Apple extends Fruit {
    override def color: String = "Red" 
}

trait Banana extends Fruit {
    override def color: String = "Yellow" 
}

　　我们试图把Apple和Banana组合起来，创造一个新的物种AppleBanana,这是一个很恐怖的事，我们看看能不能实现呢：

scala> val appleBanana = new Apple with Banana
appleBanana: Apple with Banana = $anon$1@3811510

scala> appleBanana.color
res1: String = Yellow

scala> val bananaApple = new Banana with Apple
bananaApple: Banana with Apple = $anon$1@55c1ced9

scala> bananaApple.color
res2: String = Red

　　我们看到不管是Apple混入Banana，还是Banana混入Apple,都成功的混入，而由于Scala类线性化的特性越靠近右边的特质越起作用。
　　如果我们去掉特质里的override关键字会怎么样：

trait Fruit {
    def color: String
}

trait Apple extends Fruit {
    def color: String = "Red" 
}

trait Banana extends Fruit {
    def color: String = "Yellow" 
}

　　开始互相混入：

scala> val appleBanana = new Apple with Banana
<console>:13: error: <$anon: Apple with Banana> inherits conflicting members:
  method color in trait Apple of type => String  and
  method color in trait Banana of type => String
(Note: this can be resolved by declaring an override in <$anon: Apple with Banana>.)
       val appleBanana = new Apple with Banana
                             ^

scala> val bananaApple = new Banana with Apple
<console>:13: error: <$anon: Banana with Apple> inherits conflicting members:
  method color in trait Banana of type => String  and
  method color in trait Apple of type => String
(Note: this can be resolved by declaring an override in <$anon: Banana with Apple>.)
       val bananaApple = new Banana with Apple

　　我们看到这样就无法混入了，编译错误，指出我们试图覆盖方法但没有写override关键字。编译器不让我们组合两个没有明确标注为override的具体方法。这便阻止了多重继承下子类之间相互混入同一方法，借此来处理多重继承中的方法覆盖的问题。那么我们再来试一试一个特质override了，另外一个没有会发生什么：

trait Fruit {
    def color: String
}

trait Apple extends Fruit {
    override def color: String = "Red" 
}

trait Banana extends Fruit {
    def color: String = "Yellow" 
}

　　互相混入：

scala> val bananaApple = new Banana with Apple
bananaApple: Banana with Apple = $anon$1@395eb363

scala> val appleBanana = new Apple with Banana
<console>:13: error: <$anon: Apple with Banana> inherits conflicting members:
  method color in trait Apple of type => String  and
  method color in trait Banana of type => String
(Note: this can be resolved by declaring an override in <$anon: Apple with Banana>.)
       val appleBanana = new Apple with Banana

　　如你所见，Apple混入Banana仍然失败，因为Banana没有标注其color方法可以覆盖。

总结

　　我们同过比较可以发现，Scala之所以不要求实现抽象类的时候使用override关键字就是为了帮助多重继承，来处理多重继承中的方法覆盖的问题。
　　Scala的特质是线性化的，所以如果想要使用覆盖的方法，可以在实例化的时候混入父类，而不需要定义新的类。

trait Fruit { def color: String }
trait SweetFruit extends Fruit
trait Apple { def color = "Red" }

scala> val apple = new SweetFruit with Apple
apple: SweetFruit with Apple = $anon$1@c651286

scala> apple.color
res3: String = Red
