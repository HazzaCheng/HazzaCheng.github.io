Java中避免创建不必要对象的方法

引言

　　一般来说，最好能重用对象而不是在每次需要创建对象的时候创建一个功能相同的对象。重用方式既快速，又流行。如果对象是不可变的，它就始终可以被重用。

重用不可变对象

例子

String s = new String("example");

　　按照这种方式创建String对象，每次被执行的时候都会创建一个新的String实例，但是这些对象的创建都是没有必要的。传递给String构造器的参数(“example”)本身就是一个String实例，功能方面等同于构造器创建出来的所有对象。如果这种方法是在一个循环中的话，或者是在一个被频繁调用的方法中就会创建出成千上万的不必要的String实例。

String s = "example";

　　相反，这个版本只用了Sting实例，而不是每次执行的时候都创建一个实例。而且它可以保证，对于所有在同一台虚拟机中运行的代码，只要它们包含相同的字符串字面常量，该对象就会被重用，这就是所谓的JVM中的字符串常量池。

静态工厂方法

　　对于同时提供了静态工厂方法和构造器的不可变类，通常可以使用静态工厂方法而不是构造器，以避免创造不必要的对象。
　　例如，静态工厂方法Boolean.valueOf（String）几乎总是优先于构造器Boolean（String）。构造器在每次调用的时候都会创建一个新的对象，而静态工厂方法则从来不要求这样做。

重用已知不会被修改的可变对象

　　除了重用不可变的对象外，也可以重用那些已知不会被修改的可变对象，如下面的例子：

public class Birth {
    private final Date birthDate;

    public boolean isPost90s() {
        Calendar calendar = Calendar.getInstance(TimeZone.getTimeZone("GMT"));
        calendar.set(1990, Calendar.JANUARY, 1, 0, 0, 0);
        Date startDay = calendar.getTime();
        calendar.set(2000, Calendar.JANUARY, 1, 0, 0, 0);
        Date endDay = calendar.getTime();

        return birthDate.compareTo(startDay) >= 0 &&
                birthDate.compareTo(endDay) < 0;
    }
}

　　这个类里主要包含了一个根据生日判断是不是90后的方法，isPost90s每次被调用的时候，都会新建一个Calender、一个TimeZone和两个Date实例，这些都是不必要的。
　　下面的版本用一个静态的初始化器，避免了这种效率低下：

public class Birth {
    private final Date birthDate;

    private static final Date START_DAY;
    private static final Date END_DAY;

    static {
        Calendar calendar = Calendar.getInstance(TimeZone.getTimeZone("GMT"));
        calendar.set(1990, Calendar.JANUARY, 1, 0, 0, 0);
        START_DAY = calendar.getTime();
        calendar.set(2000, Calendar.JANUARY, 1, 0, 0, 0);
        END_DAY = calendar.getTime();
    }
    public boolean isPost90s() {
        return birthDate.compareTo(START_DAY) >= 0 &&
                birthDate.compareTo(END_DAY) < 0;
    }
}

　　改进后的Birth类只在初始化的时候创建一个Calender、一个TimeZone和两个Date实例，而不是在isPost90s被每次调用的时候创建这些实例。
　　如果isPost90s被频繁的调用，这种方法会显著的提高性能，除了提高性能之外，代码的含义也更加清晰了，把startDay和endDay从局部变量改为final静态域，这些日期显然是被作为常量对待，从而使得代码容易理解。
　　然而，如果Birth类被初始化了，它的isPost90s方法永远不被调用，那就没有必要初始化START_DAY域和END_DAY域了。我们可以通过延迟初始化，即把这些域的初始化延迟到isPost90s方法第一次被调用的时候进行。则有可能消除这些不必要的工作，但是这样也会使方法更加复杂，所以不建议这么做。

自动装箱

　　众所周知，自动装箱允许程序员将基本类型和装箱基本类型混用，按需要自动装箱和拆箱，自动装箱使得基本类型和装箱基本类型的差别变得模糊起来，但是并没有完全消除区别，在性能上有明显的差别，例如下面的例子：

Long sum = 0L;
for (long i = 0; i < Integer.MAX_VALUE; ++i) sum += i;

　　这段程序算出的答案是正确的，但是比实际情况要慢一些，因为sum是Long类型，而不是基本类型long,意味着程序构造了大约2的31次方个多余的Long实例（大约每次往Long sum中增加long时构造一个实例），将Long改成long后，在我的机子上，运行时间从24248ms减少到了2855ms，结论很明显。所以要优先使用基本类型而不是装箱基本类型，要当心无意识的自动装箱。

误解

　　不要错误的认为以上内容暗示着创建对象的代价非常昂贵，我们应该尽量避免创建对象。相反，由于小对象的构造器只做很少量的显示工作，所以小对象的创建和回收动作是非常廉价的，特别是在现代的JVM实现更是如此。通过创建附加的对象，提升程序的清晰性、简洁性和功能性，通常是利大于弊的。
