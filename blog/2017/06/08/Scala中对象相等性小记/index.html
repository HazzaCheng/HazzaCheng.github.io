引言

　　Scala的相等的定义与Java的不同。

区别

　　Java有两种相等型比较：

  • ==操作符，对值类型而言这是自然的相等性，而对引用类型而言则是对象一致性。
  • equals方法，是用户定义的引用类型的规约相等性。Java编程中初学者经常在改用equals的地方用==来比较对象，例如String字符串的比较。

　　实际上Java这种对与==操作符的处理显得有些不自然，而在Scala中==相等性判断被用来表示每个类型的“自然的”相等性。对值类型而言，==是对值的比较，与Java一样，而对于引用类型，==在Scala中相当于equals。你可以重写新类型的equals方法从而重新定义==的行为，我们没法重写==方法，因为它在Any中定义为final方法。同时Scala也提供了eq方法来实现引用类型的引用相同的比较。

实现equals方法的陷阱

　　为了达到对象相等性的判断，经常需要重写equals方法，重写equals经常会遇见四个陷阱。
　　下面以一个简单的Point类作为例子：

class Point(val x: Int, val y: Int) {}

　　定义几个Point对象：

val p1, p2 = new ValPoint(1, 2)
val q = new ValPoint(2, 3)
val p2a: Any = p2

以错误的签名定义equals方法

　　下面以一个简单的ValPoint类作为例子：

class ValPoint(val x: Int, val y: Int) {}

　　定义几个Point对象：

val p1, p2 = new ValPoint(1, 2)
val q = new ValPoint(2, 3)

　　为其添加一个简单的equals方法：

 def equals1(other: ValPoint): Boolean =
    this.x == other.x && this.y == other.y

　　这个方法一开始运行都还是不错的：

println(p1 equals p2) => true
println(p1 equals q) => false

　　然而，当我们把它放到一个HashSet中就会出现问题：

val coll1 = HashSet(p1)
println(coll1 contains p2) => false

　　这是为什么？为此我们遮掉一个参与比较点的精确类型：

val p2a: Any = p2
println(p2a equals p1) => false

　　出现这种问题的原因是因为因为ValPoint类的equals方法以ValPoint而不是Any作为参数，它并没有重写Any类中的equals方法。目前，Scala和Java中的重载都是根据参数的静态类型，而不是运行期的类型来解析，因此只要是ValPoint类型，则调用ValPoint的equals的方法,一旦静态的参数是Any类型的,则调用的就是Any的equals方法,所以HashSet的contains方法返回false，由于这个方法操作的是泛型的集合，它调用的是Object类的equals方法而不是Point中的重载的变种。

　　我们可以实现一种更好的equals方法，但仍不完美：

  override def equals(other: scala.Any): Boolean = other match {
    case that: ValPoint => (that canEqual this) && (this.x == that.x) && (this.y == that.y)
    case _ => false
  }

　　这可能是更好的一些定义，但并不完美,HashSet的contains依然返回false，这便是我们下一个陷阱所要讲的，因为Point类重新定义了equals,但没有重新定义hashcode。

修改equals但没有同时修改hashcode方法

　　如上所示，用到的集合类是HashSet。这意味着这个集合类的元素会依据它们的哈希码被放进“哈希桶”中，因为我们只重写了equals方法，并没有重写hashcode方法，因此hashcode方法仍然是它在AnyRef中的样子：已分配对象地址的某种转换。p1和p2的哈希码值几乎是肯定不同的，尽管这两个点的字段值相同。
　　如果两个对象根据equals方法是想等的，那么对它们每一个调用hashcode方法都必须产出相同的整型结果。
　　如下所示实现hashcode方法：

class ValPoint(val x: Int, val y: Int){
  override def equals(other: scala.Any): Boolean = other match {
    case that: ValPoint => (that canEqual this) && (this.x == that.x) && (this.y == that.y)
    case _ => false
  }

  override def hashCode(): Int = 41 * (41 + x) + y
}

用可变字段定义equals

　　接下来我们把字段声明成var类型：

class VarPoint(var x: Int, var y: Int){
  override def equals(other: scala.Any): Boolean = other match {
    case that: ValPoint => (that canEqual this) && (this.x == that.x) && (this.y == that.y)
    case _ => false
  }

  override def hashCode(): Int = 41 * (41 + x) + y
}

　　我们定义一个VarPoint对象，并把它放到集合类中：

val p = new Point(1, 2)
val coll = new HashSet(p)
println(coll contains p) => true

　　但是如果你改变对象p的一个字段，集合中竟然就没有这个对象了：

p.x += 1
println(coll contains p) => false
println(coll.elements contains p) => true

　　这就是个很奇怪的现象了，这是个不包含p的集合，但p却在这个集合的元素中。这是因为当x字段被修改后，点对象p相当于被放在了col集合中错误的“哈希桶”中，换句话来说原来那个哈希桶不再对应到这个点对象新的哈希值，某种意义上，p这个点对象离开了coll集合的“视野”，虽然它仍然是集合元素中的一员。
　　由例子可以看出当对象的一个值改变后，集合是个不包含p的集合，但p却在集合的元素中，如果equals和hashcode依赖于可变状态,对于潜在的用户会带来问题，如果需要的比较牵扯到对象当前的状态，你通常应该取别的名字，而不是equals，并且讲相等性判断的方法命名为equalsContent或别的不同于equals的名字，如此以来，Point就继承了默认的equals和hashCode实现，而p就能在它的x字段被修改后继续在coll中被定位到。

未能按同等关系定义equals方法

　　根据scala.Any中的equals方法的契约约定，equals方法必须对非null对象实现等同关系。

equals方法中的等同关系

  • 自反射的，对任何非空值x,x.equals(x)应返回true。
  • 对称的，对任何非空值x和y，若x.equals(y)返回true则y.equals(x)返回true。
  • 可传递的，对任何非空值x、y和z,如果x.equals(y)返回true，且y.equals(z)返回true，则x.equals(z)返回true。
  • 一致的，对任何非空值x、y,多次调用x.equals（y）都应返回同一个结果。
  • 对任何非空值x,x.equals(null)应返回false

继承关系中若干级别上的相等性

　　我们可以通过给equals方法的类里添加一个canEqual方法来实现继承关系的相等性判断，这里举一个带颜色的点的例子说明一下：

object Color extends Enumeration {
  val Red, Orange, Yellow, Green, Blue, Indigo, Violet = Value
}

class ColoredPoint(x: Int, y: Int, val color: Color.Value) extends ValPoint(x, y) {
  override def equals(other: Any): Boolean = other match {
    case that: ColoredPoint => (that canEqual this) && (this.color == that.color) && super.equals(that)
    case _ => false
  }

  override def canEqual(other: Any): Boolean = other.isInstanceOf[ColoredPoint]
}

带参数类型的相等性

　　这里举一个二叉树的例子：

trait Tree[+T] {
  def elem: T
  def left: Tree[T]
  def right: Tree[T]
}

object EmptyTree extends Tree[Nothing] {
  def elem =
    throw new NoSuchElementException("EmptyTree.elem")
  def left =
    throw new NoSuchElementException("EmptyTree.left")
  def right =
    throw new NoSuchElementException("EmptyTree.right")
}

class Branch[+T] (val elem: T, val left: Tree[T], val right: Tree[T]) extends Tree[T]{

  override def equals(other: Any): Boolean = other match {
    case that: Branch[_] => (this canEqual that) &&
                             this.elem == that.elem &&
                             this.left == that.left &&
                             this.right == that.right
    case _ => false
  }


  override def hashCode(): Int =
    41 * (41 * (41 + elem.hashCode) + left.hashCode) + right.hashCode

  def canEqual(other: Any) = other.isInstanceOf[Branch[_]]
}
