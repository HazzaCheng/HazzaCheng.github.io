赫夫曼编码

　　赫夫曼编码可以很有效地压缩数据，通常可以节省20%-90％的空间，我们将待压缩数据看做字符序列。根据每个字符的出现频率，赫夫曼贪心算法构造出字符的最优二进制表示。
　　假定我们希望压缩一个10万个字符的数据文件，下图给出类出现的字符及出现频率。

\[ \begin{array}{c|lcr} & a & b & c & d & e & f \\ \hline 频率(千次) & 45 & 13 & 12 & 16 & 9 & 5 \\ 定长编码 & 000 & 001 & 010 & 011 & 100 & 101 \\ 变长编码 & 0 & 101 & 100 & 111 & 1101 & 1100 \\ \end{array} \]

　　其实也就出现了6个字符。　　

定长编码(Fixed-length Code)

　　如果使用定长编码，需要用3位来表示每个字符，这种方法需要300000个二进制位来编码文件。

变长编码(Variable-length Code)

　　变长编码可以提高压缩率，它的思想是赋予高频字符短码字，赋予低频字符长码字。上面的那个例子，用变长编码的只需要224000位二进制位来进行编码，差不多减少25%的空间开销。

前缀码

　　我们这里所说的前缀码(prefix code)，即没有任何码字是其他码字的前缀。经过有关专家的证明，与任何字符编码相比，前缀码可以保证到最优数据压缩率。
　　二进制字符码怎么进行编码呢？只要将每个字符的码字链接起来即可，例如\(abc\)的编码就是\(0101100\)。
　　前缀码的作用就是简化解码的过程，由于没有码字是其他码字的前缀，编码文件的开始码字是没有歧义的，每一个二进制串都可以被唯一的解析出来。
　　解码过程需要前缀码的一种方便的表现形式，以便我们可以容易的截取开始码字，一种二叉树即可满足这种需求，其叶结点为给定的字符，字符的二进制码字用从根结点到该字符叶结点的简单路径表示，其中\(0\)表示转向左孩子，\(1\)表示转向右孩子。下面两个图给出了定长编码和编长编码示例的二叉数：

　　注意编码树并不是二叉搜索树，更不是霍夫曼树，以为叶结点并未有序排列，而内部结点也并不包含字符关键字。
　　文件的最优编码方案总是对应一棵满二叉数，即每个非叶结点都有两个孩子结点。前面给出的定长编码方案不是最优的，是因为它的二叉数不是满二叉数，而变长编码的那棵二叉数是满二叉数。
　　赫夫曼设计了一个贪心算法来构造最优前缀码，也就是赫夫曼编码(Huffman code)。

贪心算法构造最优前缀码

　　因此，若\(C\)为字母表且所有字符的出现频率均为正数，则最优前缀码对应的树恰好有\(|C|\)个叶结点，且恰好有\(|C|-1\)个内部结点。
　　给定一棵对应前缀码的树\(T\)，我们可以容易地计算出编码一个文件需要多少个二进制位。对于字母表\(C\)中的每个字符\(c\)，令属性\(c.freq\)表示\(c\)在文件中出现的频率，令\(d_T(c)\)表示\(c\)的叶结点在树中的深度，同时\(d_T(c)\)也是字符\(c\)的码字的长度，我们记\(B(T)\)定义为\(T\)的代价，它表示编码文件需要多少个二进制位，则

\[ B(T)=\sum_{c \in C}c.freq \cdot d_T(c) \]

　　我们先设计算法，在验证算法，它的正确性证明也依赖于贪心选择和最优子结构，这样做可以帮助我们明确算法是如何做出贪心选择的。
　　我们假定\(C\)含有\(n\)个字符，算法需要自底向上地构造出对应最优编码的二叉树，它从\(|C|\)个叶结点开始，执行\(|C|-1\)个合并操作创建出最终的二叉树。算法使用一个以属性\(freq\)为关键字最小优先队列\(Q\)，以识别两个最低频率的对象将其和并。当合并两个对象时，得到的新对象的频率设置为原来两个对象的频率之和。

class BinaryTreeNode {
    BinaryTreeNode left;
    BinaryTreeNode right;
    int freq;
    FrequenceChar symbol;

    BinaryTreeNode() {
        this.left = null;
        this.right = null;
        this.freq = 0;
        this.symbol = null;
    }

    BinaryTreeNode(BinaryTreeNode node) {
        this.left = node.left;
        this.right = node.right;
        this.freq = node.freq;
        this.symbol = node.symbol;
    }

    BinaryTreeNode(int frequency) {
        this.left = null;
        this.right = null;
        this.freq = frequency;
        this.symbol = null;
    }

    BinaryTreeNode(int frequency, FrequenceChar symbol) {
        this.left = null;
        this.right = null;
        this.freq = frequency;
        this.symbol = symbol;
    }

    @Override
    public String toString() {
        return "(" + freq + ", " + symbol + ")";
    }
}

/**
 * Created with IntelliJ IDEA.
 * Description: A class for a character with its frequency.
 * Author: HazzaCheng
 * Contact: hazzacheng@gmail.com
 * Date: 2017-08-12
 * Time: 9:54 PM

class FrequenceChar {
    char c;
    int frequency;

    FrequenceChar(char c, int frequency) {
        this.c = c;
        this.frequency = frequency;
    }

    @Override
    public String toString() {
        return "(" + c + ", " + frequency + ")";
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;

        FrequenceChar that = (FrequenceChar) o;

        if (c != that.c) return false;
        return frequency == that.frequency;
    }

    @Override
    public int hashCode() {
        int result = (int) c;
        result = 31 * result + frequency;
        return result;
    }
}
  • 贪心算法，生成保存赫夫曼编码的二叉树，makeVariablelengthCode可用dfs遍历树从而生成字符和变长编码对应的map。
    /**
     * Make huffman code and save it in a binary tree.
     *
     * @param chars the list of characters
     * @return a binary tree of Huffman Code
     */
    BinaryTree makeHuffmanCodeTree(List<FrequenceChar> chars) {
        int n = chars.size();
        Comparator<BinaryTreeNode> comparator = Comparator.comparingInt(o -> o.freq);
        PriorityQueue<BinaryTreeNode> q = new PriorityQueue<>(n, comparator);
        // initialize the priority queue
        for (FrequenceChar c: chars) q.add(new BinaryTreeNode(c.frequency, c));
        for (int i = 1; i <= n-1; i++) {
            BinaryTreeNode z = new BinaryTreeNode();
            BinaryTreeNode x = q.poll();
            BinaryTreeNode y = q.poll();
            z.left = x;
            z.right = y;
            z.freq = x.freq + y.freq;
            q.add(z);
        }
        BinaryTree tree = new BinaryTree(q.peek());
        return tree;
    }
  • 生成保存赫夫曼编码的二叉树，`并用dfs遍历树从而生成字符和变长编码对应的map。
    /**
     * Make huffman code and save it in a map,
     * whose key is the character and the value is the variable-length code;
     *
     * @param chars the list of characters
     * @return a map whose key is the character and the value is the variable-length code
     */
    Map<Character, String> makeVariablelengthCode(List<FrequenceChar> chars) {
        BinaryTree tree = makeHuffmanCodeTree(chars);
        Map<Character, String> map = new HashMap<>();
        dfs(tree.root, map, new StringBuilder());
        return map;
    }

    /**
     * Use dfs to traverse a binary tree.
     *
     * @param node the binary tree node
     * @param map a map whose key is the character and the value is the variable-length code
     * @param path the variable-length code
     */
    void dfs(BinaryTreeNode node, Map<Character, String> map, StringBuilder path) {
        if (node.left == null && node.right == null) {
            map.put(node.symbol.c, path.toString());
            return;
        }
        if (node.left != null) {
            path.append('0');
            dfs(node.left, map, path);
            path.deleteCharAt(path.length() - 1);
        }
        if (node.right != null) {
            path.append('1');
            dfs(node.right, map, path);
            path.deleteCharAt(path.length() - 1);
        }
    }

　　我们来分析一下时间效率，我们这里的\(Q\)直接用了Java里的PriorityQueue，Java的优先队列每次取最小元素，C++的优先队列每次取最大元素，它是使用最小二叉堆实现的，将\(Q\)初始化花费我们\(O(n)\)的时间，后面\(for\)循环又执行了\(n-1\)次，且每个堆操作需要\(O(lgn)\)的时间，所以循环花费\((nlgn)\)。因此总的时间效率为\(O(nlgn)\)。如果将最小二叉堆换成van Emde Bos树，我们可以将时间减少为\(O(nlglgn)\)。

赫夫曼算法的正确性

　　为了证明上面的贪心算法是正确的，我们需要证明确定最优前缀码的问题具有贪心选择和最优子结构性质。下面的引理证明问题具有贪心选择性质。

引理1
令\(C\)是一个字母表，其中每个字符\(c \in C\)都有一个一个频率\(c.freq\)。令\(x\)和\(y\)是\(C\)中频率最低的两个字符。那么存在\(C\)的一个最优前缀码，\(x\)和\(y\)的码字长度相同，而且只有最后一个二进制位不同。

　　我们呢另\(T\)表示任意一个最优前缀码对应的编码树，对其进行修改，得到另一个最优前缀码的编码树，使得在新树中，\(x\)和\(y\)深度最大的叶结点，且它们为兄弟结点。如果可以构造这么一棵树，那么\(x\)和\(y\)的码字将有相同的长度，且只有最后一位不同。
　　令\(a\)和\(b\)是\(T\)中深度最大的兄弟叶结点，为了不失一般性，我们假设\(a.freq \le b.freq\)且\(x.freq \le y.freq\)。由于\(x.freq\)和\(y.freq\)是叶结点中两个最低的频率，而于\(a.freq\)和\(b.freq\)是两个任意频率，因此，我们有\(x.freq \le a.freq\)且\(a.freq \le b.freq\)。
　　有可能\(x.freq = a.freq\)且\(a.freq = b.freq\)或成立，但是如果\(x.freq = a.freq = y.freq = b.freq\)，在这种情况下引理1是肯定成立的，接下来我们证明\(x.freq \neq b.freq\)，即\(x \neq b\)的情况。
　　如上图所示，我们在\(T\)中交换\(a\)和\(x\)，生成一棵新树\(T'\)，并在\(T'\)中交换\(b\)和\(y\)生成一棵新树\(T''\)，那么在\(T''\)中\(x\)和\(y\)是深度最深的两个兄弟叶结点(注意，如果\(x=b\)但\(y \neq a\)，则\(x\)和\(y\)不是深度最深的两个兄弟叶结点)，由公式\(B(T)=\sum_{c \in C}c.freq \cdot d_T(c)\)，\(B(T)\)和\(B(T')\)的代价差为：

\[ \begin{align} B(T) - B(T') & = x.freq \cdot d_T(x) + a.freq \cdot d_T(a) - x.freq \cdot d_{T'}(x) - a.freq \cdot d_{T'}(a) \\ & = x.freq \cdot d_T(x) + a.freq \cdot d_T(a) - x.freq \cdot d_T(a) - a.freq \cdot d_T(x) \\ & = (a.freq - x.freq)(d_T(a) - d_T(x)) \\ & \ge 0 \end{align} \]

　　由上面的证明我们有\(B(T) \ge B(T')\)，同理我们可证\(B(T') \ge B(T'')\)，而又因为\(T\)是最优的，所以\(B(T) \le B(T'')\)，所以\(B(T) = B(T'')\)，因此\(T''\)也是最优树，且\(x\)和\(y\)其中深度最大的兄弟叶结点，所以引理1得证。
　　引理1说明，不失一般性，通过和并来构造最优树的过程，可以从合并出现频率最低的两个字符这样一个贪心选择开始，为什么这是一个贪心选择呢？我们将可以将一次合并操作的代价看做被和并的两项的频率之和，编码树构造的总代价等于所有和并操作的代价之和，在每个步骤可选的和并操作中，Huffman选择是代价最小的那个。
　　下面引理2来证明下构造最优前缀码的问题具有最优子结构的性质。

引理2
令\(C\)为一个给定的字母表，其中每个字符\(c \in C\)都定义了一个频率\(c.freq\)。令\(x\)和\(y\)是\(C\)中频率最低的两个字符。令\(C'\)为\(C\)中去掉字符\(x\)和\(y\)，加入一个新字符\(z\)之后得到的字母表，即\(C' = \{C -\{x,y\}\} \cup \{z\}\)。类似\(C\)，\(C'\)也定义了\(freq\)，不同之处在与\(z.freq = x.freq + y.freq\)。另\(T'\)为字母表\(C'\)的任意一个最优前缀码对应的编码树。于是我们可以\(T'\)中的叶结点\(z\)替换为一个以\(x\)和\(y\)为孩子的内部结点，得到树\(T\)，而\(T\)表示字母表\(C\)的一个最优前缀码。

　　首先我们想办法用\(B(T')\)来表示\(B(T)\)，对于每个字符\(c \in C -\{x,y\}\)，我们有\(d_T(c) = d_{T'}(c)\)，因此\(c.freq \cdot d_T(c) = c.freq \cdot d_{T'}(c)\)。由于\(d_T(x) = d_T(y) = d_{T'}(z) + 1\)，我们有：

\[ \begin{align} x.freq \cdot d_T(x) + y.freq \cdot d_T(y) & = (x.freq + y.freq)(d_{T'}(z) + 1) \\ & = z.freq \cdot d_{T'}(z) + (x.freq + y.freq) \end{align} \]

　　于是可以得到结论：

\[ B(T') = B(T) - (x.freq + y.freq) \]

　　现在我们用反证法来证明引理，假定\(T\)对应的前缀码不是并不是\(C\)的最优前缀码。存在最优编码树\(T''\)满足\(B(T'') \lt B(T)\)。不失一般性，\(T''\)包含兄弟结点\(x\)和\(y\)。另\(T'''\)为将\(T''\)中\(x\)和\(y\)及它们父结点替换为叶结点\(z\)得到的树，其中\(z.freq = x.freq + y.freq\)。于是：

\[ B(T''') = B(T'') - (x.freq + y.freq) \lt B(T) - (x.freq + y.freq) = B(T') \]

　　与\(T'\)对于\(C'\)的一个最优前缀码的假设矛盾，因此\(T\)必然表示字母表\(C\)的一个最优前缀码。
　　所以引理2得证，由引理1和引理2即可证明Huffman过程会生成一个最优前缀码，所以我们的贪心算法是正确的。
