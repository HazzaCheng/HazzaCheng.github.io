引言

　　Scala支持两种特殊的类型约束操作符，它们其实不是真正的类型约束，而是隐式查找，这两种操作符就是上下文边界(context bounds)和视图边界(view bounds)。这些操作符允许你定义一个隐式参数列表来作为泛型类型的类型约束。在隐式转换定义必须可被查找但不需要直接访问的情况下，这种语法可以让我们少打点字。
　　视图边界和上下文边界也就是**隐式类型约束(implicit type bounds)**的两种类型。
　　在这篇文章里我们还会介绍特定方法，它也是隐式类型约束的一个方法。

视图边界

　　视图边界要求一个可用的隐式视图来转换一个类型为另个类型。

def foo[A <% B](x: A) = x

　　foo方法定义了一个约束A<%B，意思是参数x的类型为A，并且在调用的地方必须存在隐式转换A=>B。可以用下面的写法表达相同的意思:

def foo[A](x: A)(implicit $sev0: A => B) = x

　　尽管这种方式需要打更多的字，但是它给隐式转换函数打了个用户自定义的标签。

上下文边界

　　上下文边界与视图边界类似，声明必须有一个给定类型的隐式值存在，上下文绑定形如:

def foo[A: B](x: A) = x

　　foo方法定义了约束A:B。这个约束的意思是参数x的类型为A，并且调用foo方法时必须有可用的隐式值B[A]存在。可以用下面的写法表达相同的意思:

def foo[A](x: A)(implicit $ev0: B[A]) = x

　　与视图边界一样，这种方式可以给隐式转换函数打了个用户自定义的标签。上下文边界在帮助提供伴生对象里的隐式值时极为有用，其自然导向了类型类。

如何使用隐式类型约束

　　Scala的隐式视图经常用于扩展已存在的类型，扩展的意思是说指给原始类型上添加额外行为。隐式类型约束用于扩展一个已有类型，同时在类型系统里保留原类型。
　　我们举个例子，在REPL里写个方法返回列表的第一个元素和列表本身。

scala> def getFirst[T](x: Traversable[T]) = (x.head, x)
getFirst: [T](x: Traversable[T])(T, Traversable[T])

scala> getFirst(Array("a","b"))
res0: (String, Traversable[String]) = (a,WrappedArray(a, b))

　　这个方法为集合的元素定义了类型参数T，其接受Traversable[T]类型的参数，返回集合的第一个元素和集合本身。当我们用Array调用此方法时，结果类型看上去是Traversable[T]类型，但是runtime类型其实是WrappedArray，这个方法丢失了数组的初始类型信息，因为Scala为了适应JVM在编译期是进行类型擦除的。
　　上下文边界和视图边界允许使用简单的方式确保复杂的类型约束，当方法不需要通过名字访问捕获的类型，但又需要在作用域里存在可用的隐式转换的时候，就是运用上下文边界和视图边界的最好的场景。
　　例如下面这个例子 。

def sendMsgToReceivers[A: Serializable](receivers: Seq[Receiver[A]], a: A) = {
    receivers.foreach(_.send(a))
}

　　sendMsgToReceivers方法需要参数是能被序列化的，但是方法本身又不做序列化这件事情。它带有可序列化隐式上下文的类型，也就是说编译器能在隐式作用域里找到类型Serializable[A]。
　　上下文边界和视图边界用于明确隐式参数的目的，隐式参数能用于从类型里捕捉关系。

用隐式转换来捕捉类型

　　自从Scala2.8以来，Scala正式加入了把类型信息编码进隐式参数的能力，有两种方式，第一种就是我们上面所说到的隐式类型约束，第二种就是Manifest，我们依次来看一下。

  • Manifest：是由编译器在必要的时候生成的类型信息，用来记录当时编译器对该类型所知的全部信息。刚开始加入Manifest是专门用来处理数组，后来被通用化，使之能用于其他需要在运行时访问类型信息的场景。类型的运行时副本也就是Manifest。
  • 隐式类型约束：是类型间的超类和等价关系的直接编码，这对于在一个方法内对泛型类型做进一步限制时很有用，这种约束是静态的，在编译时发生的。

Manifest的由来

　　Scala最初引入Manifest是为了处理数组，在Scala里数组是带有类型参数的类。一个整数的数组，其类型为Array[Int]。 　　但是在JVM里，每个基础类型(primitive tyoe)都有不同的数组类型，另外还有个数组类型是给对象的，例如Int[],Double[]什么的。Java语言是区分这些类别的，并且要求程序也区分这些类型。
　　然而，在Scala里，是允许在编码的时候使用泛型的Array[T]类型的，但是由于底层的实现必须知道初始的数组是int[]，double[]还是其他的数组类型，因此Scala需要一种方法来把这个信息附加给泛型类型，以便泛型数组的实现能够知道如何处理数组，这就是Manifest的由来。

Manifest的使用

　　Manifest可以用来附加在泛型类型参数上，传递更特定的类型信息。在Scala里所有设计数组的方法都需要为数组的类型参数附加相应的Manifest，因为尽管Scala把数组作为泛型类，但它们是被编码为JVM里的不同类型的，比如int[]，double[]，Scala选择把运行时行为隐藏在Array[T]类和相关方法后面，而不是编码成不同类型。因为要对Array[Int]和Array[Double]编码成不同的字节码，所以Scala用Manifest来携带数组的类型信息。
　　Manifest有三种类型的Manifest：

  • Manifest：保存与类型T的反射的类实例以及T的所有类型参数的Manifest值。类实例是该类的java.lang.class对象的引用，这样就可以调用该类上定义的方法。但是保存和计算Manifest类的开销可能很大，因为它需要为每个类型和类型参数访问java.lang.class对象。
  • OptManifest：一个类型需要一个OptManifest使这种需要是可选，如果有的话，那么该OptManifest实例将是Manifest的子类，如果没有，则该实例为NoMainfest类。OptManifest设计用于不是一定要有manifest才能完成功能，但是如果有manifest能提高运行效率的场景。
  • ClassManifest：这个类和Manifest类似，但它只保存给定类型的删除了的类，所谓给定类型的删除了的类就是与类型相关联但不包含类型参数。比如说类型List[Int]的删除了的类型是List类。所以ClassManifest被设计成用于不需要捕捉类型参数的场景。

　　在Scala里，Manifest用于创建抽象方法，其实现根据其处理的类型有所偏差，最终的结果输出是一致的。我们看一个泛型数组的例子，因为Scala必须根据运行时数组类型生成不同的字节码指令，所以编译器需要Array元素带有ClassManifest。

scala> def first[T](x: Array[T]) = Array(x(0))
<console>:11: error: No ClassTag available for T
       def first[T](x: Array[T]) = Array(x(0))

　　因为我们没有捕获manifest，编译器无法确定结果数组的runtime类型，我们给它加上ClassMainFest标签。

scala> def first[T: ClassManifest](x: Array[T]) = Array(x(0))
<console>:11: warning: type ClassManifest in object Predef is deprecated (since 2.10.0): use `scala.reflect.ClassTag` instead
       def first[T: ClassManifest](x: Array[T]) = Array(x(0))
                  ^
first: [T](x: Array[T])(implicit evidence$1: ClassManifest[T])Array[T]

scala> first(Array(1, 2))
res0: Array[Int] = Array(1)

　　可以看到，T类型的参数捕捉到了隐式的ClassMainfest。当用Array[Int]调用时，为类型Int构造了一个ClassManifest用于构造对应的runtime数组类型。

注意，ClassManifest自Scala2.10以来就被废弃了，已被ClassTag取代，我们看看Scala2.12的API文档里是怎么写的。
A ClassTag[T] stores the erased class of a given type T, accessible via the runtimeClass field. This is particularly useful for instantiating Arrays whose element types are unknown at compile time.
ClassTags are a weaker special case of scala.reflect.api.TypeTags#TypeTags, in that they wrap only the runtime class of a given type, whereas a TypeTag contains all static type information. That is, ClassTags are constructed from knowing only the top-level class of a type, without necessarily knowing all of its argument types. This runtime information is enough for runtime Array creation.
For example:
scala> def mkArray[T : ClassTag](elems: T*) = Array[T](elems: _*)
mkArray: [T](elems: T*)(implicit evidence$1: scala.reflect.ClassTag[T])Array[T]
scala> mkArray(42, 13)
res0: Array[Int] = Array(42, 13)
scala> mkArray("Japan","Brazil","Germany")
res1: Array[String] = Array(Japan, Brazil, Germany)

　　我们用新的API试一下。

scala> def first[T: ClassTag](x: Array[T]) = Array[T](x(0))
first: [T](x: Array[T])(implicit evidence$1: scala.reflect.ClassTag[T])Array[T]

scala> first(Array('a', 'b'))
res2: Array[Char] = Array(a)

　　我们看到，完全兼容。
　　要使用Manifest需要在把已知的特定类型传递给泛型方法前先捕捉其manifest，如果一个数组的类型已经丢失，就不能把它传给first方法了。我们举个例子，在被废弃的ClassManifest接口下试试。

scala> def first[T: ClassManifest](x: Array[T]) = Array(x(0))
<console>:13: warning: type ClassManifest in object Predef is deprecated (since 2.10.0): use `scala.reflect.ClassTag` instead
       def first[T: ClassManifest](x: Array[T]) = Array(x(0))
                  ^
first: [T](x: Array[T])(implicit evidence$1: ClassManifest[T])Array[T]

scala> val x: Array[_] = Array(1,2)
x: Array[_] = Array(1, 2)

scala> first(x)
res4: Array[_] = Array(1)

scala> first(x)
<console>:15: error: No ClassManifest available for _$1.
       first(x)
            ^

　　我们看到显然是不行的，因为值x是存在类型的数组，因为无法为数组的类型找到ClassManifest，所以无法调用first方法。我们再试试在新的ClassTag接口下。

scala> def first[T: ClassTag](x: Array[T]) = Array(x(0))
first: [T](x: Array[T])(implicit evidence$1: scala.reflect.ClassTag[T])Array[T]

scala> val x: Array[_] = Array(1,2)
x: Array[_] = Array(1, 2)

scala> first(x)
res4: Array[_] = Array(1)

scala> first(x)
res6: Array[_] = Array(1)

　　很神奇，居然可以。这个我暂时也解释不了，只能说可能ClassTag更强大把，只能看官方以后给出的信息了。
　　Manifest是在编译是捕捉的，编码了＂捕捉时＂所知的类型信息。然后就可以在运行时检查和使用类型类型信息，但是manifest只能捕捉当Manifest被查找时在隐式作用域里可用的类型。
　　Manifest虽然很有用，但是不应该滥用，要谨慎的使用，在编译器已经明确知道类型的情况下，不应该使用Manifest来确保类型约束，而应该使用另一种隐式转换在编译时捕捉类型约束。
　　根据Scala官网所提到的，将会在后续的版本将Manifest也废弃掉，转而用更强大的TypeTag代替，道理都是一样的，我们只需要到时候看看官网API就可以了。

捕捉类型约束

　　类型推断和类型约束共同起作用的结果是有时候在你需要用**具象化类型约束(reified type constraints)**时造成故障。

具象化是什么意思？
　　**把具象化想象为一种编程语言里的概念转化为一个能在运行时检查和使用的类或对象的过程。**一个Function对象就是方法概念(method)的具象化。它是一个实际的对象，你可以在运行时期调用其方法。以此类推，其他概念也可以被＂巨象化＂。
具象化类型约束又是什么意思呢？
　　它们是这样一些对象，其隐式的存在就已经验证了某些类型约束是有效的。比如说，有个类型叫做<:<[A,B]，如果编译器能在隐式作用域里找到这个类型，那么A<:B就一定是true的。换句话来说，<:<[A,B]是上界约束的具象化。

　　有了具象化约束，有时候它能帮助类型推断器自动判断方法调用的类型，类型推断算法的精巧机制之一就是利用隐式转换推迟类型解析。Scala的类型推断器从左到右推断参数列表，这使得前一个参数的类型推断结果能够影响后面的参数的类型推断结果。
　　这种从左到右推断的一个例子就是在集合中使用匿名函数额时候：

scala> def foo[A](col: List[A])(f: A => Boolean) = null
foo: [A](col: List[A])(f: A => Boolean)Null

scala> foo(List("a", "b"))(_.isEmpty)
res0: Null = null

　　foo方法利用柯里化定义了两个参数列表和一个类型参数。第一个参数列表接受一个未知类型A的列表，第二个参数接受一个使用A类型的函数。当不带类型参数调用foo方法时，调用是成功的，因为编译器能够根据第一个参数List(“a”,“b”)推断出类型参数A的类型是String，然后这个类型被应用与第二个参数列表，所以编译器能知道在这里占位符_应该是String类型，但是当我们把两个参数列表和并到一起就不行了。

scala> def foo[A](col: List[A], f: A => Boolean) = null
foo: [A](col: List[A], f: A => Boolean)Null

scala> foo(List("a", "b"), _.isEmpty)
<console>:13: error: missing parameter type for expanded function ((x$1: <error>) => x$1.isEmpty)
       foo(List("a", "b"), _.isEmpty)

　　在这种情况下，编译器因为无法知道类型，所以匿名函数_.isEmpty无法编译，因为此时编译器还没有推断出A的类型是String，因此无法把类型提供给匿名函数。
　　有时，对类型参数也可能发生同样的情况，因为编译器无法判断出一个参数列表里的所有参数，所以编译器会用隐式参数列表来协助类型推断器。
　　我们来创建一个peek方法，此方法返回一个元组(tuple)，包含一个集合的第一个元素和整个集合。这个方法能够处理Scala库里的任何集合类型，而且应该保持传给方法的参数的相应类型。

scala> def peek[A, C <: Traversable[A]](col: C) = (col.head, col)
peek: [A, C <: Traversable[A]](col: C)(A, C)

　　这个方法中，类型参数C用来捕捉集合的特定类型，类型参数A用来捕捉集合里元素的特定类型。方法返回A和C，从而保留了特定类型。但是类型推断器并不能在没有标注的情况下识别出正确的类型。

scala> peek(List(1,2,3))
<console>:13: error: inferred type arguments [Nothing,List[Int]] do not conform to method peek's type parameter bounds [A,C <: Traversable[A]]
       peek(List(1,2,3))
       ^
<console>:13: error: type mismatch;
 found   : List[Int]
 required: C
       peek(List(1,2,3))

　　如我们前面所说的一样，类型推断器无法只通过一个参数同时找打A和C的类型。我们重写一下peek方法：

scala> def peek[C, A](col: C)(implicit ev: C <:< Traversable[A]) = (col.head, col)
peek: [C, A](col: C)(implicit ev: C <:< Traversable[A])(A, C)

scala> peek(List(1,2,3))
res1: (Int, List[Int]) = (1,List(1, 2, 3))

　　新的peek方法不带类型参数也能成功的返回了，那么它是什么意思呢？与旧的peek方法不同，新的peek方法的类型参数C没有应用类型约束，而是在第二个参数列表里接受一个隐式值，这个类型为C <:< Traversable[A]。这个类型利用了Scala的操作符标识，正如以操作符命名的方法能够用作操作符标识，类型和类型参数也一样。类型C <:< Traversable[A]是类型<:< [C,Traversable[A]的快捷方式。
　　<:<在scala.predef里为任意两个具有A<:B关系的类型A和类型B提供了默认的隐式值，我们看一下源代码：

  /**
   * An instance of `A <:< B` witnesses that `A` is a subtype of `B`.
   * Requiring an implicit argument of the type `A <:< B` encodes
   * the generalized constraint `A <: B`.
   *
   * @note we need a new type constructor `<:<` and evidence `conforms`,
   * as reusing `Function1` and `identity` leads to ambiguities in
   * case of type errors (`any2stringadd` is inferred)
   *
   * To constrain any abstract type T that's in scope in a method's
   * argument list (not just the method's own type parameters) simply
   * add an implicit argument of type `T <:< U`, where `U` is the required
   * upper bound; or for lower-bounds, use: `L <:< T`, where `L` is the
   * required lower bound.
   *
   * In part contributed by Jason Zaugg.
   */
  @implicitNotFound(msg = "Cannot prove that ${From} <:< ${To}.")
  sealed abstract class <:<[-From, +To] extends (From => To) with Serializable
  private[this] final val singleton_<:< = new <:<[Any,Any] { def apply(x: Any): Any = x }
  // The dollar prefix is to dodge accidental shadowing of this method
  // by a user-defined method of the same name (SI-7788).
  // The collections rely on this method.
  implicit def $conforms[A]: A <:< A = singleton_<:<.asInstanceOf[A <:< A]
  
  @deprecated("Use `implicitly[T <:< U]` or `identity` instead.", "2.11.0")
  def conforms[A]: A <:< A = $conforms[A]

　　第一行声明了<:<类，它继承自Function1和Serializable，意味着<:<可以在任何需要java序列化的场景下使用。$conforms方法接受类型参数A，返回从类型A到A转换过来新的<:<类型实例。<:<利用了型变标注这个小技巧。因为From是逆变的，所以如果B<:A，那么<:<[A,A]顺应于(confroms to)于类型<:<[B,A]，编译器会用隐式值<:<[A,A]来满足对类型<:<[B,A]的查找。
　　捕获类型关系也能用来在以后的某时限制已经存在的类型参数。

特定方法(Specialized method)

　　我们先来介绍一下什叫特定方法，有时候有的参数化类型会对其中的某几个方法做一些限定，仅当参数支持某种特性或者集成自某个特定类时该方法才有效，这种方法就叫做特定方法。
　　特定方法是为泛型类型的特定子集设计的，它用隐式解析系统限定泛型类型的子集，我们拿Scala集合库里只能用于数字类型的特定方法TraversableOnce.sum举个例子：

def sum[B >: A](implicit num: Numeric[B]): B = foldLeft(num.zero)(num.plus)

　　sum方法接受类型参数B，其类型为集合元素的任何超类。参数num定义为对Numeric类型类(typeclass)的隐式查找。Numeric是个类型类。为给定类型提供了zero和plus等方法。这个sum方法可以对任何支持Numeric类型类的集合调用，也就是我们可以给一般不认为是数字的类型提供我们自己的数字类型，举个例子：

scala> object stringNumeric extends Numeric[String] {
     |   override def plus(x: String, y: String): String = x + y
     |   override def zero: String = ""
     | 
     |   override def minus(x: String, y: String) = ???
     | 
     |   override def times(x: String, y: String) = ???
     | 
     |   override def negate(x: String) = ???
     | 
     |   override def fromInt(x: Int) = ???
     | 
     |   override def toInt(x: String) = ???
     | 
     |   override def toLong(x: String) = ???
     | 
     |   override def toFloat(x: String) = ???
     | 
     |   override def toDouble(x: String) = ???
     | 
     |   override def compare(x: String, y: String) = ???
     | }
defined object stringNumeric

scala> implicit val str2num = stringNumeric
str2num: stringNumeric.type = stringNumeric$@4ef0bc5b

scala> List("a", "b", "c").sum
res1: String = abc

　　我们只覆盖了plus和zero方法，如你所见，只要存在合适的隐式值，String类型可以调用特定方法sum。
　　也可以用<:<和=:=来使方法特定化。<:<什么意思我们前面说过了，我们来看看=:=是什么意思，这是它的源码：

/** An instance of `A =:= B` witnesses that the types `A` and `B` are equal.
   *
   * @see `<:<` for expressing subtyping constraints
   */
  @implicitNotFound(msg = "Cannot prove that ${From} =:= ${To}.")
  sealed abstract class =:=[From, To] extends (From => To) with Serializable
  private[this] final val singleton_=:= = new =:=[Any,Any] { def apply(x: Any): Any = x }
  object =:= {
     implicit def tpEquals[A]: A =:= A = singleton_=:=.asInstanceOf[A =:= A]
  }

　　可以看出它与<:<不同的是，<:<是要求A <: B，而它要求只有A和B的类型相同，才能在在scala.predef里找到为类型A和类型B提供的默认隐式值。
　　我们来举个例子，一个对Set做压缩的方法，要求Set必须是整数：

trait Set[+T] {
    ...
    def compress(implicit ev: T =:= Int) = new CompressedIntSet(this)
}

　　当然Set里并没有这个方法，这只是我们举的一个例子，隐式的ev参数确保了原始集合必须是Set[Int]，这样才能创建CompressedIntSet。
　　特定方法是一种在提供富API的同时确保类型安全的好办法，有助于填补泛型类和特殊使用场景之间的裂缝。在Scala核心库里的集合框架用它来支持数字操作。特定方法和类型类也协作得很好，类型类为类用户提供了最大的灵活性。
