引言

　　以前没有听说过什么叫做存在类型，今天碰巧在学习Scala的时候看见了，就记录下来。
　　**存在类型(Existential Type)**是一种构造部分类型签名是已存在的类型的手段，已存在的意思是说，尽管已经有一些实际类型符合那部分类型签名，但我们并不在意那个具体类型。
　　Scala引入存在类型是作为一种与Java的泛型类型交互的手段。

Java中的存在类型

　　Java泛型编程是JDK1.5版本后引入的，还是比较晚的，Java在引入时考虑到了向下兼容的问题，因此Java集合API在用泛型做了加强的同时还支持没用泛型类型编写的代码。
　　那么Java是如何做到的呢，Java主要是通过结合使用类型擦除和一种受限的存在类型(a subdue from of existential)。
　　我们看一下Java的List接口，老的List接口设计的时候没有泛型，用老的接口写的代码却仍然和有Java泛型的代码兼容，举例来说：


public static void main(String[] args) {
    List foo = new ArrayList();
    foo.add("foo");
    System.out.println(foo.get(0));
}

输出：
foo

运行在open jdk1.8下

　　这里就没有指定List接口的泛型参数，我们也知道get方法返回的是java.lang.Object。但是也不完全是这样，当类型参数没有给出的时候，Java就使用了存在类型，也就是说，对于缺失的类型参数，唯一能够确定的信息就是它一定是java.lang.Object或其子类，这就使以前还没有泛型参数的代码，get方法返回Object，能够直接被新集合库编译。
　　但是，创建没有类型参数的List和创建List<Object>是不一样的。

public class Test {
    public static void main(String[] args) {
        List foo = new ArrayList();
        foo.add("foo");
        List<Object> bar = foo;
    }
}

　　在用javac编译上述代码的虽然不会报错，但是会出现未检查的类型转换。

　　我们主要看第四个错误，可以发现，Java不把List和List<Object>当作相同类型，但是会在两者之间自动转换，因为在Java里，两者之间的差别是很小的。

Scala里的存在类型

　　在Scala里存在类型有点和Java不同，我们在Java类里创建个存在类型，然后在REPL里引入，看看为有什么神奇的效果出现。

public class Test {
    public static List makeList() {
        return new ArrayList();
    }
}

scala> Test
   object Test

scala> Test.makeList()
res0: java.util.List[_] = []

　　我们看到REPL里返回的类型是java.util.List[_]，下划线是什么呢，Scala为创建存在类型提供了便利的语法糖，只需要在类型参数的位置上用下划线就可以了，你也可以把这个下划线看作是类型参数的占位符，编译器不确定类型参数是啥，但是它知道这里应该有个类型参数。
　　我们试试在REPL里给这个list添加参数。

scala> Test.makeList().add("foo")
<console>:12: error: type mismatch;
 found   : String("foo")
 required: ?0 where type ?0
       Test.makeList().add("foo")
                           ^

　　我们看到不可以添加，这就是Scala和Java的偏差，在Scala里我们不能向List[]里加元素，除非编译器能确定元素类型和list里的类型相同，这也代表这我们无法在不采取强制类型转换的情况下向list添加新的元素。而在Java里则是可以编译的，只不过会给出"Unchecked"的警告。
　　需要注意的是，_也可以当作一个类型参数，从而使得存在类型也可以有上界和下界，举个例子。

scala> def foo(x: List[_ >: Int]) = x
foo: (x: List[_ >: Int])List[Any]　// 注意类型是Any

scala> foo(List("Hello World!"))
res3: List[Any] = List(Hello World!)

scala> foo(List(1))
res7: List[Any] = List(1)

　　我们看到，我们定义foo方法里的List参数，类型必须是Int或者Int的超类，我们将一个字符串传进去，因为Int和String有共同超类Any，所以也就返回了一个Any类型的List。还有一个需要注意的，我们在声明完函数后它默认的返回类型就是List[Any]，所以即使我们传入一个Int值，它也会返回List[Any]类型，而普通的用类型参数而不是存在类型构造的方法，就不会这样，可以看下面的例子。

scala> def foo[T >: Int](x: List[T]) = x
foo: [T >: Int](x: List[T])List[T]

scala> foo(List("Hello World!"))
res5: List[Any] = List(Hello World!)

scala> foo(List(1))
res8: List[Int] = List(1)

　　所以大家要注意一下存在类型作为类型参数和普通的类型参数的区别。

正式语法

　　虽然我们可以用_来表示存在类型，但是在Scala声明存在类型的正式语法是使用forsome关键字，存在类型的形式为T forSome(Q)，Q是一组**类型声明(Type Declarations)**的集合。在Scala的语言规范里，很多东西都叫类型声明，包括type和val语句，而在Q块里的声明则是存在类型，编译器知道存在某种符合类型的定义，但是不知道是哪种具体的类型，所以声明在T块里的类型就可以直接地使用这些存在类型了。
　　我们来看看便利语法和正式语法的区别：

scala> val x: List[_] = List()
x: List[_] = List()

scala> val y: List[Y forSome { type Y }] = x
y: List[Y forSome { type Y }] = List()

　　这个warnning大家可以不要在意，我们只是没有意义的返回了自己，y值里的类型Y是存在类型，和x类型里的_一样。
　　我们再来看看有上界的情况：

scala> val x: List[_ <: AnyRef] = List()
x: List[_ <: AnyRef] = List()

scala> val y: List[Y forSome { type Y <: AnyRef }] = x
y: List[Y forSome { type Y <: AnyRef }] = List()

　　forSome块里的所有类型都被视为存在类型，可以用于forSome左边的类型，forSome块可以用于任何方式的类型声明，包括至或其他存在类型。
　　我们观察下面这个例子，有点奇怪，仔细理解一下：

type Exm = x.newType forSome { val x: Foo }

　　上例用名字Exm声明了一个类型，forSome块里有个val定义，意思是值x是存在类型，编译器不关心哪个Observable值，只要有一个存在就可以了，类型声明的左边是路径依赖类型x.newType。注意在这种情况下，这个存在类型是无法用便利语法来创建的，因为_只能在声明里用。
