引言

　　以前零零星星接触过一些docker命令，现在决定稍微系统的学习一下，所以写这篇博客记录一些命令用法，dcoker版本是17.1，API版本是1.33，Go的版本是1.9.2，OS是基于Arch Linux的Manjaro。

运行容器

　　我们可以用docker run创建启动一个容器，并且运行一个命令，我们来试一试：

hazzacheng@hazzacheng-pc ~> sudo docker run -i -t ubuntu /bin/bash
Unable to find image 'ubuntu:latest' locally
latest: Pulling from library/ubuntu
660c48dd555d: Pull complete 
4c7380416e78: Pull complete 
421e436b5f80: Pull complete 
e4ce6c3651b3: Pull complete 
be588e74bd34: Pull complete 
Digest: sha256:7c67a2206d3c04703e5c23518707bdd4916c057562dd51c74b99b2ba26af0f79
Status: Downloaded newer image for ubuntu:latest
root@2dc7eeadc822:/#
  • -i标志保证容器中的STDIN是开启的，有持久的标准输入的功能。
  • -t标志告诉Docker要为创建的容器分配一个伪tty终端。

　　上述命令可以在命令行下创建一个我们能与之进行交互的容器，而不是一个运行后台服务的容器，那两个参数是最基本的参数。
　　你可能怀疑，主机上也许没有ubunbu这个镜像啊，其实ubuntu是一个常备镜像，也可以称为基础镜像，它有docker公司提供，保存在Docker Hub Register上。
　　docker run命令会首先检查本地是否有ubuntu镜像，如果没有的话才会在远程Docker Hub里查找是否有该镜像。
　　我们进入容器之后，容器拥有自己的网络以及IP地址，以及一个用来和宿主机进行通信的桥接网络接口。　　 我们可用通过hostname查看容器的主机名，也就是容器的ID。

root@2dc7eeadc822:/# hostname
2dc7eeadc822

　　你几乎可以在这个ubuntu镜像里做任何正常linux系统都可以做的事情，包括用apt-get安装软件。

退出容器

　　想要退出容器的话，我们只需要输入exit命令，就可以退出到宿主主机上。但是容器仍然是存在的，通过docker ps -a命令可以查看当前系统中容器的列表，如果不加-a参数的话，默认只显示正在运行的容器。也可以加上-l列出最后一个运行的容器，无论是停止的还是运行的。也可以通过--format参数，进一步控制显示哪些信息，以及如何显示这些信息，具体的可以man docker查阅。

hazzacheng@hazzacheng-pc ~> sudo docker ps 
CONTAINER ID        IMAGE               COMMAND             CREATED             STATUS              PORTS               NAMES
2dc7eeadc822        ubuntu              "/bin/bash"         About an hour ago   Up About an hour                        loving_ardinghelli

hazzacheng@hazzacheng-pc ~> sudo docker ps -a
CONTAINER ID        IMAGE               COMMAND             CREATED             STATUS                     PORTS               NAMES
2dc7eeadc822        ubuntu              "/bin/bash"         About an hour ago   Exited (0) 5 seconds ago                       loving_ardinghelli

　　通过输出的信息，我们可以看到：ID，用于创建该容器的镜像，容器最后执行的命令，创建时间，状态，端口，名称。

辨别容器

　　我们可以通过三种方式唯一指代容器：

  • 短UUID，如2dc7eeadc822
  • 长UUID，如
  • 名称，如loving_ardinghell

容器命名

　 　Docker为我们创建的每一个容器自动生成一个随机名称，如果想为容器指定一个名称，可以通过--name参数，需要注意的容器名必须是唯一的，可以通过docker rm删除重名容器。

hazzacheng@hazzacheng-pc ~> sudo docker run --name my_ubuntu_container -i -t ubuntu /bin/bash
root@daa66284c26a:/#

重启容器

　　我们可以通过docker start来启动一个已经停止的容器，docker restart可以重新启动一个容器，这两个命令都要求前提是容器是存在的，而且不能运行一个命令，这也是它们与docker run的区别，我们也可以用docker create来创建一个容器但是不运行它。

附着到容器上

　　Docker容器重新启动的时候，会沿用docker run命令时指定的参数来运行，也就是我们之前使用的/bin/bash命令，我们可以通过docker attach命令重新附着到这个会话上，有时可能需要按下enter。

hazzacheng@hazzacheng-pc ~> sudo docker attach test_container
root@57294224b835:/#

创建守护式进程

　　之前我们创建的进程都是交互式运行的容器，我们也可以创建长期运行的容器，也就是守护式容器，没有交互式会话，适合运行应用程序和服务。
　　我们只需在docker run命令里加一个-d参数，Docker容器就会被放到后台运行，为了证明它是一直运行的，我们还在命令里加了一个while循环，让它一直打印"Hello World!"，直到容器或进程停止运行。

hazzacheng@hazzacheng-pc ~> sudo docker run --name deamon_dave -d ubuntu /bin/sh -c "while true; do echo hello world; sleep 10; done"
ccbfad3e240722ec0ee74a5fee40e8e1e16eb58c97c6b131feb8175fb98b3b8e

　　这里我们没有加上-i -t会它提供交互式会话。

查看容器内部

　　你一定会好奇，我们刚才打印的hello wolrd去哪了，我们可以用docker log命令来获取容器的日志。

hazzacheng@hazzacheng-pc ~> sudo docker logs deamon_dave
hello world
hello world
hello world
...

　　我们也可以加上-f参数来监控Docker的日志，也可以加上--tail [n]来获取日志最后n条信息，也可以用--tail 0 -f参数来跟踪某个容器的最新日志，而不必读取整个日志文件，也可以加上-t参数来加上时间戳。

hazzacheng@hazzacheng-pc ~> sudo docker logs -f deamon_dave
hello world
hello world
hello world
...
hello world

hazzacheng@hazzacheng-pc ~> sudo docker logs --tail 3 deamon_dave
hello world
hello world
hello world

hazzacheng@hazzacheng-pc ~> sudo docker logs --tail 0 -f deamon_dave
hello world

hazzacheng@hazzacheng-pc ~> sudo docker logs -tf deamon_dave
2017-11-30T12:17:59.288119926Z hello world
2017-11-30T12:18:09.317807218Z hello world
...

Docker日志驱动

　　自Docker 1.6开始，也可以控制守护进程和容器所用的日志驱动，通过--log-driver来设置，在启动Docker守护进程或执行docker run命令时使用这个选项，有好几个选项，包括：

  • json_file: 默认的选项，也为我们之前的docker logs命令提供了基础。
  • syslog: 该选项禁用docker logs命令，并且将所有的日志输出都重定向到Syslog。可以在启动Docker守护进程时指定该选项，将所有容器的日志都输出到syslog，或者通过docker run对个别容器进行日志重定向输出。
  • none: 禁止所有容器的日志。
hazzacheng@hazzacheng-pc ~> sudo docker run --log-driver="syslog" --name deamon_dave -d ubuntu /bin/sh -c "while true; do echo hello world; sleep 10; done"
b71c9903116583c80e522af21bd5a6a5b985fd5a85a1841e250d60ea62c579ff

查看容器内的进程

　　我们可用docker top deamon_dave查看容器内部运行的进程。

hazzacheng@hazzacheng-pc ~> sudo docker top deamon_dave
UID                 PID                 PPID                C                   STIME               TTY                 TIME                CMD
root                19190               19167               0                   20:37               ?                   00:00:00            /bin/sh -c while true; do echo hello world; sleep 10; done
root                20730               19190               0                   20:50               ?                   00:00:00            sleep 10

Docker统计信息

　　可以用docker stats命令来显示一个或多个容器的统计信息。

hazzacheng@hazzacheng-pc ~> sudo docker stats deamon_dave
CONTAINER ID        NAME                CPU %               MEM USAGE / LIMIT     MEM %               NET I/O             BLOCK I/O           PIDS
b71c99031165        deamon_dave         0.00%               1.785MiB / 7.688GiB   0.02%               11.2kB / 0B         4.1kB / 0B          2

　　我们看到了它们的CPU，内存，网络I/O及存储I/O的性能和指标。

在容器内部运行进程

　　我们可以通过docker exex命令在容器内部额外启动新进程，可以在容器内部运行的进程有两种类型：

  • 后台任务: 后台任务在容器内部运行且没有交互需求。
  • 交互式任务: 交互式任务则保持在前台运行，对于需要在容器内部打开shell的任务，交互式任务是很实用的。
hazzacheng@hazzacheng-pc ~> sudo docker exec -d deamon_dave touch /etc/new_config_file

　　-d表示需要运行一个后台进程，上面的例子创建了一个空文件。通过docker exec命令可以通过正在运行的容器进行维护，监控及管理任务。
　　我们也可以用-u参数为新启动的进程指定一个用户属主。
　　我们可以通过上面的命令在容器内创建一个新的bash对话，在容器内进行交互对话。

hazzacheng@hazzacheng-pc ~> sudo docker exec -t -i deamon_dave /bin/bash
root@b71c99031165:/#

自动重启容器

　　如果由于某种错误而导致容器停止运行，还可以通过--restart标志，让Docker自动重新启动该容器。--restart标志会检查容器的退出代码，并据此来决定是否重启容器，默认的行为是Docker不会重启容器。

hazzacheng@hazzacheng-pc ~> sudo docker exec -t -i deamon_dave /bin/bash
root@b71c99031165:/#

　　--restart标志被设置为always，无论容器容器的退出代码是什么，Docker都会自动重启该容器。我们还可以设置为on-failure，这样只有当退出代码为非0值的时候，才会自动重启，另外on-failure还接受一个可选的重启次数参数，例如--restart=on-failure:5，这样当容器退出代码为非0时，Docker会尝试自动重启该容器，最多重启5次。

深入容器

　　除了通过docker ps命令获取容器的信息，还可以使用docker inspect来获得更多的容器信息。

hazzacheng@hazzacheng-pc ~> sudo docker inspect deamon_dave
[
    {
        "Id": "06eb4f08f9d6c8ad165039c7b5fb6459304a7288a67b503a1b6739bbd1eb9ac7",
        "Created": "2017-11-30T13:23:27.403081115Z",
        "Path": "/bin/sh",
        "Args": [
            "-c",
            "while true; do echo hello world; sleep 10; done"
        ],
        "State": {
            "Status": "running",
            "Running": true,
            "Paused": false,
            "Restarting": false,
            "OOMKilled": false,
            "Dead": false,
            "Pid": 27613,
            "ExitCode": 0,
            "Error": "",
            "StartedAt": "2017-11-30T13:23:28.41773345Z",
            "FinishedAt": "0001-01-01T00:00:00Z"
        },
        ...

　　这是非常详细的检查，返回了包括名称，命令，网络配置和许多有用的数据，我们们也可以用-f或-format来有选择地获取容器信息。

  • 返回容器的运行状态：
hazzacheng@hazzacheng-pc ~> sudo docker inspect --format='{{ .State.Running }}'  deamon_dave
true
  • 查看容器的IP地址
hazzacheng@hazzacheng-pc ~> sudo docker inspect --format='{{ .NetworkSettings.IPAddress }}'  deamon_dave
172.17.0.2
  • 查看多个容器
hazzacheng@hazzacheng-pc ~> sudo docker inspect --format='{{.Name}} {{.State.Running}}'  deamon_dave test
/deamon_dave true
/test true

　　可以为该参数指定要查询和返回的查看散列中的任意部分。
　　我们还可以通过浏览/var/lib/docker目录来深入了解Docker的工作原理，该目录存放着Docker镜像，容器和容器的配置，所有的容器都保存在/var/lib/docker/containers/目录下。

删除所有容器

　　可以通过一个小trick来删除所有容器。

[hazzacheng@hazzacheng-pc ~]$ sudo docker rm `sudo docker ps -a -q`
ffd276e93558
06eb4f08f9d6

　　同理，这个命令稍微改造一下也可以用来停止所有的容器。
