引言

　　本文将作一些Go语言中涉及并发的一些笔记，这里只记录Go语言和其它语言不太一样的地方。

基础

　　只需在函数调用前加go关键词即可创建并发任务，关键字go并非执行并发操作，而是创建一个并发任务单元，新建任务被放置在系统队列中，等待调度器安排合适系统线程去获取执行权。当前流程不会阻塞，不会等待该任务启动，且运行时也不保证并发任务的执行次序。
　　每个任务单元会保存函数指针，调用参数，还会分配执行所需的栈内存空间。相比系统默认MB级别的线程栈，go自定义的栈仅需2KB，当然也可以按需要时进行扩容，最大能到GB的规模。
　　与defer一样，goroutine也会因“延迟执行”而立即计算并复制执行参数。

var c int

func counter() int {
	c++
	return c
}

func main()  {
	a := 100

	go func(x, y int) {
		time.Sleep(time.Second)
		println("go: ", x, y)
	}(a, counter())

	a += 100
	println("main: ", a, counter())

	time.Sleep(time.Second * 3)		// 等待goroutine结束
}

输出：
main:  200 2
go:  100 1

　　可以看出线程里是复制的变量，当然如果换成指针，结果就一样了。

var c int

func counter() int {
	c++
	return c
}

func main()  {
	a := 100

	p := &a

	go func(x *int, y int) {
		time.Sleep(time.Second)
		println("go: ", *x, y)
	}(p, counter())

	*p += 100
	println("main: ", *p, counter())

	time.Sleep(time.Second * 3)		// 等待goroutine结束
}

输出：
main:  200 2
go:  200 1

wait

　　进程退出时不会等待并发任务结束，可用通道阻塞，然后发出退出信号。

func main()  {
	exit := make(chan struct{})		// 创建通道

	go func() {
		time.Sleep(time.Second)
		println("goroutinue done.")

		close(exit)		// 关闭通道，发出信号
	}()

	println("main ...")
	<-exit		// 如通道关闭，立刻结束阻塞
	println("main exit ...")
}

输出：
main ...
goroutinue done.
main exit ...

　　如果要等待多个任务结束，推荐使用sync.WaitGroup，通过设定计数器，让每个gorountine在退出前递减，直至归零时解除阻塞。

func main()  {
	var wg sync.WaitGroup

	for i := 0; i < 10; i++ {
		wg.Add(1)   // 累加计数

		go func(id int) {
			defer wg.Done()     // 递减计数

			time.Sleep(time.Second)
			println("goroutine", id, "done.")
		}(i)
	}

	println("main ...")
	wg.Wait()   // 阻塞直到计数为0
	println("main exit ...")
}main ...

输出：
goroutine 0 done.
goroutine 9 done.
goroutine 5 done.
goroutine 3 done.
goroutine 1 done.
goroutine 4 done.
goroutine 6 done.
goroutine 7 done.
goroutine 2 done.
goroutine 8 done.
main exit ...

　　WaitGroup.Add实现了原子操作，但建议在goroutine外累加计数器，以免Add尚未执行，Wait已经退出，也就是Add操作来不及执行，计数器就已经清零了，如下面这种情况。

func main()  {
	var wg sync.WaitGroup

	go func() {
		wg.Add(1)	// 来不及设置
		println("I am here!")
	}()

	println("main ...")
	wg.Wait()
	println("main exit ...")
}

输出：
main ...
main exit ...

　　可在多处使用Wait阻塞，它们都能接收到通知。

func main()  {
	var wg sync.WaitGroup
	wg.Add(1)

	go func() {
		wg.Wait()	//等待归零，接触阻塞
		println("Wait exit ...")
	}()

	go func() {
		time.Sleep(time.Second)
		println("done ...")
		wg.Done()
	}()

	println("main ...")
	wg.Wait()
	println("main exit ...")
}

输出：
main ...
done ...
Wait exit ...
main exit ...

GOMAXPROCS

　　运行时可能会创建很多线程，但任何时候仅有限的几个线程参与并发任务执行，改数量默认与处理器核数相等，可用runtime.GOMAXPROCS函数修改。

Local Storage

　　与线程不同，goroutine任务无法设置优先级，无法获取编号，没有局部存储TLS，甚至连返回值都会被抛弃，但是除了优先级外，其他功能都可以很容易实现。

 func main()  {
	var wg sync.WaitGroup

	// 实现类似TLS功能
	var tls [5]struct {
		id int	// 编号
		result int	// 返回值
	}

	for i := 0; i < len(tls); i++ {
		wg.Add(1)

		go func(id int) {
			defer wg.Done()

			tls[id].id = id
			tls[id].result = (id + 1) * 101
		}(i)
	}

	wg.Wait()
	fmt.Printf("%+v\n", tls)

}

输出：
[{id:0 result:101} {id:1 result:202} {id:2 result:303} {id:3 result:404} {id:4 result:505}]

Gosched

　　暂停然后释放线程去执行其他任务，当前任务被放回队列，等待下次调度时恢复执行。

func main()  {
	runtime.GOMAXPROCS(1)
	exit := make(chan struct{})

	// 任务1
	go func() {
		defer close(exit)

		// 任务2，确保任务1先执行
		go func() {
			println("b")
		}()

		for i := 0; i < 5; i++ {
			println("a: ", i)

			if i == 2 {
				runtime.Gosched()
			}
		}
	}()

	<-exit
}

输出：
a:  0
a:  1
a:  2
b
a:  3
a:  4

Goexit

　　Goexit立即终止当前任务，运行时确保所有已注册延迟调用被执行，该函数不会影响其他并发任务，不会引发panic，自然也就无法捕获。
　　如果在main.main离调用Goexit，它会等待其他任务结束，然后让进程直接崩溃。

func main()  {
	for i := 0; i < 2; i++ {
		go func(x int) {
			for n := 0; n < 2; n++ {
				fmt.Printf("%c: %d\n", 'a' + x, n)
				time.Sleep(time.Millisecond)
			}
		}(i)
	}

	runtime.Goexit()	// 等待所有任务结束
	println("main exit...")
}

输出结果：
b: 0
a: 0
a: 1
b: 1
fatal error: no goroutines (main called runtime.Goexit) - deadlock!

　　无论身处哪一层，Goexit都能立即终止整个调用堆栈，这与return仅退出当前函数不同。标准库函数os.Exit()可终止进程，但不会执行延迟调用。

通道

　　Go并未实现严格的并发安全，它允许全局变量、指针、引用类型这些非安全内存共享操作，这就需要开发人员自行维护数据一致和完整性。
　　通过消息来避免竟态的模型有CSP和Actor：

  • CSP： CSP以通信来代替内存共享，实现并发安全，作为CSP核心，通道（channel）是显示的，要求操作双方必须知道数据类型和具体通道，并不关心另一操作者身份和数量。可如果另一端未准备妥当，或消息未能及时处理时，会阻塞到前端。
  • Actor：Actor是透明的，它不在乎数据类型及通道，只要知道接受者信箱即可。默认就是异步方式，发送方对消息是否接受和处理并不关心。

　　Go鼓励使用CSP通道，而Scala一般使用的是Actor。
　　底层实现上，通道只是一个队列。同步模式下，发送和接收方双方配对，然后直接复制数据给对方。如果配对失败，则置入等待队列，直到另一方出现才被唤醒。异步模式抢夺的则是数据缓冲槽。发送方要求有空槽可供写入，而接收方则要求有缓冲数据可读。需求不符时，同样加入等待队列，直到另一写入数据或腾出空槽后被唤醒。
　　除传递数据外，通道还常被用作事件通知。

func main()  {
	done := make(chan struct{})		// 结束事件
	c := make(chan string)		// 数据传输通道

	go func() {
		s := <-c 	// 接收消息
		println(s)
		close(done)
	}()

	c <- "Hello World!"		// 发送消息
	<-done	// 阻塞，直到有数据或管道关闭
}

输出：
Hello World!

　　同步模式必须有配对操作的goroutine出现，否则会一直阻塞。而异步模式在缓冲区未满或数据未读完前，不会阻塞。

func main()  {
	c := make(chan int, 3)	// 创建带3个缓冲槽的异步通道

	c <- 1	// 缓冲区未满，不会阻塞
	c <- 2

	println(<-c)	// 缓冲区尚有数据，不会阻塞
	println(<-c)
}

输出：
1
2

　　cap和len返回缓冲区大小和当前已缓冲数量，而对于同步通道则都返回0，由此可以判断通道是同步还是异步。

func main()  {
	a, b := make(chan int), make(chan int, 3)

	b <- 1
	b <- 2

	println("a: ", len(a), cap(a))
	println("b: ", len(b), cap(b))
}

输出：
a:  0 0
b:  2 3

收发

　　我们还可以用ok-idom或range模式处理数据。

func main()  {
	done := make(chan struct{})
	c := make(chan int)

	go func() {
		defer close(done)

		for {
			x, ok := <-c
			if !ok {
				return
			}

			println(x)
		}
	}()

	c <- 1
	c <- 2
	c <- 3

	close(c)
}

　　或者使用range，循环获取消息，直到通道被关闭。

func main()  {
	done := make(chan struct{})
	c := make(chan int)

	go func() {
		defer close(done)

		for x := range c {
			println(x)
		}
	}()

	c <- 1
	c <- 2
	c <- 3

	close(c)
}

　　及时用close函数关闭通道引发结束通知，否则可能会导致死锁。
　　通知可以是群体性的，也未必就是通知结束，可以是任何需要表达的事件。

func main()  {
	var wg sync.WaitGroup
	ready := make(chan int)

	for i := 0; i < 3; i++ {
		wg.Add(1)

		go func(id int) {
			defer wg.Done()

			println(id, ": ready.")		// 运动员准备就绪
			<-ready						// 等待发令
			println(id, ": running...")
		}(i)
	}

	time.Sleep(time.Second)
	println("Ready? Go!")

	close(ready)

	wg.Wait()
}

输出：
2 : ready.
1 : ready.
0 : ready.
Ready? Go!
2 : running...
1 : running...
0 : running...

单向

　　通道默认是双向的，并不区分发送和接收端。但有时我们可以限制收发操作的方向来获得更严谨的操作逻辑。可使用make创建单向通道，但没有意义，通常使用类型转换来获取单向通道，并分别赋予操作双方。

func main()  {
	var wg sync.WaitGroup
	wg.Add(2)

	c := make(chan int)
	var send chan<- int = c
	var recv <-chan int = c
	
	go func() {
		defer wg.Done()
		
		for x := range recv {
			println(x)
		}
	}()
	
	go func() {
		defer wg.Done()
		defer close(c)

		for i := 0; i < 3; i++ {
			send <- i
		}
	}()
	
	wg.Wait()
}

　　不能在单向通道上做逆向操作，close也不能用于接收端，也无法将单向通道重新转换过去。

选择

　　如需要同时处理多个通道，可选用select语句，它会随机选择一个可用通道做收发操作。

func main()  {
	var wg sync.WaitGroup
	wg.Add(2)

	a, b := make(chan int), make(chan int)

	// 接收端
	go func() {
		defer wg.Done()

		for {
			var (
				name string
				x int
				ok bool
			)
			// 随机选择可用channel接收数据
			select {
			case x, ok = <-a:
				name = "a"
			case x, ok = <-b:
				name = "b"
			}
			// 如果任一通道关闭，则终止接收
			if !ok {
				return
			}
			// 输出接收的数据信息
			println(name, x)
		}
	}()

	// 发送端
	go func() {
		defer wg.Done()
		defer close(a)
		defer close(b)

		for i := 0; i < 10; i++ {
			// 随机选择发送channel
			select {
			case a <- i:
			case b <- i * 10:
			}
		}
	}()

	wg.Wait()
}

输出：
a 0
b 10
a 2
b 30
a 4
b 50
b 60
b 70
a 8
a 9

　　如要等全部通道消息处理结束，可将已完成通道设置尉nil，这样它就会被阻塞，不再被select选中。

func main()  {
	var wg sync.WaitGroup
	wg.Add(3)

	a, b := make(chan int), make(chan int)

	// 接收端
	go func() {
		defer wg.Done()

		for {
			select {
			case x, ok := <-a:
				if !ok {
					a = nil
					break
				}
				println("a ", x)
			case x, ok := <-b:
				if !ok {
					b = nil
					break
				}
				println("b ",x)
			}
			// 全部结束，退出循环
			if a == nil && b == nil {
				return
			}
		}
	}()

	// 发送端a
	go func() {
		defer wg.Done()
		defer close(a)

		for i := 0; i < 3; i++ {
			a <- i
		}
	}()

	// 发送端b
	go func() {
		defer wg.Done()
		defer close(b)

		for i := 0; i < 5; i++ {
			b <- i * 10
		}
	}()
	
	wg.Wait()
}

输出：
b  0
b  10
b  20
b  30
b  40
a  0
a  1
a  2

　　即便是同一通道，也会随机选择case执行。

func main()  {

	wg.Add(2)

	c := make(chan int)

	go func() {
		defer wg.Done()

			select {	// 随机选择case
			case c <- i:
			case c <- i * 10:
			}
		}
	}()

	wg.Wait()
}

　　当所有通道都不可用时，select会执行default语句，由此来避开select阻塞，但须注意处理外层循环，以免陷入空耗。

func main()  {
	done := make(chan struct{})
	c := make(chan int)

	go func() {
		defer close(c)
		for {
			select {
			case x, ok := <-c:
				if !ok {
					return
				}

				fmt.Println("data: ", x)
			default: // 避免select阻塞
			}

			fmt.Println(time.Now())
			time.Sleep(time.Second)
		}
	}()

	time.Sleep(time.Second * 5)

	c <- 100
	close(c)

	<-done
}

输出：

　　也可以利用default处理一些默认逻辑，例如当前通道已满的话，生成新的缓存通道。

func main() {
	done := make(chan struct{})

	data := []chan int {
		make(chan int, 3),
	}

	go func() {
		defer close(done)

		for i := 0; i < 10; i++ {
			select {
			// 生产数据
			case data[len(data) - 1] <- i:
			default:
				data = append(data, make(chan int, 3))
			}
		}
	}()

	<-done

	for i := 0; i < len(data); i++ {
		c := data[i]
		close(c)

		for x := range c {
			println(x)
		}
	}
}

模式

　　通常使用工厂方法讲goroutinue和通道绑定。

type receiver struct {
	sync.WaitGroup
	data chan int
}

func newReceiver() *receiver {
	r := &receiver{
		data: make(chan int),
	}

	r.Add(1)
	go func() {
		defer r.Done()
		for x := range r.data{
			println("recv:", x)
		}
	}()

	return r
}

func main() {
	r := newReceiver()
	r.data <- 1
	r.data <- 2

	close(r.data)
	r.Wait()
}

性能

　　讲发往通道的数据打包，减少传输次数，可有效提供性能。从实现上来说，通道队列依旧使用锁同步机制，单次获得更多数据（批处理），可改善因频繁加锁造成的性能问题。

资源泄露

　　通道可能会引发goroutinue leak，确切地说，是指goroutine处于发送或接收阻塞状态，但一直未被唤醒，垃圾回收器并不收集此类资源，导致它们在等待队列离长久休眠，形成资源泄露，我们可以使用runtime.GC()强制垃圾回收。

同步

　　通道并非是用来取代锁的，它们各自有不同的使用场景，通道倾向于解决逻辑层次的并发处理架构，而锁则用来保护局部范围内的数据安全。
　　标准库sync提供了互斥和读写锁，另有原子操作，可基本满足日常开发需要。
　　Mutex作为匿名字段时，相关方法必须实现尉pointer-receiver，否则会因复制导致锁机制失效。

type data struct {
	sync.Mutex
}

func (d data) test(s string) {
	d.Lock()
	defer d.Lock()

	for i := 0; i < 5; i++ {
		println(s, i)
		time.Sleep(time.Second)
	}
}

func main() {
	var wg sync.WaitGroup
	wg.Add(2)

	var d data

	go func() {
		defer wg.Done()
		d.test("read")
	}()

	go func() {
		defer wg.Done()
		d.test("write")
	}()

	wg.Wait()
}

输出：
write 0
read 0
write 1
read 1
read 2
write 2
read 3
write 3
read 4
write 4
fatal error: all goroutines are asleep - deadlock!

　　我们可以看出锁会失效，将receiver类型改为*data后正常。
　　我们应该将Mutex锁粒度控制在最小范围内，及早释放。Mutex也不支持递归锁，即便在同一goroutinue下也会导致死锁。
