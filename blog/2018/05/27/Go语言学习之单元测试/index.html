引言

　　本文将作一些Go语言中涉及单元测试的一些笔记，这里只记录Go语言和其它语言不太一样的地方。

单元测试

　　单元测试我们都很熟悉，例如Java中的Junit，写单元测试的过程本身也是自己对自己代码review的过程，我们来看看Go中是如何来进行单元测试的。

testing

　　工具链和标准库中自带了单元测试框架，它们有一些限制：

  • 测试代码必须放在当前包以“_test.go”结尾的文件中。
  • 测试函数以Test为名称前缀。
  • 测试命令go test忽略以“_”和“.”开头的测试文件。
  • 正常编译操作go build/install会忽略测试文件。

　　我们做一个简单的加法测试。

func add(x, y int) int {
	return x + y
}

func TestAdd(t *testing.T) {
	if add(1, 2) != 3 {
		t.FailNow()
	}
}

输出：
~> go test -v 

=== RUN   TestAdd
--- PASS: TestAdd (0.00s)
PASS
ok      _/home/hazzacheng/Codes/go/src/hello_word/main  0.001s

　　想要测试当前包和所有子包的话，我们可以用go test ./...，标准库提供了专业类型T来控制测试结果和行为。

方法功能相关
Fail失败：继续执行当前测试函数
FailNow失败：立即终止当前测试函数Failed
SkipNow跳过：停止执行当前测试函数Skip, Skipf, Skipped
Log输出错误信息。仅失败或-v时输出Logf
Parallel鱼油同样设置的测试函数并行执行
ErrorFail + LogErrorf
FatalFailNow _ LogFataf

　　我们使用Parallel来利用多核并行来进行测试。

func TestA(t *testing.T) {
	t.Parallel()
	time.Sleep(time.Second * 2)
}

func TestB(t *testing.T) {
	if os.Args[len(os.Args) - 1] == "p" {
		t.Parallel()
	}
	
	time.Sleep(time.Second * 2)
}

输出：
~❯ go test -v
=== RUN   TestA
=== PAUSE TestA
=== RUN   TestB
--- PASS: TestB (2.00s)
=== CONT  TestA
--- PASS: TestA (2.00s)
PASS
ok      _/home/hazzacheng/Codes/go/src/hello_word/main  4.002s

~❯ go test -v -args "p"
=== RUN   TestA
=== PAUSE TestA
=== RUN   TestB
=== PAUSE TestB
=== CONT  TestA
=== CONT  TestB
--- PASS: TestA (2.00s)
--- PASS: TestB (2.00s)
PASS

　　还有一些常用的测试参数：

参数说明示例
-args命令行参数
-v输出详细参数
-parallel并发执行，默认执行GOMAXPROCS-parallel 2
-run指定测试函数，正则表达式-run “Add”
-timeout全部累计时间超时将引发panic，默认值为10ms-timeout 1m30s
-count重复测试次数，默认为1

table driven

　　我们可以利用类似数据表的模式来批量输入条件并依次对比结果。

func add(x, y int) int {
	return x + y
}

func TestAdd(t *testing.T) {
	var tests = []struct {
		x int
		y int
		expect int
	} {
		{1, 1, 2},
		{2, 2, 14},
		{3, 2, 5},
	}

	for _, tt := range tests {
		actual := add(tt.x, tt.y)
		if actual != tt.expect {
			t.Errorf("add(%d, %d): expect %d, actual %d", tt.x, tt.y, tt.expect, actual)
		}
	}
}

输出：
~> go test -v

=== RUN   TestAdd
--- FAIL: TestAdd (0.00s)
        main_test.go:23: add(2, 2): expect 14, actual 4
FAIL
exit status 1
FAIL    _/home/hazzacheng/Codes/go/src/hello_word/main  0.001s

　　这种方式将测试数据和测试逻辑分离，更便于维护，使用Error是为了让整个表全部完成测试，以便知道具体是哪组条件出现问题。

test main

　　有的时候我们需要尉测试提供初始化和清理操作，但是不像JUnit，go提供的testing并没有setup，teardown类似的机制。我们可以自定义一个名为TestMain的函数，go test会执行该函数，而不再是具体的测试用例。

func TestMain(m *testing.M) {
	// setup
	code := m.Run()		// 调用测试函数
	// teardown
	os.Exit(code)		// os.Exit不会执行defer函数
}

　　M.Run会调用具体的测试用例，但是不能为每个测试文件写一个TestMain，要实现用例组合套件，需要借助MainStart自行构建M对象，通过与命令行参数相配合，即可实现不同测试组合。

package main

import (
	"testing"
	"time"
	"os"
	"errors"
	"io"
	"runtime/pprof"

)

var errMain = errors.New("testing: unexpected use of func Main")
type matchStringOnly func(pat, str string) (bool, error)

func (f matchStringOnly) MatchString(pat, str string) (bool, error)   { return f(pat, str) }
func (f matchStringOnly) StartCPUProfile(w io.Writer) error           { return errMain }
func (f matchStringOnly) StopCPUProfile()                             {}
func (f matchStringOnly) WriteHeapProfile(w io.Writer) error {return pprof.WriteHeapProfile(w)}
func (f matchStringOnly) WriteProfileTo(string, io.Writer, int) error { return errMain }
func (f matchStringOnly) ImportPath() string                          { return "" }
func (f matchStringOnly) StartTestLog(io.Writer)                      {}
func (f matchStringOnly) StopTestLog() error                          { return errMain }

	return x + y

func TestA(t *testing.T) {
	t.Parallel()
	time.Sleep(time.Second * 2)
}

	if os.Args[len(os.Args) - 1] == "p" {
		t.Parallel()

func TestMain(m *testing.M) {


	match := func(pat, str string) (bool, error) {
		// pat: 命令行参数-run 提供的过滤条件
		// str: InternalTest.Name
		return true, nil
	}

	// 用例列表
	tests := []testing.InternalTest{
		{"add", TestAdd},
		{"a", TestA},
		{"b", TestB},
	}

	var benchmarks []testing.InternalBenchmark
	var examples []testing.InternalExample

	m = testing.MainStart(matchStringOnly(match), tests, benchmarks, examples)
	os.Exit(m.Run())
}

example

　　代码最大的用途不是用来测试，而是导入GoDoc等工具生成的帮助文档中，它通过比对输出（stdout）结果和内部output注释是否一致来判断是否成功。

func addTest(x, y int) int {
	return x + y
}

func ExampleAdd()  {
	fmt.Println(add(1, 2))
	fmt.Println(add(1, 3))

	// Output:
	// 3
	// 4
}

输出：
~❯ go test -v
=== RUN   ExampleAdd
--- PASS: ExampleAdd (0.00s)
PASS
ok      _/home/hazzacheng/Codes/go/src/hello_word/main  0.001s

　　很神奇吧，有点类似python里注释里的测试，如果没有output测试，该示例函数就不会被执行。

不能使用内置函数println/print，因为它们会输出到stderr里。

性能测试

　　性能测试函数以Benchmark为名称前缀，同样保存在“_test.go”文件里。测试工具默认不会执行性能测试，须使用bench参数。它通过逐步调整B.N值，反复执行测试函数，直到能获得准确的测量结果。

func addTest(x, y int) int {
	return x + y
}

func BenchmarkAdd(b *testing.B) {
	println("B.N", b.N)

	for i := 0; i < b.N; i++ {
		_ = add(100, 1)
	}

}

　　有一些耗时的目标，默认循环次数过少，取平均值不足以准确计量性能。可用benchtime设定最小测试时间来增加循环次数，以便来返回更准确的结果。

func addTest(x, y int) int {
	return x + y
}

func BenchmarkAdd(b *testing.B) {
	println("B.N", b.N)

	for i := 0; i < b.N; i++ {
		_ = add(100, 1)
	}

}

func sleep() {
	time.Sleep(time.Second)
}

func BenchmarkSleep(b *testing.B) {
	for i := 0; i < b.N; i++ {
		sleep()
	}
}

timer

　　如果在测试函数中要执行一些额外的操作，我们应该临时阻止计时器工作。

func addTest(x, y int) int {
	return x + y
}

func BenchmarkAdd(b *testing.B) {
	time.Sleep(time.Second)
	b.ResetTimer()	// 重置

	for i := 0; i < b.N; i++ {
		_ = addTest(3, 4)

		if i == 1 {
			b.StopTimer()	// 暂停
			time.Sleep(time.Second * 10)
			b.StartTimer()
		}
	}
}

输出：
~> go test -bench . 
goos: linux
goarch: amd64
BenchmarkAdd-8          2000000000               0.39 ns/op
PASS
ok      _/home/hazzacheng/Codes/go/src/hello_word/main  11.846s

memory

　　如果我们想要知道测试时在堆上的内存分配，我们可以使用-benchmem。

func heap() []byte {
	return make([]byte, 1024 * 10)
}

func BenchmarkHeap(b *testing.B) {
	for i := 0; i < b.N; i++ {
		_ = heap()
	}
}

输出：
~> go test -bench . -benchmem -gcflags "-N -l"

func heap() []byte {

func BenchmarkHeap(b *testing.B) {
	b.ReportAllocs()
	b.ResetTimer()

	for i := 0; i < b.N; i++ {
		_ = heap()
	}
}

代码覆盖率

　　Go可以非常简单的告诉我们代码的test coverage，帮助我们进行白盒测试。代码覆盖率也常用来发现死代码。

func TestAdd(t *testing.T) {
	if add(1, 2) != 3{
		t.Fatal("Wrong Answer")
	} else {
		fmt.Println("Right Answer")
	}
}

输出：
~> go test -cover
Right Answer
PASS
coverage: 100.0% of statements
ok      _/home/hazzacheng/Codes/go/src/hello_word/main  0.001s

　　指定covermode和coverprofile可帮助我们获取更详细的信息：

  • set: 是否执行
  • count: 执行次数
  • atomic: 执行次数，支持并发模式
~> go test -cover -covermode count -coverprofile cover.out
Right Answer
PASS
coverage: 100.0% of statements
ok      _/home/hazzacheng/Codes/go/src/hello_word/main  0.001s

~> go tool cover -func=cover.out 
./main.go:3:    add             100.0%
./main.go:7:    main            0.0%
total:          (statements)    100.0%

　　还可以在浏览器中查看包括具体的执行次数等信息。

~> go tool cover -html=cover.out

性能监控

　　性能问题一般因为执行时间过长，内存占用过多和意外阻塞。我们通过捕获或监控相关执行状态数据，就可以定位引发问题的原因，有两种捕获的方式：

  • 在测试时输出并保存相关数据，进行初期评估，然后在运行阶段通过Web接口获得实时数据，分析一段时间内的健康状况。
  • 可以用自定义计数器提供更多与逻辑相关的参考数据。

　　我们拿标准库现有的Benchmark做演示：

~> go test -run NONE -bench . -memprofile mem.out -cpuprofile cpu.out net/http
goos: linux
goarch: amd64
pkg: net/http
BenchmarkCookieString-8                          1000000              1002 ns/op             384 B/op          3 allocs/op
BenchmarkReadSetCookies-8                         500000              3077 ns/op             960 B/op         17 allocs/op
...
FAIL
exit status 1
FAIL    net/http        83.787s

　　分别保存了CPU和Memory Profile采样的数据。

参数说明示例
-cpuprofile保存执行时间采样到指定文件-cpuprofile cpu.out
-memprofile保存内存分配采样到指定文件-memprofile mem.out
-memprofilerate内存分配采样值，默认为512KB-memprofilerate 1
-blockprofile保存阻塞时间采样到指定文件-blockprofile block.out
-blockprofilerate阻塞时间采样起始值，单位:ns

　　在线采集数据的话，需要注入http/pprof包。

import (
	"net/http"
	_ "net/http/pprof"
)

func main() {
	http.ListenAndServe(":10000", http.DefaultServeMux)
}

　　用浏览器访问指定路径，就可以看到不同的监控项，直接点击或者用命令行。

go tool pprof http://localhost:10000/debug/pprof/heap?debug=1

　　还可以抓取数据进行离线分析。

~> curl http://localhost:10000/debug/pprof/heap?debug=1 > mem.out
~>go tool pprof test mem.out
