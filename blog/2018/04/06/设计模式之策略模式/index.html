设计模式之策略模式

2018-04-06 阅读时长: 3 分钟
目录

引言

　　策略模式（Strategy Pattern）作为一种软件设计模式，指对象有某个行为，但是在不同的场景中，该行为有不同的实现算法。比如每个人都要“交个人所得税”，但是“在美国交个人所得税”和“在中国交个人所得税”就有不同的算税方法。
　　它定义了算法家族，分别封装起来，让它们之间可以互相替换，此模式让算法的变化，不会影响到使用算法的客户。

结构图

　　策略模式的UML结构图如下所示：

　　ConcreteStrategyA，ConcreteStrategyB和ConcreteStrategyC作为具体策略类，继承于Strategy，封装了具体的算法或行为，有点类似简单工厂。Context上下文，用一个ConcreteStrategy来配置，维护一个对Strategy对象的引用。

实现

　　我们考虑一个实际情况，商场会经常会搞各种各样的促销活动，例如打折，满多少返利，这样也导致了收银的时候价格的不同，我们可以通过策略模式来完成这一功能。

  • 现金收费抽象类：
public abstract class CashStrategy {
    public abstract double acceptCash(double money);
}
  • 正常收费子类：
public class CashNormalStrategy extends CashStrategy {

    @Override
    public double acceptCash(double money) {
        return money;
    }
}
  • 打折收费子类：
public class CashRebateStrategy extends CashStrategy {

    private double moneyRebate = 1d;
    
    public CashRebateStrategy(double moneyRebate) {
        this.moneyRebate = moneyRebate;
    }
    
    @Override
    public double acceptCash(double money) {
        return money * moneyRebate;
    }
}
  • 返利收费子类：
public class CashReturnStrategy extends CashStrategy {

    private double moneyCondition = 0.0d;
    private double moneyReturn = 0.0d;
    
    public CashReturnStrategy(double moneyCondition, double moneyReturn) {
        this.moneyCondition = moneyCondition;
        this.moneyReturn = moneyReturn;
    }

    @Override
    public double acceptCash(double money) {
        double res = money;
        
        if (money >= moneyCondition) {
            res = money - Math.floor(money / moneyCondition) * moneyReturn;
        }

        return res;
    }
    
}
  • CashContext类：
public class CashContext {
    private CashStrategy cs;
   
    public CashContext(CashStrategy cashStrategy) {
        this.cs = cashStrategy;
    }
    
    public double getResult(double money) {
        return cs.acceptCash(money);
    }
}
  • 客户端代码：
    public static void main(String[] args) {
        double prices = 3332.1d;
        String strategy = "正常收费";
        
        CashContext cc = null;
        
        switch (strategy) {
            case "正常收费":
                cc = new CashContext(new CashNormalStrategy());
                break;
            case "满300返100":
                cc = new CashContext(new CashReturnStrategy(300, 100));
                break;
            case "打八折":
                cc = new CashContext(new CashRebateStrategy(0.8));
                break;
            default:
                break;
        }

        double totalPrices = 0d;
        totalPrices = cc.getResult(prices);
    }

　　还是非常容易理解的，很像简单工厂方法。

策略与简单工厂想结合

　　你会发现策略模式和简单工厂模式非常相似，貌似就是少了一个工厂类，多了一个Context类。客户端代码看上去比较复杂，实际上我们还能进一步改造Context类，让它更像简单工厂类，来简化客户端的代码。

  • 改造后的CashContext类：
public class CashContext {
    private CashStrategy cs;

    public CashContext(String type) {
        
        switch (type) {
            case "正常收费":
                cs = new CashNormalStrategy(); 
                break;
            case "满300返100":
                cs = new CashReturnStrategy(300, 100);
                break;
            case "打八折":
                cs = new CashRebateStrategy(0.8);
                break;
            default:
                break;
        }
    }

    public double getResult(double money) {
        return cs.acceptCash(money);
    }
}
  • 客户端代码：
    public static void main(String[] args) {
        double prices = 3332.1d;
        String strategy = "正常收费";

        CashContext cc = new CashContext(strategy);

        double totalPrices = 0d;
        totalPrices = cc.getResult(prices);
    }

　　如果你真正理解简单工厂模式和策略模式的话，你会发现如果使用简单工厂模式的话，客户端需要认识两个类CashStrategy和一个工厂类，而策略模式与简单工厂模式想结合的方法，客户端只需要认识一个CashContext类就可以了，这使得代码耦合更加降低了。

总结

　　策略模式是一种定义一系列算法的方法，从概念上来讲，所有这些算法完成的都是相同的工作，只是实现不同，它可以以相同的方式调用所有的算法，减少了各种算法类与使用算法类之间的耦合。
　　它还有一些优点：

  • 策略模式的Strategy类为Context类定义了一系列的可供重用的算法或行为，继承有助于析取这些算法中的公共功能。
  • 简化了单元测试，因为每个算法都有自己的类，可以通过自己的接口单独测试。
  • 策略模式封装了变化，不仅可以封装算法，在实践中，我们还可以封装几乎任何类型的规则，只要在分析过程中需要在不同时间应用不同的业务规则，就可以考虑使用策略模式处理这种变化的可能性。
