Scala学习笔记（十一）- Scala里的型变(Variance)

引言

　　在Scala中，高阶类型用于简化类型定义或者使更复杂类型符合简单类型参数的要求，型变给参数化类型和高阶类型增加了额外的复杂度。

高阶类型(Higher Kinded Types)

　　高阶函数是接受其他函数为参数的函数，高阶类型则是接受其他类型作为参数构造出新类型的类型，所以高阶类型又称为类型构造器。
　　下面是个高阶类型的例子：

scala> type CallBack[T] = Function[T, Unit]
defined type alias CallBack

scala> val x: CallBack[Int] = y => println(y + 2)
x: CallBack[Int] = $$Lambda$1907/1860564101@20d19f2c

scala> x(8)
10

型变(Variance)

　　在Scala中，型变是指像T[A]这样的高阶类型的类型参数可以改变或变化的能力，型变是一种声明类型参数如何变化以创建顺应类型的方式。
　　在Scala中，型变有三种形式：

  • 不变(Invariance): 对于任何类型T，A和B，如果T[A]顺应于T[B]，那么A一定等于B。在参数中不需要加任何符号。
  • 协变(Covariance): 对于任何类型T，A和B，如果T[A]顺应于T[B]，那么A <: B。参数中需要标注+。
  • 逆变(contravariance): 对于任何类型T，A和B，如果T[A]顺应于T[B]，那么A >: B。在参数中需要标注-。

　　不变和协变比较好理解，逆变理解起来就不是那么容易了，不过放到Function对象里就很容易理解了，Function对象的返回类型是协变的，这毋庸置疑，但是对参数类型就是逆变的，因为你可以拿一个函数的返回值并转换为超类，对于参数来说，你可以传入参数类型的子类，我们来举个例子。
　　假设A <: B <: C，我们定义一个函数：

val test: (B => String) = ((x: C) => "Hello World!") // 编译成功
val test: (B => String) = ((x: A) => "Hello World!") // 编译报错，type mismatch

　　通过这个例子我们发现函数的参数类型很显然是逆变的，这也很有道理，因为如果如第二种情况所示，如果参数类型是协变的，那么将类型改为A后，你们保证所有的B的子类都是A的子类，因为可能存在一个和A同级的子类D，造成type mismatch，逆变避免了这种情况的发生。
　　我们再看一下返回类型：

val a = new A
val b = new B
val c = new C

val test: (String => B) = ((x: String) => a) // 编译成功
val test: (String => B) = ((x: String) => c) // 编译失败，type mismatch

　　可以看出来是协变的，也挺好理解的，如果返回类型可以变成C的话，那么你不能保证不会存在一个和B同级的C的子类，这样也会造成type mistmatch。
　　因为Function对象里的参数类型是逆变的，所以下面这个例子就不行：

scala> trait T[+A] {
     |  def foo(a: A) = a
     | }
<console>:12: error: covariant type A occurs in contravariant position in type A of value a
        def foo(a: A) = a
                ^

　　理所当然，编译器报错提示我们把协变类型用到了逆变位置上。
　　下面我们来定一个函数对象，举个例子，利用型变灵活的对函数对象做类型转换。

　　首先创建特质Fucntion，第一个类类型是函数的参数类型，第二个类型是函数的返回类型：

scala> trait Function[Arg, Return]
defined trait Function

　　参数类型和返回类型都不变的函数对象：

scala> val y: Function[String, Any] = x
<console>:13: error: type mismatch;
 found   : Function[Any,String]
 required: Function[String,Any]
Note: Any >: String, but trait Function is invariant in type Arg.
You may wish to define Arg as -Arg instead. (SLS 4.5)
Note: String <: Any, but trait Function is invariant in type Return.
You may wish to define Return as +Return instead. (SLS 4.5)
       val y: Function[String, Any] = x
                                      ^

scala> val y: Function[Any, Any] = x
<console>:13: error: type mismatch;
 found   : Function[Any,String]
 required: Function[Any,Any]
Note: String <: Any, but trait Function is invariant in type Return.
You may wish to define Return as +Return instead. (SLS 4.5)
       val y: Function[Any, Any] = x
                                   ^

　　因为我们没有定义任何型变标注，类型不相同，编译器利索当然的报错了，接下来我们把返回类型标注成协变的。

  • 仅有协变的函数对象：
scala> trait Function[Arg, +Return]
defined trait Function

scala> val x = new Function[Any, String] {}
x: Function[Any,String] = $anon$1@c5a2d5

scala> val y: Function[String, Any] = x
<console>:13: error: type mismatch;
 found   : Function[Any,String]
 required: Function[String,Any]
Note: Any >: String, but trait Function is invariant in type Arg.
You may wish to define Arg as -Arg instead. (SLS 4.5)
       val y: Function[String, Any] = x
                                      ^

scala> val y: Function[Any, Any] = x
y: Function[Any,Any] = $anon$1@c5a2d5

　　我们看到返回类型已经支持协变了，最后我们把参数类型设置成逆变的。

  • 包含协变和逆变的参数对象：
scala> val y: Function[Any, Any] = x
y: Function[Any,Any] = $anon$1@c5a2d5

scala> trait Function[-Arg, +Return]
defined trait Function

scala> val x = new Function[Any, String] {}
x: Function[Any,String] = $anon$1@7c682e26

scala> val y: Function[String, Any] = x
y: Function[String,Any] = $anon$1@7c682e26

scala> val y: Function[Any, Any] = x
y: Function[Any,Any] = $anon$1@7c682e26

　　成功进行了类型转化。

　　我们将特质扩展一下，把它应用到实际场景：

scala> trait Function[-Arg, +Return] {
     |  def apply(arg: Arg): Return
     | }
defined trait Function
                     
scala> val foo = new Function[Any, String] {
     |  override def apply(arg: Any): String = "I get a" + arg
     | }
foo: Function[Any,String] = $anon$1@4a9ff419

scala> val bar: Function[String, Any] = foo
bar: Function[String,Any] = $anon$1@4a9ff419

scala> bar("string")
res1: Any = I get astring

scala> bar(8)
<console>:13: error: type mismatch;
 found   : Int(8)
 required: String
       bar(8)
           ^

scala> foo(8)
res3: String = I get a8

scala> foo("test")
res4: String = I get atest

　　我们看到我们可以构造bar函数对象，其直接调用foo对象，请注意这里并没有构造新对象，我们只是把一个类型赋给另一个类型，类似于多态的把一个子类的值赋给父类的引用，所以bar函数只能把String类型转为Any类型输出，但是却不能像foo函数接受任何类型，但却只能返回String类。
　　这就是型变的魅力！

高级型变

　　我们都知道，Scala里的++操作符十分强大，可以把两个集合类型组合起来，它们的所包含的值可以是不同的。

scala> val strList = List("a", "b")
strList: List[String] = List(a, b)

scala> val intList = List(1, 2)
intList: List[Int] = List(1, 2)

scala> strList ++ intList
res3: List[Any] = List(a, b, 1, 2)

　　一个String类型的list和int类型的list结合起来之后，变成了它们共同超类Any类型的list。
　　++操作符甚至可以将两个不同的集合类型结合起来。

scala> val list = List("A", "B")
list: List[String] = List(A, B)

scala> val array = Array(1, 2)
array: Array[Int] = Array(1, 2)

scala> list ++ array
res4: List[Any] = List(A, B, 1, 2)

scala> array ++ list
res5: Array[Any] = Array(1, 2, A, B)

　　这些其实都是通过型变来实现的，在实际的集合库里，由于集合库提供了许多高级特性，因此++方法的方法签名是相当复杂的，所以这里我们只实现一个简化版本的++方法，用来举个例子。

scala> trait List[+ItemType] {
     |  def ++(other: List[ItemType]): List[ItemType]
     | }
<console>:12: error: covariant type ItemType occurs in contravariant position in type List[ItemType] of value other
        def ++(other: List[ItemType]): List[ItemType]
               ^

　　我们想把这个参数定义成是协变的，但是和我们前面所举的例子一样，这样显然不是不可以的，因为我们把ItemType用到了逆变位置上。但是我们知道把两个相同的类型的列表组合起来是类型安全的，组合的结果仍然可以在ItemTpye层级上向上转换，编译器在处理型变的时候好像有点过于严格了，我们想办法来绕过限制。
　　我们可以让++方法来接受类型参数，我们可以用这个新类型参数来避免把ItemType放在逆变位置上。

scala> trait List[+ItemType] {
     |  def ++[OtherItemType](other: List[OtherItemType]): List[ItemType]
     | }
defined trait List

　　这样的话我们就可以然过了限制，我们再来实现一个EmptyList类。

scala> class EmptyList[ItemType] extends List[ItemType] {
     |  def ++[OtherItemType](other: List[OtherItemType]) = other
     | }
<console>:13: error: type mismatch;
 found   : List[OtherItemType]
 required: List[ItemType]
        def ++[OtherItemType](other: List[OtherItemType]) = other
                                                            ^

　　我们看到，编译器报错，ItemType和OtherItemType类型不兼容，这也挺好理解的，因为我们未对OtherItemType做任何限制，它当然不能随意的被转换成ItemType类型。那么我们应该对OtherItemType做什么样的限制呢，因为ItemType是协变的，我们知道可以把当前的List向ItemType层级上方转换，因此我们用ItemType作为OtherItemType的下界约束，我们修改一下。

scala> trait List[+ItemType] {
     |  def ++[OtherItemType >: ItemType](other: List[OtherItemType]): List[OtherItemType]
     | }
defined trait List

scala> class EmptyList[ItemType] extends List[ItemType] {
     |  def ++[OtherItemType >: ItemType](other: List[OtherItemType]) = other
     | }
defined class EmptyList

　　这样就可以了，我们来试试++操作：

scala> val strings = new EmptyList[String]
strings: EmptyList[String] = EmptyList@88432f5

scala> val ints = new EmptyList[Int]
ints: EmptyList[Int] = EmptyList@3324f7fb

scala> val anyrefs = new EmptyList[AnyRef]
anyrefs: EmptyList[AnyRef] = EmptyList@23ea17e

scala> val anys = new EmptyList[Any]
anys: EmptyList[Any] = EmptyList@62cf8fda

scala> strings ++ ints
res6: List[Any] = EmptyList@3324f7fb

scala> strings ++ anyrefs
res8: List[AnyRef] = EmptyList@23ea17e

scala> strings ++ anys
res9: List[Any] = EmptyList@62cf8fda

scala> anyrefs ++ anys
res10: List[Any] = EmptyList@62cf8fda

scala> ints ++ ints
res11: List[Int] = EmptyList@3324f7fb

　　我们看到，可以正常的进行++操作，并且合成后的List是两个集合的共同超类，这样一个类型安全的List接口就实现了。
　　一般来说，当在类方法里碰到协变和逆变故障时，通常的解决方法是引入一个新的类型参数，在方法签名里用新引入的类型参数，就比如我们引入OtherItemType一样，这样不仅不会造成类型不安全，而且还会灵活的多。
