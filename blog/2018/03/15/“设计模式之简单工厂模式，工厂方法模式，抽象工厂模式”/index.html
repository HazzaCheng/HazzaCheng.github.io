策略模式之简单工厂模式，工厂方法模式，抽象工厂模式

引言

　　这篇文章主要记录一下工厂模式，包括简单工厂模式（Simple Factory Pattern），工厂方法模式（Factory Method Pattern）和抽象工厂模式（Abstract Factory Pattern）。

简单工厂模式

　　简单工厂模式还是很简单的，我们用这种设计模式来模拟下计算器的设计。
　　算数操作类：

public abstract class Operation {
    private double num1 = 0;
    private double num2 = 0;

    public double getNum1() {
        return num1;
    }

    public void setNum1(double num1) {
        this.num1 = num1;
    }

    public double getNum2() {
        return num2;
    }

    public void setNum2(double num2) {
        this.num2 = num2;
    }

    public abstract double getResult();
}

class OperationAdd extends Operation {

    @Override
    public double getResult() {
        return getNum1() + getNum2();
    }
}

class OperationSub extends Operation {

    @Override
    public double getResult() {
        return getNum1() - getNum2();
    }
}

class OperationMul extends Operation {

    @Override
    public double getResult() {
        return getNum1() * getNum2();
    }
}

class OperationDiv extends Operation {

    @Override
    public double getResult() {
        return getNum1() / getNum2();
    }
}

　　工厂类：

public class SimpleOperationFactory {
    public static Operation createOperate(String operate) {
        Operation oper = null;
        switch (operate) {
            case "+":
                oper = new OperationAdd();
                break;
            case "-":
                oper = new OperationSub();
                break;
            case "*":
                oper = new OperationMul();
                break;
            case "/":
                oper = new OperationDiv();
                break;
        }

        return oper;
    }
}

　　客户端代码：

        Operation oper;
        oper = SimpleOperationFactory.createOperate("+");
        oper.setNum1(1);
        oper.setNum2(2);
        double result = oper.getResult();

　　原理很简单，如果我们想要再加一个算术功能的话，只需要再写一个Operation类，然后再在工厂类里面加入一个case就可以了。

工厂方法模式

　　那么工厂模式又是什么呢，我们还是举上面计算器的例子，其实就是将不同的Operation子类封装到不同的工厂里，我们来看下代码。
　　首先来构建一个工厂接口：

public interface OperationFactory {
    Operation createOperation();
}

　　然后替加减乘除各建立一个具体的工厂：

class AddFactory implements OperationFactory {

    @Override
    public Operation createOperation() {
        return new OperationAdd();
    }
}

class SubFactory implements OperationFactory {

    @Override
    public Operation createOperation() {
        return new OperationSub();
    }
}

class MulFactory implements OperationFactory {

    @Override
    public Operation createOperation() {
        return new OperationMul();
    }
}

class DivFactory implements OperationFactory {

    @Override
    public Operation createOperation() {
        return new OperationDiv();
    }
}

　　客户端代码：

        OperationFactory operationFactory = new AddFactory();
        Operation operation = operationFactory.createOperation();
        operation.setNum1(1);
        operation.setNum2(1);
        double res = operation.getResult();

　　我们可以看出它和简单工厂的区别，少掉了case语句的判断，这也就是工厂方法和简单工厂的区别。**简单工厂模式的最大优点在于工厂类中包含必要的逻辑判断，根据客户端的选择条件动态实例化相关的类，对于客户端来说，去除了与具体产品的依赖。**当我们例如需要加入一个模运算的时候，还必须要在case分支里添加新条件，这样虽然方便了客户端代码的编写，但实际上违反了开放-封闭原则(OCP)。
　　而工厂模式，定义一个用于创建对象的接口，让子类决定实例化哪一个类，工厂方法使一个类的实例化延迟到其子类。因为这个工厂类与分支耦合，根据依赖倒转原则，我们把工厂类抽象出一个接口，这个接口只有一个方法，就是创建抽象产品的工厂方法。然后所有要生产具体类的工厂，就去实现这个接口，这样一个简单工厂模式的工厂类，变成了一个工厂抽象接口和多个具体生成对象的工厂。这样，我们增加一个模运算的功能时，就不需要更改原有的工厂类，只需要增加此功能的运算类和相应的工厂类就可以了。
　　你会发现，工厂方法模式实现时，客户端需要决定实例化哪一个工厂来实现运算类，选择判断的问题还是存在的，也就是说，你想要加的功能，本来是改工厂类的，现在需要修改客户端代码。

抽象工厂模式

　　抽象工厂模式是啥？简单点来说，就是提供一个创建一系列或相互以来对象的接口，而无需指定它们具体的类。
　　这么说也很抽象，我们举个例子来说明下。这个例子是关于数据库切换的，假如我们在一个项目里会用到不同的数据库，我们可以通过抽象工厂模式来便捷的切换不同数据库的执行逻辑。
　　为了简单点，我们假设只用到Mysql和Oracle两种数据库。
　　假设有User和Article两张表，我们首先实现两个类来代表它们，注意下面的代码只保留结构，具体的sql语句与数据库执行逻辑就都省略了。

public class User {
    private int id;
    private int name;

    public int getId() {
        return id;
    }

    public void setId(int id) {
        this.id = id;
    }

    public int getName() {
        return name;
    }

    public void setName(int name) {
        this.name = name;
    }
}

public class Article {
    int id;
    String title;

    public int getId() {
        return id;
    }

    public void setId(int id) {
        this.id = id;
    }

    public String getTitle() {
        return title;
    }

    public void setTitle(String title) {
        this.title = title;
    }
}

　　接着我们将这两个表的再抽象成接口，里面包含插入和查询两个抽象方法，方便不同数据库根据不同的需求去实现这两个接口，来访问这两个表。

public interface IUser {
    void insert(User user);

    User getUser(int id);
}

public interface IArticle {
    void insert(Article article);

    Article getArticle(int id);
}

　　接下来根据不同的数据库来实现接口。

public class MysqlUser implements IUser {
    @Override
    public void insert(User user) {
        
    }

    @Override
    public User getUser(int id) {
        return null;
    }
}

public class OracleUser implements IUser {
    @Override
    public void insert(User user) {
        
    }

    @Override
    public User getUser(int id) {
        return null;
    }
}

public class MysqlArticle implements IArticle {
    @Override
    public void insert(Article article) {

    }

    @Override
    public Article getArticle(int id) {
        return null;
    }
}

public class OracleArticle implements IArticle {
    @Override
    public void insert(Article article) {
        
    }

    @Override
    public Article getArticle(int id) {
        return null;
    }
}

　　接着，我们构建一个工厂接口。

public interface IFactory {
    IUser createUser();

    IArticle createArticle();
}

　　然后，就是像工厂方法模式那样，给不同的数据库实现接口，建立各自的工厂。

public class MysqlFactory implements IFactory {
    @Override
    public IUser createUser() {
        return new MysqlUser();
    }

    @Override
    public IArticle createArticle() {
        return new MysqlArticle();
    }
}

public class OracleFactory implements IFactory {
    @Override
    public IUser createUser() {
        return new OracleUser();
    }

    @Override
    public IArticle createArticle() {
        return new OracleArticle();
    }
}

　　客户端代码大概是这样，根据不同需要，使用不同的数据库工厂。

        User user = new User();
        IFactory factory = new OracleFactory();
        IUser iUser = factory.createUser();
        iUser.insert(user);
        iUser.getUser(1);

　　如果你看懂了设计思路的话，你会发现其实抽象工厂方法较工厂方法，就是在工厂接口里加入了更多的抽象方法，供具体工厂根据不同的需求来实现它们。

优点

　　优点和工厂方法差不多，都符合开放-封闭原则，依赖倒置原则，具体工厂依赖于接口实现，客户端的代码与具体创建实例过程相分离，客户端通过它们的抽象接口操纵实例，产品的具体类名也被具体工厂的实现分离。

缺点

　　缺点也是显而易见的，就是在我们新加功能的时候，会显得比较繁琐。假如我们需要加一个表Project的操作，那么至少需要添加IProject，MysqlProject，OracleProject三个类，还需要修改IFactory，MysqlFactory和OracleFactory三个类。

改进

　　我们如何改进抽象工厂的缺点呢，我们考虑通过简单工厂模式来进行解藕，我们删去IFactory，MysqlFactory和OracleFactory，用一个DataAccess类来代替，通过里面的case判断来使用具体的数据库。

public class DataAccess {
    private static final String db = "Mysql";
//    private static final String db = "Oracle";
    
    public static IUser createUser() {
        IUser res = null;
        
        switch (db) {
            case "Mysql":
                res = new MysqlUser();
                break;
            case "Oracle":
                res = new OracleUser();
                break;
        }

        return res;
    }

    public static IArticle createArticle() {
        IArticle res = null;

        switch (db) {
            case "Mysql":
                res = new MysqlArticle();
                break;
            case "Oracle":
                res = new OracleArticle();
                break;
        }

        return res;
    }
}

　　这里db我们指定好了，其实可以通过从配置文件读的方式，指定数据库。
　　这样的改进，确实解藕了，客户端代码也会比较简洁，加入一个新表也比较容易，只要添加一个静态方法就可以了。但是它的缺点也是显而易见的，如果我们要加入一个新的数据库SQLSever的话，就会非常麻烦，需要在每个case分支添加额外的代码，本来我们只需要加入一个具体工厂SQLSeverFactory就可以了。

反射技术

　　其实抽象工厂方法包括工厂方法还有个共同的缺点，就是在客户端代码中我们需要具体指明用哪种数据库，例如IFactory factory = new OracleFactory();，假如我们在100个客户端代码中都这么写了，但我们现在需要将数据库更换为Mysql的话，我们就必须修改100次了，你可能会说，我们可以通过在客户端代码中添加case判断来解决这个问题，确实这样可以解决这个问题，但是我们有更好的方法解决这个问题，那就是反射。
　　这里用到反射的知识，主要是利用反射可以通过字符串来实例化类的功能，例如

IUser iUser = (IUser) Class.forName("com.hazza.abstractDbFactory.MysqlUser").newInstance();

　　com.hazza.abstractDbFactory.MysqlUser是通过字符串传进去的，看到这里你应该就懂了，我们可以把需要使用的数据库名称写到一个配置文件中，然后读取配置文件，将所有的数据操作类的名字都取成一种格式，通过字符串拼接构造出com.hazza.abstractDbFactory.MysqlUser这个类名的字符串，我们修改下之前简单工厂的代码。

public class DataAccess {
    private static final String packageName = "com.hazza.abstractDbFactory";
    private static final String db = "Mysql"; // can read from configuration files

    public static IUser createUser() throws ClassNotFoundException, IllegalAccessException, InstantiationException {
        String className = packageName + "." + db + "User";
        return (IUser) Class.forName(className).newInstance();
    }

    public static IArticle createArticle() throws ClassNotFoundException, IllegalAccessException, InstantiationException {
        String className = packageName + "." + db + "Article";
        return (IArticle) Class.forName(className).newInstance();
    }
}

　　这样我们就可以通过反射来解决掉switch的功能了，如果添加一个新的表Project需要操作，我们只需要增加三个与Project相关的类，再在简单工厂里添加一个createProject的静态方法。如果需要添加一个新的数据库，我们只需要添加相关的User类和Article类就可以了。

总结

　　通过对简单工厂模式，工厂方法模式，抽象工厂模式的学习，我们也了解了它们各自的优缺点。三者结合起来再加上反射，会使我们的设计模式更加灵活，更加容易维护和管理。
