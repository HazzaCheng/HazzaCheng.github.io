Ensemble Selection 笔记

引言

　　最近参加了一个 AutoML 的比赛，在集成的地方花了挺多的功夫，没想到集成方法居然和康奈尔大学 2004 年发表的一篇论文有点类似，其中提出了 Ensemble Selection 的集成方法，和我想的有异曲同工之处，但是人家想的要比我完善的多，所以记录下，这篇康奈尔大学的论文也可以说是集成学习的入门之作了。

Ensemble Selection

　　Ensemble Selection 的大体思想就是有一个 library 保存了很多训练好的模型，它们是用不同的参数训练出来的，论文里这个 library 有 2000 个模型，作者提出了一个 forward stepwise selection 的方法，从 library 里挑选出一个模型子集，平均它们的预测结果来达到非常好的预测效果。
　　思想还是非常简单的，Ensemble Selection 的流程也非常简单：

  1. 从空的模型集合开始集成
  2. 不断从 library 里遍历挑选模型来加入集成，要求是集成后的结果要不断在验证集上达到更好的效果，否则不加入集成。
  3. 重复第二个步骤，直到达到迭代次数的上限，或者所有模型都加入了集成。
  4. 返回从 library 里挑选的模型子集，它在验证集上有着最好的表现。

Optimization

　　Ensemble Selection 方法是非常简单的，速度快又高效，但是有时也会在验证集上出现过拟合的现象。所以作者提出了三种方法试图缓解这个问题。

Selection with Replacement

　　通过字面意思就很好理解这种做法的意思，它允许把同一个模型多次加入到集成中。为啥要这样做呢，考虑这样一个情况，最好的模型已经被加入到了集成中，剩余未加入的模型会降低集成的效果，此时与其不再加入模型，不妨将之前已经加入集成的模型再次加入到集成中，这样可以在集成效果达到顶端时，进一步进行 fine tuning，本质就是加强了这些最好的预测的权重，通过下图可见，它使学习曲线更加平滑了。

Sorted Ensemble Intialization

　　forward selection 经常会在集成的模型很少时造成过拟合的现象，为了解决这个问题，我们可以初始化一个模型集合用于集成，这个集合包含 \(N\) 个模型，它们是 library 里 \(N\) 个 performance 最好的模型。\(N\) 通常设置为5到25之间。

Bagged Ensemble Selection

　　随着 library 里 model 数量的上升，在验证集上过拟合的风险就越来越大，bagging 可以缓解这种风险，我们从 librara 里随机选取 \(M\) 个 model 作为一个 sample bag ，然后在这个 bag 里挑选 model 进行集成。设置 \(p=0.5\)，表示这个 bag 里有 library 里百分之多少的模型，那么这 \(M\) 个模型最后被集成的概率实际上不足 \((1-p)^{M}\)。我们将 Bagged Ensemble Selection 重复20次，然后平均它们的集成，这实际也是对原有的模型做了一个加权平均。

复杂度

　　这种集成方法的复杂度其实十分好计算，为 \(\mathrm{O}\left(\mathrm{D}^{*} \mathrm{M}^{*} \mathrm{K}\right)\)，其中 \(\mathrm{D}\) 为验证集的大小，\(\mathrm{M}\) 为 library 里模型的大小，\(\mathrm{K}\) 为至多迭代的轮数。
　　需要注意的是，这里我们简单把每个 model 计算 metric 的开销记为 \(\mathrm{O}\left(\mathrm{D}\right)\)，实际上有的 metric 要更耗时一点，例如 ROC 还需要排序，它的复杂度为 \(\left.\mathrm{O}\left(\mathrm{D}^{*} \log \mathrm{D}\right)\right)\)。

Conclusion

　　通过简单的学习，可以看出 2004 年提出来的 Ensemble Selection 实际上是一个非常简单的集成策略，但是在实际应用和比赛中却有着很好的表现，不得不说，有的时候简单就是一种美啊。
