01 微软还适合按软件公司理解吗？

信息截止：北京时间 2026-10-22。

微软四年收入增长 67.37%，现金FCF只增长 2.82%。

扩张期先购买资产、后取得收益，可以解释一部分现金压力；能否收回投入，要由之后的客户付款和设备使用回答。收入先形成营业利润，再经税与经营收付形成现金；其中一部分还要支持服务的维持和扩展，剩余部分才可能增加股东现金。

微软的生意可以压缩成一句话：企业为工作系统持续运转付费，微软把应用、身份、数据与计算接在一起；组织关系帮助收费重复发生，新增计算需求则要求持续投入实体资产。营业利润先看付费范围与净价格、交付服务和期间成本；股东现金还要看维持增长需要留下的资本。

错觉一：Windows 还是理解微软的中心

判断微软收入的重心，要先识别付款人和采购预算。电脑厂商购买预装授权，企业采购部门购买员工工具与安全能力，业务部门购买流程应用，技术部门消费计算和数据服务。产品界面相似或品牌相同，不代表它们按同一种单位收费，也不代表利润率相同。

先看最近完整财年的旧三分部。它们是 FY2026 的报告口径，不能与随后公布的两分部相加。

生产力与业务流程的营业利润高于智能云。这提示我们，追逐最新的云和 AI 叙事时，也要理解现有应用怎样持续收费。Microsoft 365 商业业务把办公、协作、安全和 Windows 商业部分放进企业采购体系；Dynamics 则进入财务、客户、供应链等业务流程。前者主要看有效席位与客单价，后者还要看客户采用哪些应用及消费多少服务。FY2026 年报业务说明。

这里的 Windows 至少要分两条线。OEM 授权随电脑厂商销售新设备，受出货、产品组合和库存周期影响。商业 Windows 则包含本地授权与云服务，在 FY2026 已纳入 Microsoft 365 商业产品及云服务的相关定义。它与企业安全、设备管理和长期合同联系更紧。

因此，FY2026 的“Windows and Devices”收入 17.084 十亿美元，既包含 Surface 等设备，也不覆盖所有 Windows 商业收入。拿它除以总收入，不能得到“Windows 对微软全部业务的贡献”。同一个品牌可以跨越多个财务边界；一个分部也可以包含不同收费方式。FY2026 年报 Note 18 产品分类与分部定义。

设想一家企业添置电脑、扩充员工并更新安全方案。OEM 许可随新设备发生，商业套件围绕员工和套餐持续收费，后台服务再随实际业务运行消耗资源。续费的基础是员工、权限、记录与系统仍要共同运转；利润的变化则取决于客户多买了什么、折后实际支付多少，以及微软多承担了哪些服务成本。这个场景只解释收费机制，不代表一份典型客户账单。

游戏、硬件与广告也要各看各的账

更多个人计算不等于 Windows。Xbox 包含硬件，也包含自有及第三方游戏、游戏内内容、Game Pass、云游戏和相关服务。卖出一台主机、卖出一款游戏、获得一名持续订阅者，收入周期与投入方式都不同。游戏工作室还要承担开发、延期、内容寿命和取得玩家的成本。

FY2026，Xbox 硬件收入下降 29%，内容与服务下降 5%；Game Pass 增长对后者形成部分抵消。只看主机销量会漏掉订阅和跨平台内容，只看订阅增长也会漏掉其他内容的下滑。FY2026 年报 MD&A。本文不会假定硬件天然亏损，也不会在没有独立现金流的情况下，把每项内容资产都估出一个精确价值。

搜索广告又是另一种生意：Bing、Edge、新闻及相关入口帮助广告主触达用户，部分流量还来自合作伙伴。流量获取成本简称 TAC，是理解变现要付出多少成本的一项线索。公司常披露剔除 TAC 的增长率；这个口径与报表广告收入金额不能直接混算。FY2026 年报关键指标定义。

这些业务的利润要分别验收：游戏看内容投入能否被销售与订阅覆盖，硬件看销量、组合和产品周期，广告看可变现流量扣除获客与服务成本后留下多少。它们对现金和分发有潜在贡献，投入责任也持续存在。

错觉二：Microsoft Cloud 就是 Azure

微软在 FY2026 披露 Microsoft Cloud 收入 214.4 十亿美元，同时披露 Azure 年收入首次超过 100 十亿美元。这是两个不同范围的数。FY2026 年报 Note 18、FY2026 Q4 官方电话会。

Microsoft Cloud 是跨产品的云收入集合，包含 Microsoft 365 商业云、Azure 及其他云服务、LinkedIn 的商业部分和 Dynamics 365。它像从报表中切出的一层云服务收入，已经包含在相应分部和产品收入中。把 Microsoft Cloud 再加到智能云或总收入上，会把同一美元算两遍。

Azure 主要提供计算、存储、网络、数据平台和 AI 等服务；客户消费增加，微软获得收入，同时需要提供相应计算资源。Microsoft 365 云服务则围绕企业工作与安全提供应用。二者都叫“云”，但客户买的东西、计价单位和每增加一美元收入需要的资源并不一样。

旧智能云分部也不是 Azure 的另一种写法。它还包含服务器产品、企业及伙伴服务等。公司披露的“Azure 及其他云服务”增长指标，在旧定义中又包含 GitHub 云、医疗云等业务。只看到“云利润率”，先要问它究竟覆盖哪一层。FY2026 年报业务及指标定义。

这直接影响同业比较。把微软智能云的分部营业利润率拿去与亚马逊云服务（AWS）或 Google Cloud 比较，然后断言 Azure 的独立利润率更高，证据不足。业务组合、费用分摊和收入边界不同；微软也没有披露可供直接使用的 Azure 独立营业利润与自由现金流。

应用、数据、开发工具和基础设施可以降低客户接入及管理的总成本。微软能否保留这部分价值，要看客户是否扩大付费、净价格是否站得住，以及服务成本是否改善。收入分类里的“云”字不能代替这几项证据。

错觉三：AI 增长会自动成为股东现金

从 FY2022 到 FY2026，现金购置固定资产由 23.886 增至 115.948 十亿美元。这解释了开篇反差的一大部分：经营产生的现金增长很快，新增资产消耗的现金增长更快。FY2026 现金资本开支占经营现金流的 63.38%，现金FCF率为 20.19%。精确计算与原始输入。

软件的复制成本很低，不等于提供软件服务的全部边际成本很低。一个许可证被多人使用，与一个代理持续调用模型、检索资料、处理长任务，承担的计算负担不同。微软可以通过收费、调度、自研技术和采购来改善经济性，但这些能力不能由“使用更多”直接推出。

一个有力反证来自 GitHub 自己。其 2026 年 4 月公告解释，短问答与长时间自主编码在旧计价模式下可能收取相同费用，推理成本上升使旧模式难以持续，因此转向按用量消耗 AI Credits（用于结算 AI 用量的额度）。产品更有用与厂商更赚钱之间，确实隔着计价和成本。GitHub 官方计费公告。

现金分析还要多走一步。融资租赁可以让微软先使用设备，再逐期付款。FY2026 的现金FCF 66.987 十亿美元没有扣除融资租赁本金支付 3.101 十亿美元，扣除后是 63.886 十亿美元；这两项指标不能混称。新增使用权资产又有非现金部分，不能在当年把它与现金付款全部重复扣一遍。FY2026 年报 Note 13。

SBC，即股权薪酬，也需要进入股东经济账。它影响费用、股数和抵消稀释所需的回购；简单因为当期没有现金支付就视为免费，不能成立。但在利润、现金代理和未来股数中重复扣减，同样会压低估值。第 06 篇会统一这些口径。

最强的正方是：今天的现金支出在建设未来多年受益的能力，不能拿扩张期现金FCF给成熟资产定终身价值。最强的反方是：如果容量不断扩张、设备不断更新，而客户支付和单位回报始终追不上，今天的“增长投入”会变成长期必须承担的成本。

验收应沿同一条链进行：合同支持需求判断，交付和使用支持收入判断，回款支持信用判断，扣除后续投入才支持资本回报判断。剩余履约义务 RPO 是尚待履约的合同金额；期限、履约与客户支付决定它何时转成收入和现金。

新 Agents and Infra 包括应用与代理、Azure、行业解决方案、生产力及服务器授权、咨询支持。它不能简单理解为原来的生产力与智能云相加：LinkedIn 被按业务线拆开，产品归属也发生变化。

具体说，GitHub 云和其他开发者云、Security Copilot 从旧 Azure 口径转入 Microsoft 365 商业云；医疗云与 Dynamics 365、LinkedIn 的人才及销售解决方案组成行业云。LinkedIn 营销方案和 Premium 订阅则进入 Devices and Consumer 的搜索与广告。后者既然包含 Premium，就不能全部当作广告。Microsoft 365 消费者云仍在 Agents and Infra，也说明新分部并非按企业与个人客户简单对半划分。官方迁移和指标定义，第 7—13、18 页。

一项业务从 Azure 口径移到 M365，不会因此多创造一美元现金，却会改变两条指标的增长基数。以后看到增速升降，先核对是否同一范围。官方这次只提供 FY2025、FY2026 的新口径历史，本文不会人工补出五年新两分部趋势。

新分类反映管理层试图把应用、代理与基础设施一起经营。它是否改善客户体验和资本配置，属于待检验的管理判断。尤其不能把 Agents and Infra 的利润叫作 Azure 利润，或因为名字里有“代理”，就将其中全部收入命名为 AI 收入。

收购来的公司与投资出去的钱，分开放

LinkedIn、GitHub、Nuance 和 Activision Blizzard 已进入微软的合并经营体系。它们可以各有品牌、客户或产品，却不能因为“像另一家公司”就再给微软加一份完整投资组合价值。先估包含其收入的经营业务，再加一份相同资产，会重复计算。FY2026 年报分部、收购与商誉附注。

OpenAI 则是投资与合作关系：微软确认相应权益法损益，同时存在模型、云服务与商业安排；它没有因这一投资把 OpenAI 的全部收入并入自身。Anthropic 的投资承诺、模型接入和云采购合作，也分别形成不同经济关系。FY2026 年报投资附注、微软与 Anthropic 合作公告。

这里需要记住三个动作：为服务收费、投入投资资金、确认投资会计损益。它们可以与同一个合作方有关，却不是同一笔钱。投资收益增加，不代表云客户已经付清账款；合作方采购承诺扩大，也不代表微软已取得相同金额收入。第 04 篇专门解释这些权利与敞口。

什么证据会让这套理解失效

把微软理解为“企业应用与计算能力共同运行的系统”，是本研究的分析框架，不能靠一个新名字得到证明。它也可能过度相信现有客户关系。

值得认真对待的反方是：客户继续保存微软文件与数据，却把最有价值的新工作交给别的代理；微软保留了后台服务，又承担了大量计算投入，应用端的收费能力反而下降。如果开放接口、其他模型和监管要求降低迁移摩擦，这条路径就更需要检验。

因此，本文会观察：基础席位与付费升级能否同时增长；使用增加有没有形成实现收入；云增长与资本强度是否逐步匹配；应收、合同与客户付款是否相互支持。如果只有业务叙事升级，而这些证据长期缺位，理解框架就必须重审。

02 客户迁不走的，究竟是什么？

信息截止：北京时间 2026-10-22。本文使用截止日前公开资料，讨论企业应用、业务流程与客户关系；具体 AI 盈利留待第 05 篇。

超过一百万家英国机构使用微软的商业软件。

2026 年 10 月 16 日，英国竞争与市场管理局 CMA 披露，微软的商业软件在英国被超过一百万家企业及公共部门机构使用，月度用户约两千万。监管机构同时提出，将微软的商业软件生态认定为具有战略市场地位，即 SMS，并就此征求意见。它关注的正是客户切换、产品捆绑和竞争者接入的困难。CMA 官方公告。

这组数字属于英国商业软件生态，不能当作全球 Microsoft 365 的付费席位。更有意思的地方在于，同一批客户的依赖，既能成为微软商业地位的证据，也能成为监管准备降低壁垒的理由。

转换成本保护的是未来一段时间的收费机会。只有客户继续使用、接受净价格并愿意扩展采购，这个机会才形成利润；如果客户留下却持续减少升级，历史依赖也可以与利润空间收缩同时发生。研究应把组织迁移成本与合同、接入规则带来的限制分开。

本篇的判断是：微软最难复制的部分，是已经进入组织日常运转的协同关系。 身份、权限、文件、业务记录、培训和采购互相连接，让单个产品的更换变成组织工程。但这套关系必须继续创造客户价值，才能成为值得长期拥有的护城河。

客户为什么持续付费

把软件迁走，要先把谁的工作安排好

设想一家有多个部门的企业，决定更换办公与协作系统。以下是用于解释机制的示意场景，不是某个客户的实地调查。

第一步似乎很简单：导出邮箱和文件，给员工开设新账号，安装新的应用。项目真正开始后，负责人还要回答另一组问题：原来的群组分别对应哪些部门？外包人员可以看哪些项目？离职员工留下的文档由谁接管？一份涉及财务与人事的表格，在新系统里应由谁编辑、谁审批？

这些问题没有被解决，数据即使全部搬过去，工作也没有完成迁移。

接下来是连接关系。某个销售团队用表格准备报价，通过邮件沟通，在协作工具里讨论，再把结果写入客户系统。财务需要在月底确认交易，法务要求保留审批记录。更换其中一个环节，可能影响后面几个环节。于是，迁移项目既要验证文件，也要验证权限、自动化、历史记录和员工是否知道新的操作方法。

这解释了组织迁移成本为什么高于个人更换应用。个人可以接受一段时间找不到旧文件；企业还要对业务中断、权限泄露和审计失败承担责任。承担这些后果的人，往往也不是决定订阅预算的人。

可以把迁移成本拆成几层：

要重建的东西客户真正担心什么微软优势的边界
身份与权限谁能访问、谁能批准、谁已经离职标准接口与更好的身份工具可能降低迁移难度
内容与历史格式、版本、会议和项目记录能否继续使用能导出不等于难以替代，文件格式本身会演进
业务流程自动化、例外处理、月底结账是否继续运行客户也可能借迁移清理旧流程
人的协作培训、外部伙伴和跨部门交接新员工与新团队未必承受同样的历史包袱
责任与采购谁验收、谁负责、合同何时到期多供应商采购与监管要求可以改变选择

这些属于本研究对业务机制的分析。微软年报披露的产品范围，已经横跨协作、身份、安全、设备管理和企业应用，但没有公开一个适用于所有客户的“迁移成本金额”。本文不会把示意场景包装成经过测量的客户平均成本。FY2026 年报业务与竞争说明。

这里还有一个重要区别：以前花过的钱，并不都能成为未来留下的理由。历史培训费用已经发生，属于沉没成本；真正影响今天选择的，是未来更换所需的新投入、过渡风险，以及更换后能够得到的收益。把客户过去的全部投入都算成护城河，会夸大微软的优势。

Microsoft 365：文件只是看得见的一层

许多人从 Word、Excel 和 PowerPoint 理解办公软件。企业购买 Microsoft 365 时，采购对象已经扩展到邮件、协作、身份、设备、安全和合规等能力。

FY2026 年报的 Microsoft 365 商业云定义，包含商业套件、企业移动与安全、商业 Windows 的云部分、Exchange、SharePoint、Teams、安全与合规，以及 Copilot 等。不同套餐和部署方式覆盖范围不同，不能把这些名称理解成每位客户都购买了同一套完整组合。FY2026 年报 Productivity and Business Processes。

对客户而言，有价值的集成首先表现为少做一些重复工作。组织不希望在每个系统里分别维护一遍员工状态、设备要求和访问权限；也不希望安全团队看到的使用者，与业务系统里的负责人无法对应。共同的管理体系可以减少协调和出错，这种价值足以支撑客户主动选择更完整的套件。

第二层价值来自协作对象已经在那里。文件不只是一份可以打开的内容，还与编辑者、版本、评论、共享范围和业务决定相关。会议也不只是一段录音，它可能属于某个项目，并与待办事项、客户交流和后续审批相连。迁移要保存的是工作的连续性。

第三层是组织已经掌握了如何使用这套系统。管理员知道怎样处理例外，伙伴知道怎样部署，员工知道去哪里找资料。熟悉的工具未必功能最强，却可能让企业以较小的协调成本完成任务。这是一种组织经验优势，随着人员和流程变化也需要持续维护。

但有价值的集成与限制选择，应当分别评估。

如果客户自主选择多个产品，是因为组合后更可靠、管理更简单，微软创造了可以反复收费的价值。如果客户主要因为合同差价、技术接入限制或不方便单独采购而留下，优势就更依赖规则。两者在同一笔套件销售中可能同时存在，不能只看成交结果就判定客户认可了全部组件。

选择空间扩大，提供了检验集成价值的场景：产品可以单独采购、外部工具更容易接入后，客户是否仍选择微软组合，续费与净实现收入是否保持。若基础许可续约而升级预算持续流失，应下调对套件收费能力的判断。

订阅重复，不等于每次提价都成功

Microsoft 365 商业收入的驱动，微软自己概括为安装基础扩张、平均每用户收入提升，以及本地授权向订阅迁移。订阅使收入具有重复性，也让客户定期获得重新谈判和调整产品组合的机会。FY2026 年报商业产品说明。

平均每用户收入提高，可以来自同一服务提价，也可以来自客户选择更高套餐、购买更多能力或客户组合变化。只有把有效席位、套餐、折扣、续约和服务成本一起看，才能判断定价权。

假如企业升级了安全套餐，同时取消几个外部工具，微软收入增加可能有真实客户价值支撑。如果客户只是被迫买入更多很少使用的组件，账面增长也可能伴随日后缩减预算的动力。公开报表没有逐批客户的完整使用和续约数据，这一判断必须保留缺口。

本篇因此只把分发和升级能力列为优势。Copilot、E7 和消费计费最终能增加多少利润，需要第 05 篇单独验收，不能提前记在护城河的收益里。

Dynamics：迁移的是业务如何被记录

Dynamics 的嵌入方式与办公软件不同。它涉及客户关系管理、企业资源计划、财务和供应链等业务；Power Apps、Power Automate 等工具又让组织能够在既有应用上搭建和自动化流程。微软披露，其收入与获得许可的用户、消费的应用、客单价及向 Dynamics 365 的迁移有关。FY2026 年报 Dynamics 说明。

仍用一个示意场景来理解。客户系统里的一条记录，可能对应某个客户、销售机会、交付承诺和回款安排。如果不同部门对“已完成”有不同定义，企业就需要在系统中固化规则。业务运行越久，积累的往往是标准流程和大量例外处理。

替换此类系统，需要先弄清组织究竟在做什么。哪个字段用于收入确认，哪个用于销售预测，哪次人工修改属于合理例外，都需要业务部门参与。复杂性来自企业自身，供应商通过服务这些复杂性建立关系。

这类迁移成本也会保护 Salesforce、其他企业应用厂商和实施伙伴，微软没有独占。一个已经深度使用另一套客户关系系统的企业，不会仅因为采购了 Microsoft 365，就自然把核心业务记录搬到 Dynamics。

微软的机会在于连接现有办公、数据和业务流程，减少客户重新集成的工作。对手也可以依靠更深入的行业功能、更成熟的业务流程、独立伙伴以及更好的服务体验保住客户。竞争要落到具体项目：谁能更可靠地支持企业运营，谁的整体实施和维护成本更合适。

集成还有反方向的负担。定制越多，升级与维护可能越复杂；客户也可能发现，原来的流程需要重做。一次重大业务重组、并购或技术迁移，都可能让原先很难推动的替换变得值得。

因此，“进入核心流程”提供了持续收费的基础，却没有免除产品更新和服务责任。把所有定制都称为永久黏性，会漏掉客户主动简化系统的机会。

不同护城河的边界

LinkedIn：有网络效应，也有不同的买方

LinkedIn 与办公套件的护城河来源不同。它连接职业人士，并通过人才、营销、Premium 订阅和销售解决方案收费。人才与销售客户看重寻找合适对象的能力，营销客户关心触达与转化，个人订阅者又有自己的职业与使用需求。FY2026 年报 LinkedIn 业务说明。

这里存在局部网络效应：更多真实、相关且持续更新的职业信息，可以提高招聘与寻找商业联系的价值；企业更积极地使用，也可能吸引更多职业人士参与。这个循环是否成立，要看匹配质量和参与意愿，不能只看注册人数。

新增加一批长期不更新资料、也不参与互动的账号，未必给招聘者增加相同价值。更多营销内容也可能消耗用户耐心。网络规模与网络质量之间，需要平台持续平衡。

LinkedIn 的壁垒因此带有行业和地域差异。某个职业群体在平台上足够密集，会对招聘客户有价值；另一个群体可能主要通过本地招聘渠道、行业圈子或其他方式交流。同一个平台里的不同客户，也可以同时使用多个服务。

更不能把 LinkedIn 的网络效应自动移植到整个 Microsoft 365。一个企业里更多同事使用共同工具，会减少协作摩擦；这与全球职业网络吸引更多参与者，作用范围和收费逻辑都不同。微软的规模优势、组织转换成本与局部网络效应，应当各自找到证据。

FY2027 的重列又提醒我们，要按业务线看 LinkedIn：人才与销售方案进入行业云，营销方案和 Premium 进入搜索与广告。分类改变没有创造新的网络，也没有增加收入，只是让原来一个品牌里的不同经济关系更加可见。官方重列材料第 7—13、18 页。

分销的优势，在客户决定试用之前就开始了

微软的销售并不只靠产品页面。它通过直接销售和广泛的伙伴网络，为不同规模客户提供采购、部署、管理和支持服务。年报把伙伴体系列为间接销售的重要渠道。FY2026 年报 Distribution, Sales, and Marketing。

一个新功能进入已有企业合同，可以减少寻找预算负责人、评估供应商和安排部署的工作。管理员熟悉现有管理工具，实施伙伴也已有对应能力，这些条件会让微软更容易获得试用机会。

机会本身有经济价值。竞争者即使在某个功能上更出色，也需要解释接入、维护、数据处理和责任分工；客户采购的还包括供应商能否稳定提供服务。新厂商未必有足够时间和客户逐一完成这些证明。

然而，进入采购清单与赢得持续付费之间仍有距离。免费附带、试用、套餐分配和主动购买，代表不同强度的需求证据。销售团队能把产品交到客户手上，使用者仍要判断它是否值得进入日常工作。

伙伴也有自己的激励。它们可能从既有系统的实施与维护获得收入，也可能从帮助客户转向其他工具获得机会。渠道不是永久只替一家厂商服务的资产。产品越复杂，服务生态越重要；复杂性过高时，服务费用又可能成为客户寻找更简单方案的原因。

分发体系减少了接触采购人、通过部署评估和培训管理员的工作，使新品更容易进入试用。完成采购之后，仍要靠产品效果、续费和净收费覆盖服务成本；试用机会不能直接记作利润壁垒。

对手可以从一块有价值的工作开始

微软面对的竞争，往往发生在单个工作环节。企业应用年报列出的竞争范围很广，要理解这种竞争，需要观察对手从哪里进入，以及客户需要替换多大范围。

Google Workspace 所代表的浏览器协作路线，可以从新的团队和新的工作习惯开始。对于尚未积累大量本地文件、旧流程和定制的组织，历史迁移负担较轻。一个竞争者若能先成为新团队的共同工作环境，就可能避开最难的整套替换。

这是一条竞争机制，不能据此推断某类客户已经整体转向 Google。微软也持续提供云服务与跨设备体验。决定结果的，是具体客户的协作需求、兼容要求、管理与价格，而不是产品出现在哪个年代。

独立安全供应商可以从另一个入口进入。客户可能愿意为更好的检测、响应或风险隔离保留独立工具，甚至愿意承担多供应商管理成本。集中采购可以减少协调，也可能增加对同一供应商的依赖。两种选择各有需要解决的问题。

微软在端点、身份及云安全面对众多专业供应商竞争，年报也承认这一点。评价它的套件优势，需要比较实际安全效果和管理负担；不能因为客户已经支付套件费用，就认定外部安全工具没有生存空间。FY2026 年报各业务竞争说明。

Salesforce 等业务应用厂商的路径，则是守住客户关系和业务记录，再与办公、数据及其他工具连接。客户可以同时使用微软办公套件和另一家厂商的业务系统。跨产品协同有利于微软交叉销售，却不意味着每个客户都要把所有系统交给它。

这些路径共同说明，竞争者不必先复制整个微软，才能取走一部分高价值工作。它可以在某个工作环节建立优势，通过接口与微软并存，再逐步扩大自己的客户关系。

对微软而言，这也是一种可接受的经营方式。它可以从基础服务、身份或计算中继续收费。投资者需要验收的是，留下的业务价值与利润是否足够，而不能仅凭“客户仍然使用微软”就宣告应用端竞争没有影响。

最强反方：关系怎样失效

安全是护城河的一部分，也是一项持续负债

企业愿意把工作放在一个系统里，需要相信服务商能够保护它，并在出现问题后及时告知和纠正。部署范围越广，责任越重。

2024 年 6 月提交美国国会的书面证词中，微软总裁 Brad Smith 接受了网络安全审查委员会（CSRB）所指出的微软问题责任，并表示将处理适用于微软的建议。随后官方听证回顾记录了议员对公开说明迟迟未纠正的追问。Smith 书面证词第 1 页、国会听证回顾。

本研究未取得原始 CSRB 报告全文，因此不把二次转述写成已经逐页核实的调查结论。上述证词和听证材料，已经足以让“客户留下就证明完全信任微软”的推论受到挑战。

客户可能同时面对两个事实：现有供应商发生过严重问题，而立刻更换整套系统又会带来新的风险。短期续约可以体现连续运营的需要，不能单独证明服务质量已恢复。

微软通过 Secure Future Initiative，即 SFI，披露安全整改进展。后续材料可以用于观察投入和控制改进，但属于公司自述，不等同于独立验收。第 07 篇会进一步检验承担责任、激励和整改闭环。微软 SFI 进展页面。

从护城河角度，重要的是持续结果：同类问题是否反复发生，客户能否获得足够信息，整改标准是否稳定，以及风险是否改变采购安排。依赖越深，事故可能影响的业务范围越大；集中化带来的管理便利，需要与这种集中风险一起估价。

因此，安全优势需要不断再投入才能维持。它不应被当成已有客户数量自然附送的一项永久资产。

监管降低的，可能是护城河中最容易被误认的一层

CMA 的 2026 年 10 月意见指出，微软在其调查的五类商业软件活动中有较强地位，客户切换障碍和商业集成优势限制了其他供应商的竞争。它拟继续研究 Copilot 竞争、安全捆绑和跨云许可等问题。截至本次截止日，SMS 认定仍属临时意见，最终法定期限在 2027 年 2 月；SMS 本身也不推定违法。CMA 2026-10-16 公告。

此前，微软在 2025 年公布 Teams 相关承诺的实施说明，包括提供含与不含 Teams 的套件、相应价差、客户切换与折扣保障，以及数据导出和互操作接口。其中许可和定价调整自 2025 年 11 月 1 日起实施；互操作、导出及地区与合同保障按各自条款适用。微软 2025-09-12 实施说明。

它们为投资者提供了一种检验方法：让对手更容易接近客户，再看微软还能保留什么。

如果客户可以更容易地导出数据、选择单独产品、使用外部协作工具，微软仍因质量、管理和总成本赢得选择，优势的含金量更高。如果收费主要依赖外部产品难以接入，降低限制就可能改变利润分配。

互操作也不会自动消除所有迁移成本。一个接口开放了，客户仍需要映射权限、验证记录、培训员工和安排责任。技术障碍降低后，组织问题依然存在；这些问题又可能随着工具和服务改善而逐渐变轻。

本研究没有把监管视为必然摧毁微软的力量，也没有把微软的市场地位写成长期收费的保证。更合适的观察，是区分客户主动购买的协同价值与规则维持的绑定，并跟踪后者变化后真实的续约和采购结果。

当模型能够替换，哪一层关系还能留下

微软与 OpenAI 在 2026 年 4 月修订合作，模型与产品知识产权许可改为非独占。10 月 21 日，OpenAI 又宣布其模型和 Codex 工作流将进入 Google Cloud。投资者不能继续用早期的排他性描述解释截止日的竞争格局。微软合作修订公告、OpenAI 2026-10-21 公告。

自研和开放模型也让“只有一家能够取得智能”越来越难成为稳固假设。模型可替换，对微软有两种方向相反的影响。

一方面，微软可以选择更合适的模型，减少单一供应商依赖。企业仍需要身份、权限、上下文、安全与部署能力，多模型的管理需求可能扩大这些服务的价值。

另一方面，竞争者同样可能调用强模型。客户还可以把数据保留在原系统，通过其他入口完成工作。这样一来，微软可能继续提供后台服务，而最有价值的交互和新增预算流向别处。

这里需要尤其小心“企业数据优势”的措辞。微软承载、连接并获得授权处理客户工作数据，不意味着它拥有这些数据。它能够争取的回报，来自帮助客户安全有效地使用数据，而不是把客户的信息视为自己的永久产权。

2026 年 9 月，Amy Hood 在公开会议上强调完整技术栈、分销体系、企业信任和客户保有自身知识产权的作用。这是管理层提出的竞争逻辑，本文用客户选择和经济结果检验它。Hood 官方会议记录。

AI 的最终增量利润不在本篇展开。对护城河而言，当前最关键的问题是：模型供应更开放后，微软能否继续成为组织愿意付费的管理与工作层。

如果给挑战者一千亿美元，能复制什么

把一千亿美元交给一个假想挑战者，是思维实验，不是预测某家公司的投资预算。

它可以购买人才、开发工具、部署模型、补贴客户，并建设伙伴体系。它也可以集中攻下一类客户或一种工作，从而避免复制微软全部业务。

它比较难在短期获得的，是大量组织已经建立的权限安排、工作习惯、业务例外、合作伙伴经验和采购信任。买到技术与形成这些关系之间，存在时间和执行要求。

但挑战者有一个优势：可以从新增工作开始。新团队、新业务和新交互方式，没有那么多旧系统要照顾。未来五年或十年的竞争，很可能取决于谁承接新增工作，以及老客户在何种时点愿意重做流程。这是情景判断，不是对未来份额的承诺。

微软的防守也不能停在让旧系统更难离开。它需要让新增产品值得采用，让现有系统更容易与外部工具共同工作，并在扩大使用的同时保持质量和合理成本。客户因服务更有价值而增加依赖，与客户因障碍而延迟退出，对长期回报的含义不同。

最强的反方可以这样表述：微软守住了历史数据和基础服务，却失去了新增工作的入口；监管减少绑定，竞争者带走高价值应用，客户继续续约但减少升级。公司仍然庞大，投资者原来预期的收费空间却缩小了。

公开资料尚不能判断这条路径会以多大范围发生，也不支持为它配置概率。可以把失效过程写成可复核的顺序：新增工作先被外部入口承接，客户随后减少升级或谈判净价格，微软仍承担后台与计算成本。若这些现象持续共同出现，收入规模的稳定就不足以支持原来的应用利润预期。

03 Azure 多卖一美元，先要投多少钱？

信息截止：北京时间 2026-10-22。财务以美元计；微软财年截至 6 月 30 日，同行季度按相同日历期间对齐。本文检验需求怎样经过交付、使用和资本投入，变成股东可以验收的回报。

Azure 一年多卖了 293.28 亿美元。

微软 2026 年 9 月公布的新口径，把 Azure 的 FY2025 收入重列为 726.10 亿美元，FY2026 为 1,019.38 亿美元，全年增长约 40%。与此同时，微软 FY2026 全公司现金购置物业及设备达到 1,159.48 亿美元，另有 246.08 亿美元新增融资租赁使用权资产。官方重列材料第 17—18 页、FY2026 现金流表与租赁附注。

收入和投入一起变大，尚不能回答标题里的问题。后两项属于整个微软，服务 Azure、第一方应用、研发及其他需要基础设施的业务。把它们全部除以 Azure 新增收入，会得到一个看似精确、归属却不成立的“每增收一美元要投多少钱”。

拆开这门生意，收入主要受收费使用量、折后有效单价和服务组合推动；营业利润还取决于设备、电力、网络、维护与调度成本。股东能拿到的现金再受投产时滞、资产更新和经营资金占用约束。因此，需求、利润与现金要沿同一批资源分别验收。

研究截止日的披露指向一项供给约束：能在客户需要的地点和时间投入服务的容量。客户下单后，电力、网络、设备和系统必须一起到位；资源交付后，还要取得足够的付费使用，并在更新前回收资本。需求旺盛只覆盖这条链的起点。

需求怎样形成收费

先把这一千亿美元的边界画清楚

这次披露比“Azure 增长很快”多给了投资者一项重要信息：一个可以识别的收入金额。但使用它之前，要先理解微软改了什么。

FY2027 的新定义将 GitHub 云及部分开发者云服务、安全 Copilot 移入 Microsoft 365 商业云，将医疗与生命科学云移入行业方案云。重列后的 Azure 更集中于云及 AI 消费型平台、基础设施和虚拟桌面等服务。FY2026 新口径第四季度收入为 294.17 亿美元，同比增长约 42%；早先“Azure 及其他云服务”的同季增长为 43%，两者有不同边界。重列材料第 7、13、17—18 页。

因此，本篇用 726.10 亿和 1,019.38 亿美元比较两个完整财年。更早的旧指标可以解释历史变化，不能在缺乏桥接时直接接成长序列。这里的约 40% 是公司披露的四舍五入增长，不是承诺未来按同样速度延续。

利润的边界仍然比收入模糊。旧 Intelligent Cloud 包含 Azure、服务器本地产品及企业服务等；新 Agents and Infra 又汇合了 Microsoft 365、行业方案、授权和支持。它们的营业利润都不能直接改名为“Azure 营业利润”。微软也未单独披露 Azure 的完整现金流与投入资本。

披露支持收入与收费机制的研究，也支持从合并及分部报表观察成本压力；Azure 独立现金流和投入资本仍然缺失。后文使用的合并投入只能检验资本负担，不能计算 Azure 每增收一美元的精确资本成本或独立回报率。

客户购买的是可以持续运行的工作

把传统云理解为“把服务器搬到别人机房”，只能解释一部分价值。

一家企业除了计算，还需要存储、数据库、网络、开发工具、安全与运维支持。不同工作对可靠性、响应速度、数据位置和预算都有要求。云服务商把这些需要组织成可采购、可部署、可持续维护的服务，客户便可以按自己的业务节奏使用。

微软年报说明，云服务既有订阅，也有消费计费。订阅收入通常随服务期确认，消费型服务按照客户使用的资源确认收入。这与客户签下合同的金额、当月收到的发票和实际支付的现金，是不同的观察点。FY2026 Note 1，Revenue Recognition。

从经营上看，收入可以拆成不同服务的有效单价与收费使用量。所谓有效单价，需要包含合同折扣、资源类型、地区、服务等级和客户组合；它不同于网站上的某个挂牌价格。用量也不是单一的“客户数”：原有客户增加业务、新客户迁入、客户把工作做得更省资源，都可能同时发生。

这给重复收费提供了基础。一项已经进入日常运营的系统，往往持续需要计算和数据服务。客户的业务增长、数据积累或新增应用，可以扩大消费；客户优化程序、清理闲置资源或调整架构，也可以减少消费。

所以，持续使用不等于供应商可以轻松持续提价。微软要争取的是客户完成一项工作后的总收益。客户若认为相同结果可以更低成本取得，就有动力优化、谈判或分散采购。云服务商的价值，需要通过可靠性、工具、效率和整体维护成本不断补充。

第 02 篇讨论的组织转换成本，能让微软更容易获得业务和维持续约。它不能免除 Azure 在每一类工作负载上接受成本与服务检验。

训练和推理，让“多用一点”有了不同含义

AI 又把消费的结构变得更复杂。至少要把传统云工作、模型训练和模型推理分开理解。

传统工作负载包括企业应用、数据库、存储与分析等。客户可以因业务扩张增加需求，也可能在迁移完成后集中优化资源。稳定运行的业务有助于供应商规划容量，但不能假设其使用一直单向增加。

训练是在数据和计算资源上投入，形成或更新模型能力。某个大型训练项目可能集中消耗大量资源，交付与排期也会影响收入出现的季度。项目完成之后，客户还会否继续训练、使用哪种硬件、选择哪家供应商，取决于后续效果和预算。一次大规模任务不能自动视为同额永续订阅。

推理则是把已经建立的模型用于回答、生成和执行任务。它可能随着应用进入日常工作而反复发生，也伴随持续的服务成本。更多用户、更长任务、更复杂的模型调用，可以增加消费；模型变小、计算效率提高、缓存与调度改善，又可能减少完成相同任务需要的资源。

上述是解释机制的分类，不是微软披露的三套独立损益表。公开资料不足以把 Azure 全部收入和利润精确分给三者，也不支持给每类工作填入一个统一毛利率。

投资者真正需要分清的是，效率提升以后，谁得到收益。如果客户支出下降而新任务迅速增加，总消费仍可能扩大；如果客户节省下来的资源没有被新增需求补上，服务商就可能面对用量或单价压力。更好的技术能够扩大客户价值，也可能加快旧硬件和旧收费方式的调整。

由此可见，“推理需求会长期增长”还缺少资本回报的一半答案。最终需要检验的是：实际收费是否覆盖服务、维护与资产更新，并在竞争中留下合理回报。任务数量、生成内容或模型调用的增长，可以帮助解释需求，不能代替这项检验。

从合同到交付和回款

合同、收入和收款，需要分别追踪

微软 FY2026 年末商业剩余履约义务，即商业 RPO，为 6,780 亿美元，平均期限约 2.3 年，约 30% 预计在未来十二个月确认。RPO 包含递延收入及将来开票、确认的部分，说明已有合同对应的未来业务，但不是当期收入，也不是全部已经收到的现金。FY2026 Note 12。

理解一笔云业务，可以分别问四个问题：客户承诺买什么，微软能否交付对应容量，服务何时达到收入确认条件，以及钱何时收回。四者没有固定的先后顺序；预付款可以早于交付，部分收入也可以早于最终收款。

每个问题都可能改变投资判断。合同签订后容量迟迟不上线，需求暂时无法变成服务。容量上线却用量不足，已投入资产仍要承担成本。收入确认后收款变慢，经营规模扩大也可能占用更多资金。客户提前付款，则可能改善现金周转，但仍留下未来提供服务的义务。

Q4 电话会披露，商业 RPO 同比增长 84%，剔除 OpenAI 后增长 25%；该季度商业 RPO 的环比增长全部来自前沿模型公司之外的客户。这两组信息需要一起阅读：大合同影响总增速，而新增合同又不只来自模型公司。FY2026 Q4 电话会商业结果段。

这仍没有给出统一的客户信用结论。不同客户的资金来源、合同期限、用量安排与付款能力各异。一个客户既是合作伙伴又是重要买方时，应该特别检查其支付和持续投入能力；相关投资与合同权利见第 04 篇。

本篇只保留一条纪律：合同积压、已交付使用、已确认收入和实际收款分别记录。追踪它们之间的转化，比把 RPO 增长直接翻译成下一年的利润增长更有用。

一栋建成的机房，还需要成为可以交付的服务

云容量不是在订购设备时就完成了。

土地、建设、电力、网络、设备、冷却及软件系统需要共同到位，才有可能支持客户工作。微软 FY2026 风险因素明确列出电力可得性、接入延迟、许可、建设人员、服务器和关键部件等限制，并承认容量不足与投入过量都可能带来损害。FY2026 10-K，Risk Factors。

这使“供不应求”成为有边界的好消息。它说明在现有条件下仍有未满足需求，也意味着微软暂时不能为其中一部分需求收费。投资者还要知道，缺口出在哪里、能否按期补上，以及客户愿意等待多久。

Q4 管理层说，Azure 需求继续超过可用容量，增长好于预期的一部分原因，是 中央处理器（CPU）与图形处理器（GPU）设备效率提升及新容量更早交付；新增季度容量很快被使用并变现。这是有价值的经营证据，因为它把效率、上线和收入联系起来，但仍属于公司对该季度的解释。Q4 电话会 Intelligent Cloud 段。

从股东角度，更重要的是这条链能否反复运转。一次提前交付可以改善当季收入；持续降低从付款、安装到可收费之间的时间，才可能改善资本周转。

反面情景也应写得具体。供应限制缓解后，客户可能重新谈价，把部分任务交给其他服务商，或发现原先准备的需求不再有同等价值。先前因缺货而难以观察的闲置问题，可能在新增容量上线后出现。因此，当前交付出来的容量迅速被使用，不足以证明未来每一批新增资产都会取得相同回报。

利用率背后，是把不同需求组织在一起的能力

同样一批设备，能够持续完成多少有价值的客户工作，决定了成本被多少收入分担。

不能只拿一个平均使用率说明问题。客户需求有不同的地区、时间、可靠性和任务特征，某处闲置的设备未必可以立即满足另一处缺口。投入已经发生以后，调度、软件、维护和设备组合，仍会影响能提供多少可收费服务。

微软年报将云规模经济归纳为资源采购部署、汇集不同需求提高使用效率，以及多租户减少维护成本等方面。真正需要证明的，是这些优势能否抵销复杂度、供给成本和客户折扣，而不只是拥有很多机房。FY2026 年报 Business，Microsoft Cloud。

Q4 面对超建风险的提问，Amy Hood 给出的最强辩护，是新增投入更多转向交付周期相对短的 CPU 与 GPU；当需求变化时，可以放慢采购和安装。同时，多地区、多行业、多类客户及自有应用，可以帮助微软调整容量使用。她也提到部分土地和建设投入的时点可以改变。Q4 电话会 Bernstein 问答。

多样客户和任务给管理层提供了调整资源用途的机会，延后设备选择则可能缩短错误采购的暴露时间。是否真的降低损失，要看需求变化后资产能否转用、采购能否延后，以及对应付款责任是否一并改变。

但灵活性需要按资产和合同分别验收。已经承诺的租赁、电力、建设与采购，能否减少或延期，条款并不相同。放慢下一批 GPU 采购，也不会自动取消已经开始计费的机房和设备。管理层所说的可调度和可延后，是需要通过后续现金及交付结果检验的能力。

Azure 与 Copilot，也在争取同一批新增资源

微软自身的产品组合，让资本配置比“Azure 订单多就把设备全给 Azure”复杂得多。

在 Q3 电话会中，管理层明确表示，要在 Azure、第一方应用、研发，以及到期服务器替换等用途之间平衡新增供给。Q4 讨论容量灵活性时，又强调自有应用业务同样会使用建设中的资源。Q3 容量与展望段、Q4 Bernstein 问答。

这种组合既是优势，也是投资者容易重复计算的地方。

一项容量用于外部 Azure 客户，可能形成消费收入；用于微软自己的应用，回报需要从应用收费、客户留存或服务成本中体现；用于研发，则可能先形成费用，效果在之后的产品中才出现。同一资源有不同的使用者，并不意味着可以把每一种潜在收入全部算进一次资本投入的回报。

反过来，只因某项支出没有立即形成 Azure 收入，也不能认定它没有经济价值。一次让自有应用更可靠、更便宜的投入，可能改善整个微软的收益。需要检验的是实际结果，而不是替每笔研发提前计入未来成功。

公司层面的管理目标，是在不同用途间配置有限资源，使整体回报更好。公开报表却没有提供统一的、可供外部投资者逐笔核对的容量转移价格和独立现金流。新 Agents and Infra 把相互关联的应用与基础设施放到一起，正体现这种经营思路；它同时要求投资者更谨慎地解读单品盈利。

这一点也限定了本篇的结论。Azure 收入增速可以告诉我们外部平台的需求和交付变化，却不能完整衡量全部微软 AI 投入的回报。Copilot 怎样收费、使用成本怎样回收，第 05 篇另行展开。

1900 亿变成 1750 亿，先变的是计量边界

2026 年 4 月，微软预计自然年 2026 资本开支约 1,900 亿美元，其中包含更高部件价格的影响。7 月 Q4 电话会将相关预期改为约 1,750 亿美元，必须连同原因一起看。Q3 资本开支展望、Q4 资产寿命与展望说明。

微软从 FY2027 起，将数据中心及办公建筑的估计使用寿命由十五年延至二十五年。管理层称，FY2027 营业利润受益很小，更大的影响，是未来更多数据中心租赁将从融资租赁转为经营租赁。

公司的 CapEx 口径包含融资租赁，不包含经营租赁。分类变了，所列资本开支金额便会改变。管理层明确表示，除这一寿命及分类影响外，自然年 2026 的投入预期没有变化。不能把金额减少直接解释为经济投入退潮，更不能把二十五年建筑寿命写成 GPU 的使用寿命。

这种变化不会让长期使用资源的付款责任消失。融资租赁的资产取得、负债和本金支付，与经营租赁费用和经营现金流支付，有不同报表呈现；跨期比较需要重新连接它们。

FY2026 年末，微软尚未开始的租赁安排为 3,291 亿美元，主要与数据中心有关，部分还附有条件。它们预计在之后数年开始，不能全部当成下一年债务；也不能因为尚未开始就视为没有约束。FY2026 Note 13。

这里最容易犯的分析错误，是拿资本开支表里更小的数字，提前庆祝现金转化改善。真正的改善应该出现在资源交付、客户付款、经营租赁支付、设备更新和其他资本占用共同形成的结果中。

最强的两种解释，争论的其实是现金转化

最有力的乐观解释是，微软正在支付建立下一阶段供给的前期成本。云和 AI 客户扩大需求，机房与设备投入先到，容量上线以后逐步产生收入；软件调度、模型组合与芯片效率改善，又让已有资产完成更多任务。广泛客户和第一方应用为容量提供多种去处，规模最终可以转化为较好的周转和回报。

这套解释获得了部分经营证据支持：新口径 Azure 年收入已经超过一千亿美元，Q4 增长仍强，管理层也披露了容量更早变现和效率改善。它值得认真对待，不能因为当年现金支出大就直接判定投入失败。

最强的反方则承认这些需求真实存在，却追问取得这些需求的代价。客户越多，可能越需要昂贵设备、电力和租赁；效率进步也可能被竞争价格或客户节省吸收。收入增长之后，下一批更新投资仍然很大，现金回报就可能长期达不到原先按软件业务形成的预期。

更困难的情景，是合同刚性与客户预算转弱同时出现。客户降低用量、重新议价或延后新任务，已经承诺的资源支出却下降得更慢。此时，强订单历史并不能自动保护新资本的回报。

最容易看错的环节是把供不应求当作资本回报保证：短缺时客户愿意等待，容量充分后却可能重新议价。正方需要证明投产更快、付费使用和收款持续跟上，且更新资本没有吞掉增量现金；反方则需要证明收入增长必须由不断增加的资本责任支撑。单看扩张期支出高点，也不足以判定失败。

未来五年，把判断落到可以重审的证据上

本篇不把约 40% 的年增长延伸成未来五年的承诺。更有用的做法，是列明不同路径怎样被识别。

如果新增容量持续按期交付、客户使用和付款跟上，效率提升又逐步减轻合并资本占用，那么“前期投入最终形成回报”的解释会增强。公司层面的现金改善仍需结合其他业务，不能一见改善就全部归给 Azure。

如果收入继续增长，资本和租赁支付也必须以相近力度持续增加，投资者需要降低对轻松现金释放的期待。增长可以有价值，但需要更多钱维持的增长，应采用不同的回报要求。

如果容量更充分后增长明显转弱，同时合同转化、收款或价格出现压力，就应重审原有需求质量。若收入很好而设备更新、预付款、应付款和租赁承诺持续积累，也应检查是否只是把资金负担推迟到下一阶段。

可实际跟踪的证据包括新口径收入、管理层对交付和需求的解释、RPO期限与客户结构、应收与收款变化，以及合并资本和租赁现金流。独立 Azure 利用率、单品利润和投入资本仍存在披露缺口；这些缺口需要持续记下，不能用一个分部平均值悄悄补上。

因此，对标题最诚实的回答是：公开资料还不能给 Azure 每新增一美元收入配上一个可靠的独立投资金额。它已经证明自己能吸引很大的付费需求；下一项需要证明的，是在持续提供这些服务、更新资产和履行长期承诺之后，微软还能留下多少回报。这个问题，必须让后续的交付与现金来回答。

04 OpenAI：微软的一项资产，还是一项依赖？

241 亿美元收入，60 亿美元应收。

这是微软 FY2026 年报披露的两项 OpenAI 关联交易数据：全年商业安排收入 241 亿美元，包含收入分成；截至 2026 年 6 月 30 日，应收 OpenAI 款项为 60 亿美元。微软同时披露，所持投资约代表 OpenAI 按转换口径计算的 25% 权益，并按权益法核算。FY2026 年报 Note 1。

同一家公司在微软账上承担不同角色：作为客户，它要为服务付款；作为技术伙伴，它提供有期限和条件的权利；作为被投企业，它影响投资价值及后续资金需求。研究需要为各条关系分别追踪现金和义务，再看风险是否集中在同一资金来源上。

只看投资，会漏掉服务收入和客户信用；只看客户，会漏掉模型许可和股权风险；只看合作，又容易把多年采购承诺当成已经收到的钱。

本篇围绕一个问题展开：微软从合作中取得的权利，是否足以补偿它承担的资金、履约和客户敞口？ 答案需要逐条查账，不能由一家被投企业的新融资估值替代。

服务收入、收款、投资收益与新增投入可以朝不同方向变化。收入增长可能先增加应收，投资收益可能来自资本结构变化，大额采购承诺又可能要求微软先形成供给。只有把这几条现金路径接起来，才能判断合作增加了多少可支配回报。

公开信息足以确认这些关系存在，却没有公开完整私人合同。本研究不会用推测填上分成比例、总额上限、违约补偿或证券优先权。未知条款的处理，会直接影响对资产价值与风险的判断。

更重要的是，同一笔经济利益只能计入一次。如果已经把云服务和分成现金流放进经营预测，另给投资加值时，就要检查估值是否再次包含了同一项商业权利。只要标题分别叫“云”“AI”“投资组合”，并不能防止重复计算。

先改掉旧比例，再讨论值多少钱

有关微软与 OpenAI 的叙事，经常沿用旧的“49%持股”说法。本次研究不把这个数字当作截止日可核验权益，也不据此推断微软控制 OpenAI。未公开完整历史经济分配安排时，一个百分比可能混合投资回收、利润分配与转换权益等不同含义。

能够采用的公开时间线更清楚。

2025 年 10 月 28 日，双方公告称，OpenAI 重资本化后，微软投资按转换及摊薄口径计算约占 27%，当次公告给出约 1,350 亿美元价值。公告的分母包括员工、投资者和 OpenAI Foundation 等各类所有者。双方 2025-10-28 公告。

到微软 FY2026 年报，披露的是约 25% 的 as-converted 权益。它属于 2026 年 6 月末的财务披露。27% 与 25% 对应不同时间与资本结构，不能挑一个较大的比例贯穿全篇。

“按转换口径”也需要保留。它说明权益是在特定转换假设下计算，不能自动当成与一家上市公司普通股完全相同的投票权、清偿权和可出售股份。微软采用权益法，而没有把 OpenAI 全部资产、负债、收入和成本并入自身报表，也说明不能把投资比例直接解释为控制权。FY2026 年报投资政策与 OpenAI 段落。

1,350 亿美元同样有日期。它是 2025 年重资本化公告中的投资价值描述，不是微软当时立即可以提取的现金，也不是本次截止日已经验证的出售净收入。

计算“融资估值乘微软比例”很容易，真正困难的部分在乘法之外：证券权利是否相同，转换和退出有什么限制，未来融资会怎样稀释，还需要多少资金。把这些条件省掉，计算结果就比证据更精确了。

“独家伙伴”已经经历了重要修订

股权比例只是关系的一部分。对微软经营更直接的影响，可能来自它能使用什么技术、通过什么渠道销售，以及合作方必须在哪里消费。

2026 年修订保留了微软作为 OpenAI 主要云伙伴的地位，并描述产品先在 Azure 推出的安排；公告同时保留与微软支持所需能力有关的例外。完整适用条件不能由一段公开说明替代，也不能把主要云伙伴理解为所有产品只能由 Azure 提供。

微软的模型与产品 IP 许可持续到 2032 年，但改为非独占。分成方面，微软不再向 OpenAI 支付收入分成；OpenAI 向微软的分成则延续至 2030 年，不再由技术进展决定期限，同时受总额上限约束。具体比例与上限未公开。

这些条款不能只按“微软让出了独家”理解。取消一边的支付，可能改善某些产品经济；保留许可，有助于业务连续性；更灵活的合作，又可能减少双方相互限制的成本。

同样不能只按“伙伴关系更稳固”理解。排他性下降后，其他云和应用厂商可能接近同类模型能力。微软需要更多依靠分销、企业服务和成本效率赢得客户。

公开修订呈现的是权利交换。它既有保留，也有让出，未公开的合同细节使我们无法精确计算交换是否划算。投资判断应承认这种不透明度，而不能选择其中一条最动听的条款代替整体分析。

HLBV：持股变小，也可能确认收益

微软对 OpenAI 的投资采用权益法，并使用 HLBV，即假设按账面价值清算的方法。年报解释，原因在于清偿权与优先顺序不同于表面持有比例。FY2026 年报 Note 1。

理解它可以先设想一次并未真正发生的清算：如果被投企业把账面净资产按约定权利分配，各类投资人分别能够取得多少？微软需要跟踪自己在这一假设下可分得金额的变化，并区分新增资金、分配及其他资本结构变化。

因此，权益法损益不能简单写成“25%乘 OpenAI 净利润”。比例没有表达的优先权，可能改变分配结果；重资本化与融资，也可能同时改变净资产和投资人的相对权利。

一个看似反常的结果由此出现：微软的比例被稀释，账面上却可能确认收益。其他投资人投入资本、权利安排变化之后，假设清算下的可分得金额可能上升。会计上的增加，不要求微软在同一天把投资卖掉或收到分红。

微软披露 FY2026 的 OpenAI 投资净收益，主要与重资本化稀释收益有关。按全年公告的精确调整表，税前净收益为 65.30 亿美元，税后影响为 49.63 亿美元。两种金额不能互换，更不能把它们称作 OpenAI 支付给微软的现金股息。FY2026 年报 Note 3及Q4 全年 GAAP 调整表。

权益法信息还可能存在时滞。微软会计政策允许在及时财务信息不足时，采用最多三个月滞后的投资数据，并对重大中间事件另行处理。观察当季投资损益，不能默认它与被投企业同季的经营状态完全同步。

HLBV 不是把风险藏起来的证据，也不是投资价值已经兑现的证明。它是一套有特定权利基础的计量办法。投资者需要把会计变动与现金收支分开，尤其要避免因为某年确认了很大收益，就把它放入未来每年可以重复的利润。

付款链与信用风险

241 亿美元收入，到底证明了什么

FY2026 的 241 亿美元，证明微软已按适用会计政策确认了与 OpenAI 商业安排相关的收入。年报明确其中包括收入分成，因此不能把全额改名为“纯 Azure 算力销售”。FY2026 年报关联交易披露。

关联交易本身不等于收入无效。微软确实可以向被投企业提供有价值的基础设施与服务，双方的投资关系也不意味着所有交易都需要在微软合并报表中自动抵销。OpenAI 没有作为微软子公司并表，分析必须尊重这个边界。

收入确认也不关闭信用问题。期末 60 亿美元应收说明，一部分已确认收入在该时点尚未转成收款。它可能受到合同账期、业务增长、开票时点等多种因素影响。只有一个期末余额，不能据此推导账龄恶化，更不能宣布款项无法收回。

真正需要补上的，是付款期限、账龄结构、担保、合同抵销权以及后续回款。公开材料没有提供完整答案。我们应当把这视为需要监控的客户敞口，不能把信息不足自动判成安全或危险。

采购承诺又处于更早一层。2025 年公布的新增 2,500 亿美元 Azure 采购，表明双方签订了未来商业安排；它不是公告当天新增的年度收入。服务需要建设和交付，客户需要使用和付款，合同也可能跨越多年。

把承诺金额直接加进当前收入，会跳过整条履约链。把它再与 RPO 或其他合同余额相加，还可能重复计算已经包含的同一项安排。第 03 篇讨论的基础设施投入，正是这些收入实现之前需要经过的资产环节。

出资、收款与循环融资风险

微软披露，与 OpenAI 投资有关的累计资金承诺为 130 亿美元，截至 2026 年 6 月末已投入 119 亿美元。累计承诺、累计已付和当年现金支出属于三个不同期间口径。FY2026 年报 Note 1。

不能拿累计出资额与一年服务收入相减，宣称投资已全部收回。提供服务有相应成本，收入中有应收，投资资金与服务现金的法律归属也不同。收入超过某个历史投入数字，并没有计算资本回报率。

但这类关系确实有一个值得严肃研究的风险：模型公司取得融资，使用资金购买云服务；云公司同时投资模型公司并扩张资产，以满足采购。融资、设备、收入和未来承诺互相支持，也可能共同依赖最终用户愿意持续付费。

在需求真实且回报足够时，这可以是建设新产业的融资方式。外部资本先投入，基础设施提供服务，最终客户为有用产品付费，价值逐步覆盖前期成本。

如果终端需求的现金贡献长期不足，链条就更依赖持续融资。云公司的客户可能收入高速增长但仍需要大量资本；云公司又可能一边收服务款，一边承担新出资或新增设备义务。收入有履约基础，与整体资金循环能长期持续，是两个需要分别验证的问题。

最强反方承认服务收入真实，同时追问谁在最终承担付款。若终端客户的现金不足以支持模型公司的算力支出，持续融资就承担更多责任；融资放缓又可能同时影响微软的应收、投资和未来容量需求。微软还要履行先前形成的资产与合同责任，损害便可能跨多个账目传导。

这种风险分析没有直接证明会计造假。要作出更强指控，需要交易实质、收入政策、履约与现金证据。公开信息不足时，用一个“循环”标签替代全部研究，既可能错杀真实生意，也可能漏掉真正需要量化的信用敞口。

观察应按资金来源向资产回收展开：终端用户持续付费，合作方能够承担算力账单，微软应收转成现金，新增资源在更新前收回成本。若合作方融资压力与微软应收、出资责任同时上升，应联合重审敞口；若资源能转给其他付费客户，也应计入缓冲。单品毛利和完整账龄未披露，仍须保留缺口。

多模型合作的价值归属

Anthropic：另一种模型选择，另一组资本关系

2025 年 11 月 18 日，微软、NVIDIA 与 Anthropic 公布合作。微软承诺最多投资 50 亿美元；Anthropic 承诺购买 300 亿美元 Azure 算力，并拟签订最多一吉瓦的额外容量；Claude 的接入覆盖 Foundry 和 Copilot 家族。微软合作公告。

这几项内容不能合成一句“微软用 50 亿换来 300 亿收入”。投资上限未必已经付清，采购跨越履约期，云服务需要成本和资本，一吉瓦又是容量单位而非销售金额。

2026 年 2 月 12 日，Anthropic 宣布 Series G 融资 300 亿美元、投后估值 3,800 亿美元，并说原研究包括微软与 NVIDIA 此前宣布投资的一部分。公告没有给微软单独完成的出资额或准确持股。Anthropic Series G 公告。

2026 年 5 月 28 日，Anthropic 又宣布 Series H 融资 650 亿美元、投后估值 9,650 亿美元，同时明确亚马逊云服务（AWS）仍是主要云和训练伙伴。微软的云合作因此与其他供应商关系并行。Anthropic Series H 公告。

对微软有利的推断是，多模型选择有助于降低单一伙伴依赖，也让企业客户能够选择更适合任务的能力。对微软不利的推断是，其他云也可以服务同一模型，单靠“能提供 Claude”难以形成独有收费权。

它还增加另一组资金和信用问题。50 亿美元上限不能除以某次估值就反推精确比例，因为融资日期、证券权利和实际出资都未完整公开。融资估值大幅增加，也不意味着微软能够按同等条件立即出售。

微软 FY2026 Q4 披露 32 亿美元 Anthropic 投资收益。这是会计损益，不能与 300 亿美元采购承诺、未来云收入和投资价值同时无差别加总。FY2026 Q4 离散项目说明。

正方与反方，其实在争不同的东西

正方的核心逻辑是：微软较早取得前沿技术与商业权利，又拥有企业销售、应用和云基础设施，可以在多个环节获得收益。即便某个模型伙伴不再领先，多模型平台和自己的产品也可能继续服务客户。

这条逻辑有现实基础。微软已有产品接入，商业收入已经披露，许可与分成也有公开条款。把整个合作仅仅叫作一笔风险投资，会低估经营关系的重要性。

反方关注的则是价值归属。模型供应商可能保有产品、品牌与终端客户；其他云逐步获得接入；微软需要持续建设资产，还可能面对投资与客户风险的相关性。即使整条 AI 产业链创造巨大价值，微软股东获得的份额仍可能低于投入和价格所要求的水平。

因此，多模型战略也有成本。支持更多伙伴，需要工程、销售、治理与计算资源；客户选择扩大，可能提高平台吸引力，也可能提高客户议价能力。数量更多，并不保证微软能收取更高净价格。

判断合作是否成功，不能只问哪家模型更强。还要问：微软能否获得稳定技术供给，客户是否愿意为它提供的整套服务付费，服务和投资能否各自带来足够回报。这些环节可以分化，不能用一个模型排行榜概括。

合并判断与重审条件

怎样避免把风险与收益同时算错

第一步，经营分析保留实际服务收入，同时认真研究收款和成本。关联关系不会让收入自动消失，也不会让客户信用天然更好。

第二步，投资损益与经营重复性分开。HLBV 和稀释收益有助于理解报表变化，但未来经营能力不应靠重复发生相同资本交易来成立。公司剔除 OpenAI 影响的调整后每股收益（EPS），也没有自动剔除 Anthropic 等全部离散项目。

第三步，资本承诺按时间和条件列明。投资承诺与服务合同不同，已开始与尚待交付的容量也不同。不能把新闻金额全部当下一年现金缺口，更不能因为不在当期现金流出中就视为没有义务。

第四步，未上市投资估值只在证据足够的边界内讨论。缺少退出和权利信息时，可以把它保留为不确定价值，而不让基准判断依赖一个新闻估值乘法。具体怎样进入微软整体估值，第 08 篇再统一处理。

最后，联合看风险，分别记账。一个合作方融资受阻，可能同时影响投资、应收与未来算力需求，但损失需要逐项确认，不能在每个栏目里重复扣除同一经济冲击。

三千万付费席位，不是三千万张全年原价账单。

微软在 2026 年 7 月公布的 FY2026 Q4 业绩中表示，Microsoft 365 Copilot 已超过三千万付费席位。同期电话会披露，GitHub Copilot 有五千万 users。前者明确带有“付费席位”口径，后者没有说五千万全部付费，更没有给出两个产品可以相加的独立人数。FY2026 Q4 公告、官方电话会。

如果把期末席位乘上统一月费，再乘十二个月，就得到了一个很容易传播的“AI 收入”。这个计算跳过了年内新增时点、套餐、折扣、产品重叠与会计确认。

即使收入计算正确，股东利润还隔着推理、数据处理、安全、部署与持续研发成本。产品被用得更频繁，客户可能受益更多，厂商也可能先承担更多支出。

Copilot 的价值捕获要走完一条链：客户有值得自动化的工作，采购预算愿意付款，微软的净收费覆盖服务成本，新增现金再覆盖研发和资本需求。任务量增长扩大机会，利润由实际价格、任务成本和旧收入被替代的程度共同决定。

需求先进入客户预算

客户省下的时间，怎样变成微软的收入

AI 产品首先需要替客户完成有价值的任务。它可以减少准备资料、寻找信息、编写代码或处理业务记录的时间，也可以让以前不经济的任务变得值得执行。

但“节省时间”与“节省现金”之间存在距离。以下是机制示意：员工更快完成一份报告后，企业可能让他处理更多工作，也可能改善报告质量，或减少加班。只有在相应条件下，时间节省才会表现为工资、外包或其他现金支出下降。

对客户而言，新增收入、服务质量和更快交付同样有价值；对研究者而言，这些价值需要分别测量。不能把所有节约时间乘上员工工资，再把结果全部视为可供软件厂商收费的空间。

任务是否完成，还要包括人工复核、纠错和责任。一个工具生成初稿很快，却需要专业人士花很多时间检查，客户获得的净改善就与演示速度不同。处理低风险摘要，与批准一笔付款、修改生产系统或作出专业判断，需要的验收标准也不同。

微软官方会披露客户使用案例和生产率效果。这些案例能够说明产品有具体用途，但它们是经过选择的样本，不能据此推导全部客户的平均回报。愿意扩大部署的客户，是有价值的需求线索；长期续费与实际使用分布，才更接近收费能力的持续证据。

采购预算取决于任务完成质量、净节省和业务结果，竞争工具与自行搭建方案限制客户愿付价格。微软还要覆盖推理、数据处理、复核支持等成本。客户价值与服务成本之间能留下多大空间，决定增长最终归客户、模型供应商还是微软股东。

席位、用量与结果，是三种不同的账单

传统企业软件常按用户收费。客户购买一定数量许可，在一定期限内使用约定能力，预算相对容易预测。用户工作得更多，通常不会因为每次点击都增加同等账单。

AI 长任务改变了成本分布。同样一名员工，可以只问一个短问题，也可以让代理持续检索、调用工具、修改内容并多轮尝试。相同席位的资源消耗，可能差别很大。

按用量计费能够把一部分成本与收入连接起来。账单可以与 token（模型处理文本等内容的计量单元）、任务调用或其他计量单位有关，但客户要面对用量不确定性，也可能设置预算上限、减少低价值任务或改用其他工具。

结果计价又更进一步：客户为完成某项工作支付费用。它与按用量收费并不相同。一次成功处理和多次失败重试，消耗的计算可能不同；对客户价值相近的两个结果，取得成本也可能不同。

如果未来更多合同按结果定价，就需要定义何为完成、谁来验收、错误怎样处理，以及外部因素如何分担。这里讨论的是商业机制，不能把管理层关于结果导向的愿景，当成所有现有 Copilot 产品已经采用的合同条款。

计价方式客户得到的确定性微软需要承担的主要问题
按席位预算与使用权限较清楚重度使用成本、套餐定价与席位替代
按用量能限制消费，支出随使用变化价格弹性、计量透明度与单位成本

微软正在组合这些方式。Amy Hood 在 2026 年 9 月公开会议上讨论了用户许可的预算可预测性，以及消费计价承接新增工作成果的作用。这是对商业模式方向的说明，不是已经公开的产品独立利润表。Hood 官方会议记录。

收费机制与实际证据

M365 Copilot：要把付费覆盖拆到合同里

Microsoft 365 的企业客户已经购买办公、协作和相关服务，Copilot 有机会进入现有工作与采购体系。这降低了触达和部署的一部分障碍，也让升级更容易成为客户讨论的议题。

它不意味着新增收入等于所有现有席位按统一价格升级。客户可以只给部分岗位购买，也可以先部署再扩大，或者在不同套餐之间选择。期末三千万付费席位，也包含在财年不同时间加入的用户。

截至研究截止日取得的美国企业官网，M365 Copilot add-on 挂牌为每用户每月 30 美元、按年付，且需要合格的基础 M365 许可。这是特定 SKU 的挂牌条件，不能替代全球实际成交价格。企业价格页，2026-10-22 取得版本。

看一张真实账单时，至少需要问：它是哪种产品，覆盖哪些席位，服务期限多长，是否折扣或促销，是否另含用量，哪些金额是在替代原来的支出。缺少这些信息，无法从席位准确推回收入。

本研究没有取得具体客户的原始账单或续约合同。这里采用公开计费条款解释账单机制，实际客户平均成交价保持未知，不用官网挂牌补齐。

免费或无额外收费的入口也需要分开。Copilot Chat 对符合条件的账户可以包含在既有许可中，部分代理功能另按用量。客户使用了 Chat，不等于购买了完整付费 Copilot；客户没有单独付 add-on，也不意味着微软无法从基础订阅或相关消费中收费。

E7 使收入分配更需要克制

微软在 2026 年 3 月宣布，E7 于 5 月推出，挂牌每用户每月 99 美元，集合 E5、Copilot、Agent 365 以及相关身份和安全能力；Agent 365 单独挂牌每用户每月 15 美元。微软 E7 公告。

一名客户从原有套餐转到 E7，新增经济收入取决于升级前后的净差，以及其中有多少替代了原先已经购买的产品。研究者不能给 E7 全额收入后，再把包含的 Copilot、身份与安全收入各加一次。

捆绑可能帮助产品普及，也可能降低单项能力的实现价格。只有分别观察采用、使用、续费与收入，才能判断扩大付费覆盖究竟创造了多少增量。

M365 的难题因此不是有没有人购买。付费覆盖已经有公开证据。更难的是覆盖中的哪些客户真正把产品用进工作，并愿意在下一次预算讨论中继续增加净支出。

GitHub：官方已经给出一次成本反证

GitHub 的例子把抽象问题变成了具体计费变化。

2026 年 4 月 27 日，GitHub 宣布自 6 月起向 AI Credits（AI 用量结算额度）计费过渡，并解释，旧模式下短问答与长时间自主编码的计价可能相同，GitHub 吸收了不断增加的推理成本，原 premium request 方式难以持续。GitHub 官方公告。

这不是“用户不喜欢产品”的证据。恰恰可能是产品用途扩大后，原有收费单位无法对应新的资源消耗。一次长时间代理任务，不再等同于过去的一次简单辅助请求。

公告保留 Business 每用户每月 19 美元、Enterprise 每用户每月 39 美元的基础价格，同时规定 included credits 与额外消费。基础月费保持不变，并不意味着重度使用客户的最终账单不变。

公告还给出 6—8 月过渡期积分安排。促销额度不能当成永久套餐；已经存在的按年订阅，过渡条件又可能延续到合同到期。研究收入时，需要看客户所处合同批次，不能假设所有人同一天以同样方式结算。

按量收费可以改善收入与成本的对应，也会改变用户行为。管理者可能设置额度，开发者可能选择更便宜模型、减少重复尝试，或者把某些任务移到其他工具。更透明的计量既可能帮助微软变现，也可能让客户更仔细地比较价格。

FY2026 Q4 电话会中，微软说 GitHub Copilot 达到五千万 users，并在开发者产品的上下文中披露 Copilot 收入环比增长超过 60%。这一增速不能写成整个 M365 Copilot 的收入增长，五千万 users 也不能改成五千万付费用户。官方电话会开发者业务段落。

可得出的结论是，新的使用与计价已经开始产生收入；不能据此给出未披露的 GitHub Copilot 独立利润率。增长发生在计费转换期，后续还要验收促销结束、预算控制与续约之后的持续性。

不同业务怎样捕获价值

以下按安全、业务流程与消费者分别检验收费和成本。

安全：价值取决于风险和响应，成本也包括责任

安全产品可能帮助客户发现问题、调查告警和执行处置。价值不仅是省去多少人工，还包括响应质量与业务风险。但这些结果需要在实际环境中验证，不能仅靠演示数量。

与已有安全套餐整合，有助于微软分发能力和统一治理。客户也可能保留独立供应商，以获得不同检测能力或降低集中依赖。因此，安全功能进入套件，与客户愿意为它额外支付费用，仍是两项证据。

自动化一旦涉及执行动作，就需要严格的权限、复核和回滚。资源成本之外，部署、调查、客户支持和责任安排也可能影响经济性。没有产品级成本披露时，不能假设安全 AI 天然比办公 AI 更赚钱。

FY2027 重列把 Security Copilot 从旧 Azure 指标移到 M365 商业云；大部分其他安全业务此前已在相关应用体系。这是分类变化，不能据此称新增加了一份 AI 收入。官方重列材料第 7—13 页。

业务流程：减少人工步骤，也可能减少旧许可

Dynamics 等应用将 AI 放进销售、财务、服务与供应链流程。一个有用的代理可以降低处理工作所需时间，也可以增加服务能力；价值最终取决于它能否可靠地执行客户的业务规则。

这里存在原有收入被替代的可能。假设一项流程原来需要多个员工使用应用，自动化后由较少人员监督更多工作，基础用户许可需求可能改变。新增消费收费能否超过减少的旧收入，需要单独计算。

相反，一些原本因人工成本太高而没有执行的工作，也可能开始被执行，扩大软件消费。两种方向都合理，不能因为任务总量增加就假定所有收入都是净新增。

微软年报把 Dynamics 收入驱动描述为用户许可、应用消费、平均每用户收入及向云服务迁移。AI 会改变这些变量之间的关系，而不只是给原来每项收入再叠一个增长率。FY2026 年报 Dynamics 业务说明。

消费者：订阅、免费触达与广告各有自己的账

消费者可以通过订阅、已有应用或免费入口接触 AI。对微软而言，有些使用可能支持订阅留存，有些可能帮助搜索或广告触达，也有些需要持续承担计算成本。

不能把消费者使用量全部折算成企业 add-on 收入。个人与家庭订阅包含的能力、免费产品和搜索场景，与企业账户的合同和预算不同。

即使消费者订阅增长，也需要区分价格、用户数量、套餐和其他功能的贡献。AI 带来的留存改善可以有价值，但没有足够披露时，不能给它指定一个精确份额。

对广告相关场景，还要比较新增触达和商业转化，扣除相应流量与服务成本。更长的对话是否创造更多可变现机会，需要证据，不能从停留时间自动推出利润。

贡献利润，先把增量说清楚

如果无法取得产品独立利润，研究仍可以建立清楚的经济框架，而不编造一个数字。

一项产品的增量贡献，可以按以下思路组织：

增量贡献 = 新增席位与升级的净收入 + 新增用量或结果收入 − 被替代的原有收入 − 增量服务与支持成本。

这是一条分析关系，不是公司披露公式，也不是完整的经济利润。它尚未解决固定研发、共享基础设施、资本占用和税的分摊。

分析应比较同一客户采用前后的净收入和服务范围。原有基础套餐收入继续归原业务，组合账单只计一次，自动化减少的许可收入进入抵减。这样才能分清新增需求、收费单位迁移与旧收入替代。

支出方面，直接推理只是第一层。检索、上下文处理、存储、网络、工具调用、安全检查、任务编排和人工支持，都可能产生资源消耗。一个失败任务反复重试，也可能增加成本，却没有增加相同的客户价值。

固定成本则属于另一层。产品需要研发、模型与系统优化、销售和持续维护。短期贡献为正，不代表累计投入已经回收；把所有共享成本都压给一款新品，也会扭曲判断。

因此，应先判断一项工作在增加使用时是否带来正的增量贡献，再讨论规模能否覆盖长期成本和资本回报。第 06 篇统一报表与现金口径，第 08 篇再处理整体估值，这里先把因果链建立起来。

模型便宜，为什么不一定让微软利润更多

单位计算成本下降，对商业化有帮助，但它可以流向不同主体。

微软可以保留部分效率改善，降低履约成本；也可以把价格降给客户，扩大使用；竞争者如果同时改善，又可能迫使市场价格更快下降。客户获得更便宜能力，与微软保留更高利润，并不总以同样幅度发生。

任务本身也在变化。一次请求的处理更便宜，却可能容纳更长上下文、更多工具调用和更复杂的代理循环。单位 token 成本下降，不能直接推导每个客户的总服务成本下降。

成本比较应固定任务质量和完成标准，把模型调用、失败重试、检索、复核与支持一起计入。若单次调用更便宜而完整任务更长，总服务成本仍可能上升；若效率红利主要通过降价交给客户，使用增长也未必同幅提高利润。

模型路由、缓存和系统优化有助于把合适任务交给合适能力，微软也在公开会议中强调效率与模型选择。但效率需要通过可持续成本和客户体验体现，不能把技术吞吐量提升直接当成利润率提升。FY2026 Q4 电话会、Hood 会议记录。

自研或开放模型可以扩大供应选择；外部强模型也可能帮助竞争者。第 04 篇已经讨论合作权利，本篇只保留它的经济后果：供应更灵活，有助于控制成本，但最终售价和客户选择仍由竞争约束。

机制情景与后续验收

以下逐个检验五种机制在哪里形成收入、成本与替代效应。

以下不是五份盈利预测，也不分配主观概率。它们是可以同时、分业务发生的机制，用来安排后续证据。

情景一：有价值的席位稳定扩散

更多客户从小范围试用进入日常工作，购买覆盖逐步扩大，续约保持，套餐和实际价格能够支撑服务成本。微软已有分发体系帮助扩大采用，客户也确实获得可重复的价值。

支持这一情景的，是不同合同批次的持续使用、续费与净收入，而不是某个大型客户的首批采购。如果付费席位增多但激活、使用或次年续费较弱，就需要降低对扩散质量的判断。

情景二：代理用量扩大，计价成功跟上

客户购买许可后使用更多代理，微软把一部分新增工作转为按量收费。客户从成果中获得足够价值，愿意接受超出基础套餐的账单，新增消费也能覆盖相应成本。

最难的部分是预算管理。用量收费透明之后，客户可能主动限额。需要观察在额度控制、促销结束与模型替代之后，收入和使用是否仍能共同增长。

情景三：效率红利主要留在客户侧

模型和系统不断降低成本，同行也快速跟进，客户以更少支出取得相近能力。微软可能获得更多使用和更大市场，但单位收入下降，利润改善没有技术进步看起来那么快。

这不等于产品失败。它意味着技术创造的经济剩余更多传给客户。观察单位任务价格与规模，需要同时跟踪服务成本，不能只看到价格下调就悲观，或只看到用量增加就乐观。

情景四：自动化压缩原有席位

代理替代一部分重复操作，企业减少某些岗位或应用许可，同时购买新的 AI 消费。微软需要用新增收入弥补旧收入减少，并承担新的计算负担。

这个情景最容易被“AI 收入”标签遮住。分析必须看同一客户升级前后的净支出与服务范围，不能只汇报新收费项。实际效果也可能因行业和岗位分化，不应假定所有客户都缩减席位。

情景五：新增工作由外部入口承接

客户保留微软基础服务和数据，却通过其他代理、应用或模型完成新增工作。微软可能继续从底层订阅或计算中收费，应用端的高价值预算却不完全归它。

第 02 篇讨论的身份与流程关系，仍有防守价值；接口开放和多模型供应，又让竞争者更容易进入。需要观察用户实际在哪完成工作、谁取得新增支出，以及微软留下的收入是否足以覆盖它承担的资源。

五种情景的分歧，都不能由一次付费用户增长关闭。它们关注的是同一条链的不同环节：采用、留存、实现价格、旧收入替代、单位成本和价值归属。

遇到缺失，可以用公开趋势限定判断范围。例如，产品使用和相关业务收入可以提供不同方向的证据；它们无法精确拆开所有贡献时，就保留多种解释。不能为了得到一条整齐增长曲线，把年末席位、用户总量和年度收入拼成同一个指标。

也要防止口径变化产生假加速。FY2027 的 M365 商业席位纳入 GitHub Cloud 付费席位，商业云收入也加入相关开发者与安全业务。原有和新指标需要对齐版本，不能因为重列数字变大就宣布商业化突然改善。官方指标重列与定义、重列对照表。

怎样同时认真对待机会与反方

正方已经有实质证据：付费席位、企业部署、使用和消费收入都在发展。微软有机会把 AI 放进既有工作，也有能力调整价格、优化系统与扩大模型选择。将一切归为宣传，会忽视已经发生的收费变化。

最强反方并不需要否认需求。它只需要指出：客户获得更多价值时，微软可能同时面临更高服务成本、更激烈竞争和旧产品被替代；新增收入很大，仍可能不足以达到资本回报要求。

这条反方什么时候变弱？当实际续费、实现收入和成本改善能够连续相互支持，当新增消费不只依赖促销或少数试点，当基础业务变化也被计入净增量，它就会变弱。

反过来，如果使用持续扩大，产品贡献却长期只能靠更高标价、重新限额或不断扩大的投入解释，我们就不能把“正在规模化”当作无需期限的免责理由。

产品级利润表仍未公开，独立利润率继续保持未知。后续应把续费、同客净实现收入、旧许可变化与完整任务成本并排观察；只有这些指标共同支持增量贡献，才有依据提高对股东现金回报的判断。在缺少产品损益披露时，不据采用规模推定利润率。

微软的现金 FCF，已经连续两年下降。

FY2026 的净利润却达到 1,337.49 亿美元，经营现金流（CFO）达到 1,829.35 亿美元。两个数字都很强。但扣除现金购置物业及设备（PP&E）的 1,159.48 亿美元后，按现金收付观察的自由现金流，即本篇所称现金 FCF，只剩 669.87 亿美元，低于上一年的 716.11 亿，也低于 FY2024 的 740.71 亿。FY2026 财务报表。

标题还要再往前问：这些钱中，有多少已经承担租赁本金、员工股权成本、资产更新及其他资金占用，有多少是公司可以在不伤害未来经营的前提下分给股东的？

这五年不是一条简单的“利润没有变成现金”曲线。经营现金流也在扩大，客户确实向微软支付了大量资金。变化发生在下一层：支持业务所需的资产购买，越来越多地使用了这些现金。

建设和设备先付款、后形成收入，允许扩张期现金释放暂时承压。验收需要保留时间顺序：相关资产投产后，用量、收款与更新支出是否支持资本回收；若每次现金改善都需要把下一批付款向后推，增长投入的解释就仍未闭环。

这两个判断需要同时成立：不能把资本开支高直接当坏生意，也不能把它从股东账里拿掉，只留下利润增长。

毛利率下降，营业利润率为什么还能上升

FY2025 到 FY2026，合并毛利率由约 68.82% 降至 67.94%，营业利润率却由约 45.62% 升至 46.78%。这提示我们，成本变化并不都发生在同一层。

毛利需要承担提供产品与服务的成本。微软在 FY2026 MD&A 中指出，AI 基础设施和产品使用增加，以及业务组合向 Azure 变化，影响了毛利率；效率改善抵销了一部分压力。营业利润则还扣除研发、销售营销和行政费用。这些费用增长慢于收入时，营业利润率可以在毛利率下降的同时上升。FY2026 MD&A，Summary Results及Operating Expenses。

因此，营业利润率改善有真实的经营含义：公司在扩大规模时控制了部分费用增长。它没有证明每一种 AI 服务的毛利都在提高，更没有证明每一笔基础设施投入已经形成同样好的现金回报。

净利润又多了一层。FY2026 其他收入及费用净额为正 106.97 亿美元，FY2025 为负 49.01 亿美元，其中包括投资、衍生品、利息及其他项目。年末投资估值变化可以进入当年利润，却不一定伴随同额现金进入公司。

OpenAI 投资在 FY2026 带来税前净收益 65.30 亿美元、税后净影响 49.63 亿美元，主要与重资本化的稀释收益有关。公司剔除此项后的净利润为 1,287.86 亿美元，但这个指标仍没有剔除所有投资或离散项目；例如 Q4 还有 Anthropic 投资收益。FY2026 Note 3及Non-GAAP桥接、Q4 财务说明。

判断核心经营时，应先看营业利润及其成本结构，再把投资和税务影响接回净利润。不能因为公司提供了调整后每股收益（EPS），就把它改名为“全部经常性利润”。

五年比较也有特殊项。FY2022 净利润包含无形资产转移带来的约 33 亿美元税益；FY2023 又受到税率变化及重组费用影响。历史净利润的起伏，需要和当年的解释一起读，不能只沿着表格画一条外推线。FY2023 年报比较说明。

折旧和摊销，是过去取得资产后分配到当期的费用；现金通常已经在其他时点支付。将它们加回，帮助我们从会计利润回到本期经营现金，但不意味着资产将来无需更新。表里的“及其他”也不能省略，把整项都称为纯折旧。

投资与衍生品调节把相关非现金损益等从经营现金流中处理掉。因此，投资账面收益很大时，净利润可以迅速增长，CFO 却不会自动获得同额现金。第 07 篇管理层评价以及终章估值，也需要维持这条边界。

递延税同样涉及确认与支付的时间差。FY2026 账面所得税费用为 321.85 亿美元，所得税现金支付净额为 211.88 亿美元；FY2025 的现金支付约为 287 亿美元。客户收款和现金税变化共同影响了 CFO，不能把全部现金增长都归因于销售效率。FY2026 Note 11及Cash Flows讨论。

最后一项也不只是日常“应收减应付”。它包括税项、递延收入及长期经营余额等。客户应收增加会占用现金，收到预付款或增加部分应付又可能暂时释放现金。需要看具体项目和后续转回，而不是把任何 CFO 高于净利润的年份都评为高质量。

相反，669.87 亿美元也不能直接称为全部可分红现金。它没有完整回答融资取得资产、长期付款责任、必要更新以及股权报酬的问题。

可分配给股东的现金，要在维持竞争地位和经营能力所需投入之后判断。增长与维护共用资产，公开计划不足以客观拆分。下列现金层次因此保留各自名称和扣项：它们用于识别资金责任，不能把最宽松或最严厉的一层直接命名为精确所有者收益。

SBC 为什么既已经扣过，又需要再看

股权薪酬最容易让利润表与现金流分析发生重复计量。

在 GAAP 营业利润和净利润中，SBC 已经作为费用扣除；现金流表又把这项非现金费用加回。因此，以 CFO 为起点的现金 FCF 并没有保留同样的股东经济成本，读者需要另外关注稀释或维持股数所需的回购。

若以已经扣除 SBC 的营业利润、税后经营利润（NOPAT）为估值起点，情况就不同了。再扣一次全额 SBC，会重复计算这项成本。未来股份变化、现金等价成本与利润费用，需要选择一致的处理方法，不能只挑让价值更低或更高的算法。

这也是本文把“现金观察”和“经济模型”分开的原因。现金表可以展示扣 SBC 后的代理值；后续现金流折现模型（DCF）已保留 SBC 费用，并将融资租赁作为债务处理，不会再次扣同一笔 SBC 和租赁本金。

当期 SBC 费用还不等于当期归属股票的市场价值。授予日估值、服务期确认、股价变化、税款代扣和实际发行之间存在时差。薪酬成本被确认，并不能只凭当年股数没有增加，就认定员工奖励对股东免费。

公司的营业利润也已经承担研发、销售和管理等当期费用。研究可以追问这些投入是否值得，却不应把所有带有“投资”意味的费用从经营现金流里再扣一遍。财务谨慎的价值在于不漏项，也不重复扣项。

回购很多，股数为什么只减少一点

FY2026，微软公开回购计划买回约 3,600 万股，花费 167.19 亿美元。现金流表列出的普通股回购金额却是 222.71 亿美元，两者相差 55.52 亿美元。FY2026 Note 15与Cash Flows Statements。

差额对应员工股权奖励归属时，为缴纳税款而回购股份等口径；附注对此类回购作了约 56 亿美元的舍入披露。现金流流出是真实的，但不能把全部 222.71 亿美元都称为公开市场回购计划对其他股东的额外返还。

再看股份表，年初约 74.34 亿股，发行约 2,900 万股，公开计划回购约 3,600 万股，年末约 74.27 亿股。按这些以百万股取整的数据计算，发行量相当于回购股数约 80.56%，股数净减少约 700 万股，约为年初的 0.09%。这是一组近似股数比较，不是逐笔交易精度。

它说明回购的一大作用，是抵销新发行，之后才是净缩减股本。发行并不全部等同本年新增 SBC，回购也并不因抵销发行而失去价值；需要检验的是，公司为取得员工服务付出了什么，以及回购所付价格是否合理。

从每股角度看，同样一家公司，股份更少时每股对应的权益通常增加；但若回购价格过高，花掉的现金也可能超过其他股东获得的经济好处。EPS 增厚只展示每股会计结果的一部分，不能替代资本配置评价。

还要区分三个分母：全年加权平均稀释股数用于 EPS，财年末股数用于时点余额，最新已披露股数用于当前参考市值。它们有各自日期和用途，不能用一个期末每股数字倒算全年回购效果。

这一年的回购质量，最终要与人员激励、投资机会和支付价格一起判断。第 07 篇会把这件事交还给作决定的人；第 08 篇再讨论价格。

现金分红和宣派分红，也不是同一笔期间数字

FY2026 现金支付股息为 264.45 亿美元，董事会当年宣派股息约为 270.35 亿美元。宣派形成决定和相应付款义务，现金支付则发生在具体支付日，跨财年时两者自然不同。FY2026 Note 15，Dividends。

例如，财年末宣派、下一财年支付的股息，会先体现在义务里，再进入下一期现金流。不能看到宣派额高于现金流表，就推断公司少付或现金异常；也不能把宣派与支付再相加，当成返还两次。

公开回购计划的 167.19 亿，加本年现金股息 264.45 亿，合计 431.64 亿美元，与公司所称全年向股东返还超过 430 亿美元的范围相符。若改用现金流表全部回购，则需要同时解释其中员工税款代扣的部分。

股息能够证明董事会愿意持续分配现金，不能独立证明分配可长期增长。更有用的判断，是公司在更新资产、履行租赁和其他义务之后，分红是否仍有可靠的经营支持，而不依赖出售资产或持续提高财务负担。

FY2026 CFO 很强，年末现金及短投仍比上一年减少了 177.22 亿美元。投资和融资活动共同使用资金，已经足以说明只看 CFO、忽略资产负债表变化，会错过资本配置的另一半。

债务与租赁要逐项识别，再讨论净现金

财年末金融债务账面额为 402.94 亿美元，融资租赁负债为 665.94 亿美元，经营租赁负债为 219.25 亿美元。三项加起来是 1,288.13 亿美元，正是某些标准化数据里“总债务”的一种口径。FY2026 Note 10及Note 13。

如果已经使用包含租赁的标准化总债务，再把两类租赁各加一次，就重复计算。相反，若只看金融债务，也会漏掉融资取得资产的长期付款责任。

以融资租赁视为债务、经营租赁费用保留在经营利润中的观察口径，现金及短投先扣受限短投后为 730.43 亿美元；金融债务与融资租赁合计为 1,068.88 亿，差额为 338.45 亿美元。这个差额不包括其他投资，也不是下一年的全部到期现金缺口。长期义务要和期限、付款安排及未来经营现金一起看。

租赁的现金分类尤其重要。FY2026 融资租赁本金支付 31.01 亿美元，列于融资活动；相关利息支付进入经营现金流。经营租赁支付则已影响 CFO。若从现金 FCF 出发评估本期融资租赁付款，扣本金有意义；不能再把已在 CFO 中的经营租赁付款扣第二遍。

新增融资租赁使用权资产也不是当期全部现金支付。资产开始使用时，报表可以同时增加资产和负债；现金义务在未来履行。它提醒我们经济投入已经增加，却不能与当年本金、未来全部租金一起毫无区分地扣三遍。

第 03 篇讨论过 FY2027 建筑寿命由十五年改为二十五年，并使更多未来租赁转为经营租赁。对财务分析的含义是，未来公司 CapEx、经营费用与 CFO 的边界会变，前后比较需要桥接，不能只按某一栏变小或变大判断回报已经改善或恶化。Q4 资产寿命与租赁分类说明。

组件应收与设备应付，说明付款时点还没有走完

FY2026，支持服务器组件采购活动的其他应收达到 278 亿美元，上一年为 82 亿。设备购置中仍在应付账款的金额达到 267 亿美元，上一年为 69 亿。FY2026 Note 1，Contract Balances及Note 6。

这些不是可以相互抵销的同一笔数字。组件采购相关的其他应收，不等于卖给终端客户的全部贸易应收；设备应付也不等于资产还没有投入经营。研究需要分清资源、付款和资产确认的时间。

这两项变化解释了为什么现金资本开支不能代表全部经济投入，也解释了为什么不能把资产负债表两期差额直接抄进现金流表。汇率、并购、非现金取得和分类等因素，都会使余额变化与当期现金支付不同。

它们也为反方提供了具体检验点：如果采购支持资金回收慢，设备应付之后集中支付，或新资产需要更早替换，某期好看的经营现金流可能没有带来同样充足的股东现金。正方则需要证明，这些安排帮助更快交付，并在后续用量与收款中取得合理回报。

本篇不把 278 亿全部当成坏账，也不把 267 亿全部当成额外新增损失。它们属于需要继续追踪的资本占用和付款责任，不能因为不是当期现金流表里最醒目的一行，就从经济账里消失。

收入端也有类似纪律。年末总剩余履约义务（RPO）为 6,840 亿美元，商业部分为 6,780 亿，约 30% 预计十二个月内确认；其中包含递延收入。合同量、预收或开票、收入及现金不能相加当作四份价值，预计确认时间也不是公司对来年全部收入的承诺。FY2026 Note 12。

每股现金与资本回报

34.04% 的 ROE，能证明什么

用 FY2026 净利润 1,337.49 亿美元，除以年初和年末股东权益的平均值 3,929.33 亿，得到净资产收益率（ROE）约 34.04%。这是采用平均净资产的 GAAP 回报率；不能把全年 EPS 除以某个期末每股净资产，混成另一套结果。

这个比率与微软较强的盈利能力一致，却不是新投入 AI 资本的投入资本回报率（ROIC）。分子包括当年的投资收益和税务影响，分母是会计股东权益；回购、商誉、历史费用化投入、投资和融资方式都会影响它。

高 ROE 公司也可能在新增项目上取得较低回报。老业务留下的利润，可以暂时掩盖新资产周转变慢；新项目的结果尚未成熟，也可能暂时拉低合并回报。需要继续检验新增资金，而不只引用公司历史平均水平。

会计寿命进一步说明这种差别。FY2023 服务器及网络设备估计寿命由四年延至六年，使当年营业利润增加约 37 亿、净利润增加约 30 亿美元。账面利润改善有明确的估计变更贡献，但服务器购置款并没有因此退回。FY2023 Note 1。

同样，现金流中的折旧、摊销及其他，与纯折旧也不同。FY2026 又重列了 FY2024、FY2025 的部分现金流调节项，CFO 总额没有变化。比较历史表格时，应保留版本和完整调节，不能把旧年某一行与新年另一行拼接，得出不存在的经营突变。

巴菲特的一美元测试，需要追到每股经济结果

把留在企业里的每一美元当作需要验收的资本，问题就会更清楚：它能否形成足以补偿风险与等待的未来股东价值？

对于微软，不能只把留存收益余额的增加，与某段市场市值增长相除，就宣告通过测试。投资损益、回购、分红、市场折现偏好和未来预期，都能改变这些数字；报表没有提供足够资料，将每一次资本配置的回报分别归因。

每股验收要同时看分子和分母：旧资产在更新前产生的现金、新资产形成的增量现金、分红及回购后的资金责任，以及净股数变化。若新增利润继续被设备、租赁和采购占用吸收，历史平均回报再高，也不能证明新资本具有同样的分配能力。

价格仍然重要，但本篇只放一个观察尺度。用研究截止日前已披露的 2026-09-30 在外普通股 7,426,426,719 股，配合 10 月 21 日参考收盘价 532.95 美元，合成市值约 3.958 万亿美元。这不是声称上述股数在 10 月 21 日盘中已经公开，也不是实时股数。2026 Proxy 第 82 页、参考历史价格。

669.87 亿美元现金 FCF 对应约 1.69% 的历史现金收益率；若只减 SBC 经济成本代理、尚未减融资租赁本金，则为 545.82 亿，对应约 1.38%。这与前表按“先扣本金再扣 SBC”得到的 514.81 亿，是不同层次的指标，不能互换。

这两个收益率都不是承诺股息，也不意味着增长投资没有价值。它们说明，在当前参考价格下，投资判断需要依靠未来经营和现金回收，而不是只靠当年的现金分配。完整价值与安全余地，留到第 08 篇统一判断。

最强的反方则无需否认利润。它只需证明，设备、租赁、采购资金和股权报酬持续吸收新增收益，使每股可分配现金长期弱于收入与净利润表现。若再投入没有逐步得到回收，“规模扩大”就不能代替股东回报。

这些变化值得记录，因为监督所需的财务、技术和客户经验也在变化。但不能仅凭某位知名人士加入提名，就预先确认董事会更有效。

真正的监督问题更具体：重大项目按什么标准获批，需求变化后谁能要求重估，管理层的财务调整是否被充分追问，安全或客户风险能否压过短期业务目标。公开文件描述委员会与制度，却没有披露所有内部讨论，因此我们无法证明每项挑战都已发生。

缺少公开会议细节，也不能反过来断言独立董事没有作为。合理判断是，制度提供制衡条件，实际效果需要从决策、责任和后续改变中寻找。

接班同样如此。公司披露持续安排关键岗位的继任与人才培养，可以确认这项工作被纳入治理；外部投资者却无法据此知道突发离任时的全部执行方案。本研究不指定未经公布的接班人，也不把经营系统的延续押在某个名字上。

台账要保留同一个项目的原始目标、外部条件、后续投入与实际结果。交割、会计增厚、产品采用和经济回报分别验收；缺少可归因现金流时，评价就停在公开证据能够支持的位置。

管理层改变路线，也需要按原因判断。需求或技术变了以后调整投入，可以是纪律；把原来明确的验收条件悄悄换掉，则会削弱可信度。没有原始记录，两者很容易在事后被写成同一个成功故事。

Activision：完成收购，只完成了第一道验收

Activision 最初公告的交易值为 687 亿美元，包含净现金口径；最终购买会计对价为 754.08 亿美元。两个数字定义不同，不能相减后直接叫作“超支”。FY2026 年报确认，收购在 2023 年 10 月 13 日完成，最终分配包含 510.01 亿美元商誉。2022 年收购公告、FY2026 年报 Note 7。

原先理由涉及内容、玩家、移动业务与跨平台机会。管理层希望将游戏资产与微软的技术、分销和订阅结合，这是一条可以理解的战略逻辑。

取得内容资产后，微软还要支付开发、整合与运营成本，面对延期、玩家需求和销售方式变化。对股东有意义的是收购及后续投入共同带来的增量现金，能否补偿占用资本与其他用途的机会成本；单纯并入更多收入不能完成这个判断。

“增厚 non-GAAP EPS”尤其容易误导。它回答的是特定调整后每股利润如何变化，未必包含购买会计、整合及其他经济成本的全部影响。收购用掉的资本，也需要与替代用途比较。

本研究没有取得能够独立归因的完整收购现金流，因此不计算 Activision 实际内部收益率。股价上涨、用户增加或尚未发生商誉减值，都不能替代这项缺失的验收。

FY2026 游戏业务出现的减值和离散费用，也不能被全部归给 Activision。管理层需要为整个游戏组合负责，研究者同样需要避免把所有好坏变化都压在最大一笔交易上。

可以继续核对的，是内容发布和客户需求、订阅与其他销售的替代关系、整合成本、资产占用和现金贡献。只有这些变量能够共同解释回报，战略理由才逐步转成股东证据。

Nuance：行业入口有价值，仍要交回资本账

Nuance 的原始公告交易值为 197 亿美元，包含净债务。实际于 2022 年 3 月 4 日完成；最终购买会计对价为 187.61 亿美元，商誉为 163.26 亿美元。2021 年公告、FY2023 年报 Note 8。

最初公告计划当年交割，并预计在相应完成时点前提下，FY2022 小幅摊薄、FY2023 增厚 non-GAAP EPS。实际交割推迟，应保留这项偏离；公告本身也列有监管和其他完成条件，不能把附条件预期改写成无条件保证。

医疗工作流、专业语音与既有客户关系，可以帮助微软进入通用办公工具难以直接解决的场景。原公告把行业云和医疗能力列为理由，这比泛泛的“买入 AI”更具体。

但后来出现新的医疗 AI 产品，并不自动证明当初买价合理。发展可能同时需要收购后的研发、模型、分销和持续资本支持。新收入的全部价值，不能只归给最初取得的资产；后续投入也应进入总回报。

大量商誉说明购买价格包含对未来收益和协同的期待，未证明这种期待已经实现。商誉测试服务于会计资产可回收性判断，投资者还要考虑机会成本和资金被占用的时间。

两项收购均保留“战略理由可解释、实际 IRR缺证据”的判断。后续产品还依赖研发、模型和分发，不能把新收入全部归给购买日取得的资产。验收需要把购买对价和持续投入一起放进现金回报，公开披露尚不足以完成这项归因。

AI、伙伴和股东回报，在争同一份资源

管理层面对的选择并不只有“投资或不投资”。它还要决定投资哪类能力、何时投入、使用自有资金还是租赁融资，以及保留多少调整空间。

云与 AI 存在真实需求，但基础设施要先建设，设备与容量又有不同寿命和用途。高增长时期，越容易把未来需求视为既定，越需要区分客户信号、合同质量和难以撤回的承诺。

Amy Hood 在 2026 年 9 月公开会议中，把长周期土地、电力和建设与较短周期设备投入分开讨论，并表示在回报足够时可以使用债务市场。它提供了一套资本配置逻辑，尚不能当成每个项目都已通过独立回报测算的证明。Hood 官方会议记录。

要验证这套逻辑，应看需求变化时设备安排是否调整，已建资产是否能够服务不同客户，以及现金回报能否逐步跟上。会计分类改变造成的资本开支指引变化，也应与实际减少采购、建设和租赁分开。

伙伴投资增加另一层取舍。微软可能通过出资获得技术与商业关系，也会承担被投企业资金与客户风险。管理层有能力取得重要合作，不等于所有合作都给微软留下了足够经济利益。第 04 篇已经拆开这些权利，这里关注的是谁承担追加资金，以及何时需要停止扩大敞口。

董事会需要约束难以撤回的扩张：客户和现金回报落后时，能否推迟设备、改变用途或缩小新增承诺；原项目是否继续沿用同一套验收口径。公开资料没有逐项审批记录，后续资源安排与现金结果是外部能够检查的证据。

回购与分红，要看真实取舍

FY2026，微软在公开回购计划下回购 3,600 万股，金额 167.19 亿美元；现金流量表中的现金股息支付为 264.45 亿美元。前者是计划回购口径，后者是现金支付口径，各有定义，不能把董事会授权金额当成实际执行。FY2026 年报股东权益与现金流量表。

2024 年宣布的 600 亿美元回购授权没有到期日，也可以终止。它提供实施权限，并非到某个日期必须花完的债务。2024 年回购公告。

评价回购，要把价格、未来价值和净股数一起看。买回股票可以提高剩余股东的每股权益，也可能只是抵消员工奖励造成的稀释；以高于经济价值的价格执行，还可能损害留存股东。股价随后上涨或下跌，都不是独立验收标准。

员工归属时用于税款处理的扣股，也与公开回购计划不同。第 06 篇已经统一现金与股数桥，本篇不再把几种金额加成一个笼统的“回馈股东”。

分红表达了实际现金分配，投资则试图扩大未来现金。合适的比例应随投资机会与风险变化而调整。公司成熟不意味着应把全部现金立即分掉，AI 前景广阔也不意味着所有新增资金都应投入算力。

资本纪律最终体现在替代用途的比较：新增项目的现金回报是否优于回购、分红或保留流动性，需求转弱时是否同步改变采购和融资。公司未披露每次内部选择，研究只按可见决策、原始解释与后续结果评价，不预设团队的每项选择都最优。

责任与纠偏

一次安全危机，比一句文化口号更有分量

评价诚信，最有信息量的时刻往往是事实对公司不利的时候。管理层是否及时说明已知与未知，是否纠正先前表述，是否让责任进入制度，比平时说了多少次客户至上更可检验。

2024 年 6 月提交国会的证词中，Smith 表示微软接受 CSRB 所指出问题的责任，并承诺处理适用于微软的建议。官方听证回顾则记录，议员追问为何公开侵入原因说明经过六个月才被更正，Smith 表示公司内部也有同样的讨论。Smith 书面证词第 1 页、国会听证回顾。

这里涉及公开原因说明的纠正时效，不能改写成“同一个漏洞六个月没有修复”。本研究未取得原始 CSRB 全文，也不会把二次转述装成逐页核实的全部调查结论。

可以同时保留两项证据：正式承担责任是正面行动；面对关键事实变化，公开纠正迟缓是负面记录。只讲其中一项，都会使诚信评价失真。

FY2024 Proxy 还披露，Nadella 主动请求降低现金激励，董事会将按既定评价约 1,066 万美元的金额调整到 520 万美元。这是承担责任进入薪酬的一项可见行动。FY2024 Proxy 第 32 页。

它没有让 FY2024 总薪酬减半。股权授予日价值等项目变化后，当年薪酬汇总表总额仍高于 FY2023。把现金激励扣减宣传成总薪酬下降，会抹掉原始披露中最需要区分的口径。

安全评分高，不等于独立闭环

FY2026，CEO 现金激励中安全项目权重为 10%，董事会给出的评分为 160%。它说明安全已进入激励评价，也说明董事会认可了相关表现。2026 Proxy 经营评价，第 43 页。

这仍是董事会自评，不能当成外部独立验证的安全改善幅度。160% 不是事故风险下降 160%，也不能直接代表某个技术控制完成率。

微软的 SFI 进度报告披露工程和治理改进，可以帮助观察执行；公司自述与独立验收之间仍有距离。下一步要看类似根因是否重复、通报与更正是否及时、控制标准和进度能否持续核对。SFI 2026 年 7 月进展。

因此，对本次危机的结论应保持完整：责任与整改行动可见，透明度曾受到有依据的质询，独立闭环证据仍不充分。我们不据此推断个人内心，也不给“诚信满分”。

系统能否在领导者判断失误时纠偏

持续投入需要组织记忆：项目最初基于什么需求、什么收益和什么成本获批；后来改变了哪些假设；继续投入与终止分别需要什么证据。

当同一位领导者推动战略、协调产品并解释结果时，系统尤其需要允许不同信息进入决策。财务人员需要能够报告不理想的回报，安全人员需要能够延迟上线，业务负责人需要能够缩小项目，而不把每次调整都视为战略失败。

这是治理分析的要求，不是本研究已经看到微软全部内部流程的声明。外部可以检验的是，坏消息出现后公司是否改变资源，原先指标是否保留，例外与偏差是否得到解释。

分部重列也有同样的问题。按组织实际调整报告可以提高相关性，历史桥接又必须足够清楚。新分类不能成为不再解释旧承诺的理由。微软提供重列历史，是有帮助的信息；未提供的更早可比区间，也需要保持缺口。

接班风险不只是下一位 CEO 的名字。若产品、客户、资本与风险判断都依赖少数人协调，突发变化可能提高执行难度；若制度能保留客户关系、技术判断和反对意见，个人变化的影响就更可控。

我们能够观察团队稳定性、职责变化和治理安排，仍无法在一次年报阅读后证明公司已经完全摆脱关键人物风险。

反方与评价边界

最强反方：更大的公司，未必留下更多每股价值

最值得认真对待的反方，并不需要否认团队能力。它可以承认微软擅长取得客户、推出产品、建设资产，并指出这些能力也可能推动过度扩张。

技术竞争让投入有紧迫性，资本充足让大项目更容易实施，规模和战略地位又比长期经济利润更容易展示。项目可以取得收入、市场影响和组织支持，却长期达不到最初应有的回报要求。

如果继续投入主要由“已经花了很多”推动，沉没成本就可能进入新的资本决定。并购后的协同愿景、算力的长期需求、伙伴的下一轮融资，都可能让验收期限不断后移。

这不是已被证明的微软现状，而是必须设计证据来排除的失败路径。管理层的历史能力越强，投资者越容易替它解释每次偏差，反而更需要一致标准。

失效信号为什么要求重审
客户与现金回报持续落后，却扩大难以撤销的承诺资本配置可能失去需求与回报约束
项目连续改变验收口径，却不保留原目标和偏差长期承诺变得无法被证伪
并购与新品只有收入故事，长期缺少成本和回报解释规模可能替代每股价值成为主要目标
回购长期无法形成可解释的每股改善需要重新比较价格、稀释与替代用途
同类安全根因或公开纠正迟延再次出现责任进入制度的效果需要重新检验
重大岗位与权力变化缺少清楚责任安排个人集中和组织连续性风险上升

这些信号触发研究重审，不自动构成交易指令。单季投资或现金流变化，也不足以证明整套管理失效；判断需要结合项目周期和当时信息。

把三个判断留在不同格子里

就公开证据而言，团队的产品、商业与组织执行能力有经营结果支持。能在既有客户体系中扩展应用、云和新收费方式，是值得承认的能力。

资本配置的结论更有条件。并购与私人投资有可理解的战略理由，独立现金回报却未全部公开；算力投入的长期回收，也需要后续经营兑现。因此，能力证据强于逐笔投资回报已经得到证明的证据。

诚信评价同样应具体。正式承担责任、主动调整激励与增加披露提供了正面信息，关键事实纠正迟延又必须保留为负面记录。不能因为一次行动就推断全部人格，也不能因为一个问题就抹掉所有执行。

长期投入则有多年度资源与产品行为可以观察。投入持续，只说明管理层愿意继续投入；投入是否值得，还要回到客户、成本、现金和每股结果。至于个人是否热爱事业，公开资料不足以让本研究作心理判断。

这套分法没有提供一个易传播的总分，却能在下一次重大决定公布时继续使用：先确认原有证据，再要求新投入交出自己的结果。

这些选择共用资本、管理注意力和风险承受能力。评价团队可以承认产品及商业执行，同时要求每笔新增资本保留自己的验收条件；两项判断并不冲突。

利润倍数反映当期会计盈利，现金倍数又受到扩张期支出的压制。估值需要把两者接起来：现有收费能力还能维持多久，新增需求要占用多少资本，剩余现金能否在股份变化之后提高每股回报。只挑其中一个分母，都会省略对价格最重要的条件。

前七篇已经建立了判断的基础。企业工作流与分销提供收费优势，Azure有庞大需求，Copilot已经出现付费和消费；模型合作的排他性下降，产品单位利润没有完整披露，新增基础设施又改变了资本强度。管理层具备执行证据，但逐笔资本回报仍不能全部验证。

以原研究参考价购买，需要哪些经营和资本改善才能支持回报？本篇先列明模型、反解和敏感性，再集中给出价格与证据条件。所有判断均基于原研究信息集和历史参考价，参数及适用限制逐项列明。

估值先回答：哪一部分钱能够分配

本篇以经营利润为起点，避免把OpenAI等投资重估当成每年可重复的主营现金。经营利润已经承担当期研发、销售、管理和股权薪酬；再按研究假设扣税，得到税后经营利润，简称NOPAT。

然后需要留下净经营再投资。这里的“净”并不只指一张现金资本开支表，而是资产购买、融资取得资产、更新折旧与经营资金变化等共同决定的资本需求。留下的钱支持后续增长和竞争，其余才是经营资产能够向资本提供者分配的现金流，简称FCFF。

模型经营现金流 = 税后经营利润 ×（1 − 净再投资比例）。

这是简化模型的分析关系，不是微软发布的现金指引。公开资料没有完整的产品资产和资金计划，因此本研究将净再投资比例明示为假设，无法声称已经逐笔验证了每台设备、预付款和租赁的未来排期。

第06篇的现金观察不能不经转换就放进这条公式。CFO包含利息、税务时差、股权薪酬加回和经营余额变动；现金FCF只扣现金购置物业设备。模型则从已扣股权成本的经营利润出发，要求把相关经济投入包含在再投资中，并在最后处理债务与非经营资产。

选择这一方法，是为了不漏掉资本成本，也避免重复扣减。SBC保留在营业利润里，模型不再额外扣一次同额SBC，也不同时假定所有激励都造成免费新增股份。融资租赁作为债务，新增相关经济资本包含在再投资假设内；没有在每年再重复扣融资租赁本金。经营租赁费用继续留在经营结果里，最后也不再扣同一项经营租赁债务。

这些约定可以使计算保持一致，不能保证预测合理。现实中授予日SBC与未来股票经济成本有差异，未来租赁结构又会改变。若这些变化足够大，就需要更新模型，而不是用一种公式永久掩盖它们。

用两个财务分部对账，不给每个产品各算一遍

截至研究日，微软已提供FY2027新两分部结构及FY2025、FY2026重列历史。FY2026的Agents and Infra（简称A&I）营业利润为1,363.65亿美元，Devices and Consumer（简称D&C）为188.72亿美元，合计1,552.37亿美元。官方重列材料第15页。

模型对两个分部统一采用20%的规范化税率，得到1,090.92亿和150.976亿美元NOPAT。20%是研究选择，不是公司披露的分部税率；统一处理便于对账，但没有消除地区、业务及税法变化的风险。

这两个起点覆盖微软全部合并经营。M365、Azure、Dynamics、GitHub、医疗、Windows、游戏和相应广告业务，已经位于其中。它们可以在经营分析中拆开理解，估值时不能在两个分部之外再各加一个完整价值。

OpenAI等投资的非经营损益不在营业利润里，相关投资资产再在股权桥中单独处理。微软向伙伴提供服务、取得商业收入，属于经营预测需要考虑的内容；若以后对伙伴权益单独做现金流估值，还要确保对方模型已扣支付给微软的服务成本，并检查权利重叠。

本篇的“分部加总”只是同一现金流模型的贡献对账。它没有另找一套倍数，把结果称为独立SOTP验证。分部现金流和投入资本没有公开，若把假设拆分包装成第二项证据，确定性感受会增加，证据却没有增加。

对经营上相互依赖的应用和基础设施，两分部也不是天然可以按当前结果分拆出售的公司。本研究保留共享成本分配与协同风险，不把重列后的利润直接改称每项资产可以独立实现的现金。

终值为什么不能拿一个喜欢的PE来填

十年后的微软仍会经营。终值要处理2036年之后的现金，不应只因为今天同业交易在某个倍数，就把那个倍数搬到十年后。

本模型用永久增长关系：在稳态，想让NOPAT每年增长g，若新增资本回报为ROIC，需要留下约g/ROIC的利润再投资；剩余部分才可以分配。

稳态经营价值/NOPAT =（1 − g/ROIC）÷（r − g）。

其中r是美元经营资产要求回报，g也是美元名义永久增速。它们必须同币种，且g只描述十年之后，不是前十年的增长率。中性Agents and Infra采用g为3%、增量ROIC为20%，留存率为15%；在r为10%时，终值经营价值/NOPAT约12.14倍。

这里是经营资产对NOPAT的倍数，不是可以与当前GAAP净利润PE直接并列的同一个指标。公式相似，不意味着分子、税、融资与成本定义已经相同。

本研究选择的永久增速没有超过主Skill对美元口径的约束。3%或3.5%仍是长期判断，不能由当前AI收入增长40%证明。新增资本回报也不能照搬历史ROE，尤其当新的增长越来越依赖设备、能源与长约时。

这套关系还隐含一项重要条件：维持经营能力所需的资本，与经济折旧、净再投资之间能够被正确连接。若实际设备替换支出长期高于会计折旧，而模型没有补足差额，简单的留存率会高估可分配现金。会计寿命从四年改为六年、建筑从十五年改为二十五年，都不能自动改善这种经济关系。

因此，使用公式优于随意挑倍数，但公式仍需要正确的经济输入。它不会替研究者证明资本效率，也不会让没有披露的维护性投入变成已知。

2036到2037，还藏着一次现金转化改善

独立复核指出，中性Agents and Infra的净再投资率在FY2036为20%，稳态变为15%。NOPAT增速从8%降为3%，可分配比例却从80%提高到85%，使下一年FCFF增长约9.44%，高于3%的永久NOPAT增长。

这不是公式少除一年造成的算术错误，而是模型包含了一次成熟期资本释放。保守与乐观情景也有类似转换。读者如果只看到“永续增长3%”，很容易漏掉这部分价值。

这种释放可能来自建设高峰过去、资产进入稳定运行、更新需求更可控。但它不能没有证据。如果终值阶段仍需留下20%利润，而不是15%，保持3%永久增长就对应较低的稳态增量资本回报。独立敏感性下，中性每股价值由386.07降到371.30美元。

另一项测试，将中性Agents and Infra前十年每年的净再投资率提高十五个百分点，并把稳态留存设为25%，其余条件保留，价值约327.67美元。这是资本强度的条件敏感性，没有被赋予发生概率。独立复算结果。

资本留存比例同时决定每年的可分配现金和终值阶段的分配能力。若竞争要求更多设备与持续更新，利润仍可增长，股东现金却可能低于原路径。应先审查资本假设，再讨论情景价格之间的差距。

模型的保守情景不是所有风险的下界，327.67也不是资本开支持续高企的唯一答案。若需求走弱、价格下行和固定承诺同时发生，损害可以大于单变量压力测试。报告保留这种联合尾部，没有把它塞进一个主观概率平均数。

资本门槛与股权桥

10%的要求回报，从哪里来

本研究实际读取的FRED参考，是2026年10月20日美国十年期国债收益率5.12%，页面于21日更新。它是一个有日期的名义美元利率参考，不是23日的新报价，也不是本文可以代读者锁定的交易收益。FRED DGS10、本次利率来源笔记。

主模型选择10%的美元要求回报，判断上可拆成5.12%参考与4.88%风险补偿，归一化beta取1。这是约10%的投资门槛；4.88%是选择该门槛后的算术表达，不是精确测得的市场风险溢价，beta也不是本研究估计的历史参数。

由于本模型折现经营现金流，它不能冒充已经通过资本结构权重、债务市场价值、税盾和股权成本完整估计的正式加权平均资本成本（WACC）。若使用另一套WACC，需要连同融资租赁、经营租赁和税的约定一起重建，不能只换一个更低数字让估值变好看。

同时提供9%和11.5%的敏感性，是承认资本门槛的判断成分。三个情景用相同门槛比较，没有让乐观增长同时偷偷享受一套未说明的低折现率。

监管、重大安全事故、伙伴违约等离散事件，也不通过提高beta来悄悄处理。它们可能改变具体现金流、增长或造成一次损失，时间结构与持续折现惩罚并不相同。本模型没有对所有尾部逐笔量化，必须在限制里承认，而不能因r取了10%就宣布风险已经全部覆盖。

主模型最窄的r−g为6.5个百分点；9%敏感性与3.5%永久增速配对时仍有5.5个百分点。数值约束通过可以防止分母过窄造成的放大，却不会证明选定的资本回报率合理。

受限资金也不是永久损失。当前从自由现金中剔除，是一种流动性约定；如果未来释放或用于支持采购，应在经营资金桥里解释。不能先永久删掉资产，再把同一笔回收视为全部新增收益。

这座桥还没有单独估计维持日常运营必须保留的最低现金，而是把所列现金作统一余额代理。若需要留存一部分，应相应减少股权加项，并与经营资本预测保持一致。不能把表中全部非受限余额都称为今天可以无条件分红的现金。

金融债务采用账面代理，其未来本金面值另约461.36亿美元；若用面值替代，机械影响约每股0.79美元。这个差异应披露，却远小于增长、再投资和折现假设造成的变化。完整债务公允价值与价格日余额尚未重建。

经营租赁继续作为经营费用，不再扣其负债。否则，租金已经降低经营现金，又从股权桥中扣一份对应债务，会把同一负担重复计量。采用另一种租赁资本化方法也可以，但必须同时改利润、现金与债务，不能拼接两种方法最有利的部分。

反向DCF：历史参考价要求什么

另一种看法，是先接受532.95美元，再追问它要求公司做到什么。

在中性消费者业务、再投资路径、终值和10%门槛固定的前提下，将Agents and Infra未来十年NOPAT设成一个恒定增长率，反解得到约17.79%。只有在这些固定条件下，这个增速才使模型支持参考价格。条件反解结果。

这不是“市场一致预测微软收入增长17.79%”。它不是收入，也不是EPS，更不是一个可以脱离再投资而存在的唯一答案。若资本需求更高，需要的经营表现就更强；若要求回报更低或稳态能力更好，所需增长就不同。

反向模型的价值，是给商业研究设置验收压力。未来十年保持较高税后经营利润增长，同时逐步减少每单位利润必须保留的资本，这比引用当季Azure约40%的收入增速提出了更完整的要求。

它也暴露线性外推的问题。中性主路径本来由18%逐步降到8%，恒定17.79%的反解改变了后期利润规模和资金回报要求。不能只因为第一年接近，就说两种预测差不多。

若增长更强还需要更多再投资，反解时固定的资本比例就可能失效。因此，这个数字适合帮助读者提出问题，不适合印成一个看似精确的市场隐含承诺。

未上市投资，能不能把价格差一把补上

第04篇解释了，OpenAI、Anthropic的法律权利、投资损益和云商业现金不能重复计算。本模型采用其他投资账面代理，没有再给这两家企业单独叠加最新融资估值。

如果读者相信微软所持非经营权益比代理值高很多，可以直接做透明敏感性：每增加1,000亿美元可归属、可实现且未重复计入的净价值，按本次股数机械增加约每股13.47美元。

这是一条单位换算，不是本研究确认存在1,000亿美元漏计价值。权利、税、退出、追加资金和商业现金流重叠都需要先处理；不能把被投企业的整个公司估值当作微软可得金额。

在其他条件不变时，参考价与中性模型的股权差约1.091万亿美元。仅靠非经营资产弥补如此规模，需要非常强的可归属净价值证据。它不证明未来私人投资一定达不到某个价值，也说明单靠一条融资新闻，无法替代经营现金研究。机械敏感性底表。

真正可能大幅改变微软价值的，仍包括这些伙伴如何帮助产品收费、供应是否稳定、客户需求与现金回收。它们已经进入经营判断，不能在这里再次全额加值。

若私人投资发生损失，同样要区分股权账面、应收、合同与可转用资产。多个风险可以相关，但每一笔经济损失也只应计一次。

横向比较，也不能靠“都是云”缩短路径

AWS与Google Cloud的分部利润，帮助我们理解云可以形成经营收益；它们不能直接替微软提供统一PE。Amazon有其他经营与投资，Alphabet有其他广告业务、共享研发和资本开支，Oracle等企业又有不同融资、许可与云组合。

即使只比云分部，Google Cloud的Workspace、TPU销售和并购，AWS的成本分摊与电力合同衍生品，微软新旧分部的应用和授权边界，也都不同。第03篇已按同一日历季度拆过这些差异。同业比较来源包。

公平比较至少需要对齐税前或税后、GAAP或调整利润、租赁、投资收益、SBC与增长资本。若微软用剔除现金和投资后的经营倍数，对手却使用未调整公司整体PE，得到的便宜没有意义。

没有足够信息建立统一现金模型时，横向比较更适合提出问题：谁需要更高资本强度，谁的客户结构更集中，谁能在同样任务上保留更多利润。它不适合在无法对齐的数字里选一个低倍数给自己背书。

三份已精读卖方也不能代替这一步。招银国际2026年1月报告在营业利润预测大致不变时，因为资本开支上修而下调DCF目标价；光大区分GAAP与剔除OpenAI影响后的盈利，其FY2026预测仍含重估因素；较旧华安模型的部分倍数实为营业利润倍数。这些材料帮助我们检查假设，不提供截至本次截止日的三个独立“正确价格”。卖方精读与纠错。

估值近似与适用限制

哪些近似值得记住，哪些小数点不值得争

本模型已把第一笔FY2027年末现金的折现距离，设为价格日之后约0.69年，并按实际天数除365.25计算。它避免把估值日期直接停在6月30日。

但余额桥仍来自6月末，FY2027全年现金统一放在年末。7月至价格日的现金积累、回购、分红、债务和受限资金没有完整滚动，不能把它称为真正的价格日stub模型。未披露季报尚未出现时，这种近似必须交代。

本研究不会为了展示精度，给未知的季度余额填一个推算后仍称事实的数字。也不会机械只按剩余时间削减FY2027现金，却不补已累积资金和已发生分配。调整应在完整余额与现金框架里进行。

其他重要限制包括：分部税率采用统一假设，分部现金需要模型分摊，未上市投资用账面代理，实际维护性资本与净再投资未完整闭环，以及宏观与重大法律、安全事件尚未逐笔量化。

相比之下，较新股数与较旧股数之间的小幅差异、债务账面与本金的机械影响，虽然也需要对账，却不能代替这些大问题。研究严谨性不是保留更多小数，而是让对结论最有影响的未知保持可见。

最终判断与行动条件

把分歧落回资本，而不是押一个标签

愿意买微软的人，可以有很扎实的理由。组织关系、产品渠道、计算规模和实际付费需求都提供了证据。它不需要在每个模型上获胜，仍可能通过管理、工作流与基础设施取得回报。

不愿以参考价买入的人，也不必否认这些优势。他可以只是要求：未来高增长和较低资本占用尚未同时验证，终值又承担大部分价值，原研究参考价没有留下足够偏差空间。

两种判断最有建设性的争论，是下一批资本能否形成更好的现金回收，以及客户价值中有多少能由微软保留。模型更强、产品更普及、订单更多，都可以增强某一部分证据，却不独立完成这个答案。

本文最需要警惕的分析错误，是把熟悉的高质量软件生意，直接套到新增算力与代理服务上；另一个错误，则是看到资本强度上升，就忽略客户已经支付的价值和未来效率改善。好的研究应同时保留两边的验收条件。

在上述条件下，经营能力值得继续跟踪，历史参考价下新资金以观察为主；既有持仓按经营论文和组合约束复核，买入讨论需要更低价格或更充分的资本回报证据。以下将各项判断、价格区间和失效条件放在一起；企业优势要经过现金和价格检验，才能进入买入讨论。

什么价格进入可考虑区间

在本组经营与10%要求回报下，中性值约386美元。若希望再保留20%的价格误差保护，机械计算约为309美元。考虑模型本身仍有较大资本转化不确定性，本研究将约300美元以下作为可以进一步研究分批买入的条件区，而不是把309美元当自动下单线。

折价能保护估计误差，不能修复坏生意。若更低价格来自客户需求、资本效率或合作权利被破坏，原来的386美元也需要下调。此时价格跌到某个旧区间，不自动增加安全余地。

相反，如果后续现金回收、净再投资、单位经济和信用证据明显改善，价值可以上调。投资者未必必须等到300美元，但应先修改有依据的参数，再讨论新价位，而不是因为股价上涨便提高目标。

已有持有者，需要回答另一个问题

持有者面对的不只是“今天是否首次买入”，还包括原来的论文、持仓约束、未来资金用途和替代机会。本研究不知道读者的账户情况，不以同一个点估值机械要求所有人卖出。

如果原论文是企业工作流、云与AI能够持续创造较高每股价值，就应检查这条逻辑是否仍成立，而不只看当年GAAP EPS。原研究参考价高于某个中性条件值，意味着原研究条件下预期回报要求更紧，不等于业务立即失去吸引力。

如果持有理由已经变成“市场一直愿意给高倍数”，就需要承认原论文已被价格叙事替代。一个很好的企业，也可能让过高买价付出多年时间成本。

持仓过于集中时，价格和基本面判断还要与组合承受力分开。即使预计长期价值不错，也不能假定自己能够承受所有资本周期、监管和伙伴风险共同出现。这里不提供固定减仓比例，因为比例需要账户约束，而不是从一张公司估值表推出。

持有判断应留下可复核的记录：客户与收费支持什么现金路径，新增投入何时需要调整估计，合作权利或信用恶化怎样影响价值。论文仍成立时，另按组合集中度、资金用途和替代机会决定是否继续承担风险；论文失效时，先重建价值，旧成本和旧价格带不能替代判断。

重审信号必须指向一项假设

触发信号首先重审什么不能直接得出的结论
容量上线后增长与付款持续落后客户需求、实现价格与资金回收一季增速低就证明全部AI投入失败
收入强劲但资本和租赁负担长期不降净再投资路径与稳态ROIC把高增长当现金转化已兑现
Copilot付费和使用增加，续费/实现收入证据不足增量贡献、套餐和成本免费用户或试点就等于稳定利润
应收、出资与伙伴融资压力同时上升关联信用、投资与服务敞口在每个栏目重复扣同一项损失
重要许可或市场规则改变可收费范围、竞争与产品组合仅提高折现率就算处理完成
安全根因反复、事实纠正再次迟延信任、责任与治理纠偏能力以董事会自评高分代替独立闭环
管理层持续改变验收口径而不保留原目标资本配置纪律与论文可证伪性因团队历史能力强而免于检验

这些是研究纪律，不是公司承诺，也不是统计证明最优的交易规则。出现信号之后，需要查原因、持续性、财务影响和原假设，再决定行动。它们没有被设定成自动必卖指令。

同样，一次好消息也需要沿相同路径验收。新增大型客户首先支持需求，收款支持信用，利润与现金支持经济结果；不能让一个环节的进展替其他环节提前勾选。

证据范围与长期假设

发行人身份、财年、财务三表、已读合同公开条款与董事状态，具有较清楚的原始来源。核心财务还完成了五年、二十四个可比字段合计一百二十点的两源核对。它们支持研究起点，不直接证明未来能产生多少超额回报。

单品利润、分部现金流、私人合同、客户账龄、维护性资本和实际长期增量ROIC，仍有重要未知。三份独立卖方全文提供了不同时间的模型与问题，不能消除未披露数据；一份旧报告更不能冒充当前市场共识。

本模型公式已独立复算，币种、终值分母与机械双算经过检查。这使计算更可信，不会使再投资率下降、20%的稳态资本回报或当前治理改善变成已证实事实。AI能够整理和反向检验公开资料，不能替代未来经营兑现。

实际投资确定性还取决于买价、资本回报、持有期间的信息变化和自身承受力。资料充分的公司，同样可能在某个价格下缺少安全余地；有清楚数值的报告，也可能对未来判断错误。

后续观察

下一次正式财报披露后，应先更新新两分部口径，再检查付费与现金、资本与租赁、客户信用、治理承诺是否仍与本文假设一致。更新的第一步是重建事实差异，第二步才是修改模型。

本研究没有为这些观察设定自动监控或交易。它们是一套可以在新信息出现时继续使用的研究问题，也使《看懂微软》的终点回到开篇：企业客户为什么继续付费，以及股东最终为维持这种能力留下了多少钱。
